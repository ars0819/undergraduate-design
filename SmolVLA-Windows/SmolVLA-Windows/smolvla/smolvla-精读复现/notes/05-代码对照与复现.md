## 2. 训练前向：一张图 + 五个细节

**数据流**（`VLAFlowMatching.forward`，`modeling_smolvla.py:741-774`）：

```
actions (B,50,7) → pad 到 32                        ┐
noise ε ~ N(0,1)                                    ├─ x_t = t·ε + (1−t)·A
t ~ Beta(1.5,1)·0.999+0.001                         ┘   目标 u = ε − A
        │
        ├─► embed_suffix(x_t, t) → action_in_proj + time MLP → (B,50,720)
        │
prefix_embs (B,177,960) ← 2×[64 图] + 48 语言 + 1 state
        │
att_2d_masks = make_att_2d_masks(pad_masks, att_masks)   # 块因果（见 fig-attention-masks）
        │
VLM 16 层 (expert 层交错) → suffix_out (B,50,720)
        │
action_out_proj → v_t (B,50,32)
        │
losses = MSE(u_t, v_t)  →  裁到 7 维  →  mask 掉 action_is_pad  →  取平均
```

**五个容易忽略的细节：**

1. **loss 先在 32 维上算，再裁到 7 维**（`modeling_smolvla.py:773` → `:325`）。所以 `VLAFlowMatching.forward` 直接返回的 loss 不是论文意义下的动作 loss；policy 层裁剪后才是。做可视化/迁移学习时别踩。
2. **`action_is_pad` 只影响 loss，不影响 attention**（`:328-331`）。episode 边界处的无效动作步会置零 loss，但它们的 token 仍然参与 attention。
3. **padding 的动作维在 attention 里完全可见**（`embed_suffix` 的 `pad_masks` 恒为 1，`:730`）。这是"统一 32 维"的代价，模型必须自己学会忽略它们。
4. **dtype 是混合的**：checkpoint 实测 **474 张 BF16 + 26 张 FP32**。FP32 的 26 张 = 5 个投影层（各 2 张）+ 8 个 CA 层的 `k_proj/v_proj`（各 2 张）。代码在各层用 `hidden_states.to(q_proj.weight.dtype)` 显式对齐（`smolvlm_with_expert.py:244`），**不要顺手把全模型 `.to(bf16)`**。
5. **训练精度不由 `use_amp` 控制**：`use_amp` 只影响 eval/inference 的 autocast；训练用 `--accelerator.mixed_precision`（默认 `"no"`）。bf16 来自 VLM 构造时的 `torch_dtype="bfloat16"`。

**自检小脚本**（想验证 $t$ 的分布）：采样 10 万个 `sample_time`，均值应约 **0.60**（Beta(1.5,1) 的均值是 0.6，乘 0.999 加 0.001 后仍约 0.60）；如果你拿到 0.5，说明用了均匀分布，是错的。

## 3. 推理流程：prefill 一次 + 去噪 10 次 + 队列

**代码路径**：`lerobot-eval` → `select_action`（队列）→ `_get_action_chunk` → `sample_actions` → `euler_integrate(denoise_step)`。

```
1) prefill（只做一次）:
   prefix_embs (B,177,960) → VLM 16 层全部走 self-attention → 缓存 16 层的 K/V
   （注意：prefill 时所有层都走 forward_attn_layer，包括"CA 层"——CA 层在去噪时才读缓存）

2) 10 步 Euler:
   x = ε (B,50,32)
   for step in 0..9:
       t = 1.0 - 0.1*step
       v = denoise_step(x, t)     # 只跑 50 个 action token
       x = x + (-0.1) * v
   返回 x

3) select_action 队列:
   队列空时调用一次 _get_action_chunk，得到 (B,50,7)，
   取前 n_action_steps 个放入 deque；之后每次调用 popleft() 一个动作。
```

**关键点：**

- `use_cache` **必须为 True**。设为 False 时奇数层（CA）拿不到缓存，会在 `forward_cross_attn_layer` 里对 `None` 做 layernorm 直接崩（实测 `AttributeError: 'NoneType' object has no attribute 'dtype'`）。所以"关 cache 省显存"这条路走不通。
- 每步去噪前，SA 层会把 50 个 action 的 K/V 追加进缓存，步末要裁回前缀长度（`modeling_smolvla.py:855-858`）；**自定义推理循环漏了这步，缓存会越跑越长**。
- `n_action_steps` 决定"一个 chunk 执行几步后才重新预测"：**79 步的 episode + `n_action_steps=50` → 只调用了 2 次策略**（这也是本次复现只花 8.9 s 的原因）。论文仿真协议用 1（每步重预测）。
- 延迟结构（定性）：prefill 是主要成本（177 token × 16 层），每步去噪只有 50 token × 16 层。所以 **chunk 越大、prefix 越长，prefill 越占主导**。

| | 论文 §4.3 仿真协议 | 官方 checkpoint / LeRobot eval 默认 |
| --- | --- | --- |
| 每执行 1 个动作就重新观测？ | **是**（`n_action_steps=1`） | 否（`n_action_steps=50`，执行完整 chunk） |

### 6.6 协议探针：只改 `n_action_steps`，结果从成功变失败

在复跑验证了确定性之后，做了一次最小对照（同一权重、同一 seed 1000、同一 task 0、同一初始状态，**只改 `n_action_steps`**）：

| `n_action_steps` | 结果 | 步数 | rollout 耗时 | 视频 |
| --- | --- | --- | --- | --- |
| **50**（官方 config 默认） | ✅ success | 79 | 4.55 s | 85,754 B / 80 帧 |
| **1**（论文 §4.3 仿真协议） | ❌ fail | 280（跑满上限） | 33.91 s | 244,218 B / 280 帧 |

失败的那条 rollout 末帧：[`figures/repro/probe-n1/frame_03.png`](../figures/repro/probe-n1/frame_03.png)（机械臂悬停在碗上方，目标盘子为空）。

**怎么解读（重要，别过度解读）：**

- 这是 **n=1 单例**，只能说明"该 checkpoint 在这个任务/seed 下对执行协议极敏感"，**不能**当作成功率结论，也不能证明"论文 Table 13 错了"。
- 但它给出了一个非常实际的教训：**论文数字与 leadboard 数字都在特定执行协议下成立**。官方 `smolvla_libero` 的 config 默认 `n_action_steps=50`，而论文 §4.3 说仿真里每执行 1 个动作就重新观测——两者恰好就是上面这两行。想"复现论文数字"，必须先把协议对齐，否则可能得到完全相反的结论。
- 一个待验证的假设：每步重规划会**重新采样 flow-matching 噪声**，同一观测下相邻两次预测的动作可能不一致 → 高频抖动 → 失败。固定噪声（或用 RTC）可能改善。这值得作为一个小实验。
- 论文 Table 13 的"执行 1–10 步更好"结论来自**它自己从零训练的模型**；官方 release 的 checkpoint 是另一套配方，行为不必一致。

**全量评测的时间估算**（基于上表）：`n_action_steps=1` 时单回合墙钟 ≈ 43 s（rollout 33.9 s + 启动/加载约 9 s）。LIBERO-Spatial 10 任务 × 10 回合 ≈ 100 回合 ≈ **1 小时量级**。建议先跑 10 任务 × 1 回合试水，再决定是否跑全量。

## 8. 复现者最容易踩的 8 个坑（来自代码对照，按危险程度）

1. **flow matching 三件套必须一起改**：`x_t = t·ε+(1−t)·A`、目标 `ε−A`、推理从 `t=1` 到 `t=0`。改其中任何一个（比如照论文的 $\tau$ 写成 `τA+(1−τ)ε` 却保留 `ε−A`）都会学出反向速度场，且不报错。
2. **`use_cache=False` 在 cross_attn 模式下推理必崩**（CA 层拿不到缓存）。别试图关 cache 省显存。
3. **`num_expert_layers=0` 不是"0 层"**——它表示 expert 层数 = `num_vlm_layers`（16）；`self_attn_every_n_layers=2` 不是"跳层"，而是"偶数层 SA、奇数层 CA"。
4. **`max_state_dim=32`/`max_action_dim=32` 是 padding 上限**，不是真实维度；LIBERO 实际 state 8 / action 7。loss 只在真实维度上算。
5. **归一化顺序**：先 MEAN_STD 归一化（8/7 维），再补零到 32；反过来的话零 padding 会被减均值除 std，语义全错。
6. **图像域是 [-1,1]**：`[0,1]` → `×2−1`；如果你喂的是 ImageNet 归一化的图，性能会明显下降且不报错。
7. **相机顺序/命名**：`camera1` 必须是主视角、`camera2` 是腕部；反了不报错但掉性能。LIBERO 用 `--rename_map` 把 `observation.images.image/image2` 映射过去。
8. **RoPE theta=10k（不是 SmolVLM2 的 100k）**：released checkpoint 都是按 10k 训的，自己改回 100k 会和权重不匹配。
