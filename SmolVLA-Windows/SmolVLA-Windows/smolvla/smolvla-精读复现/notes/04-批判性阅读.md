## 0. 先把结论分成三档

读一篇论文最忌讳"全信"或"全疑"。我会这样分级：

| 档 | 结论 | 证据强度 |
| --- | --- | --- |
| **A. 证据较强** | 交错 CA/SA 比纯 CA/纯 SA 好；动作间必须因果；flow matching 比 L1 回归好；社区数据预训练有大幅收益；异步推理能显著缩短任务时间/提高固定时间吞吐 | 有消融或真机对照，趋势一致；但都只有 1 个 seed、数字不可精引 |
| **B. 方向可信但数字不可引** | LIBERO 87.3 打赢 π₀ 86.0、0.45B 追平 3.3B、`N=L/2` 和 0.75 宽是"最佳权衡" | 有对比，但协议不统一/无方差/效率侧无测量 |
| **C. 说了但没证据（或与证据矛盾）** | "可在 CPU 部署"、"训练快 40%、省 6× 显存"、"0.75 宽是好的 trade-off"、"跳过隔层优于缩小 VLM"、"state 放前缀对 SA 也更好" | 没有任何表格/实测支撑，部分与自家数字直接矛盾 |

## 1. 公式与记号层：三个必须自己动手验证的点

### 1.1 flow matching 公式的方向是"隐式的"

- 论文写 $\mathbf{A}^\tau=\tau\mathbf{A}+(1-\tau)\epsilon$、$\mathbf{u}=\epsilon-\mathbf{A}$。
- 但如果把 $\tau$ 当作沿路径前进的时间变量，对 $\mathbf{A}^\tau$ 求导得到的是 $\mathbf{A}-\epsilon$，**与论文写的 $\epsilon-\mathbf{A}$ 差一个负号**。
- 只有当"时间变量"取 $1-\tau$（也就是代码里的 $t$）时，$\epsilon-\mathbf{A}$ 才是正确的目标。论文正文没有说明采样方向/积分方向。
- 代码里明确是 `FlowConvention.NOISE_AT_ONE`：$x_t=t\epsilon+(1-t)\mathbf{A}$、目标 $\epsilon-\mathbf{A}$、从 $t=1$ 积分到 $t=0$（`common/flow_matching.py:49-70`、`modeling_smolvla.py:751`）。

**这不是论文独有的错**（π₀ 同源代码也这样），但意味着：**照抄论文公式自己实现，很容易把速度场符号搞反**，而模型会完全学不出来且不报错。

### 1.2 $\tau$ 的 Beta 分布超参论文没给

论文只说 "In keeping with Black et al. (2024), we sample $\tau$ from a Beta distribution"。代码是 $\mathrm{Beta}(1.5,1.0)\times0.999+0.001$（`modeling_smolvla.py:601`）。这是一个**实打实的复现缺口**：换了 Beta 参数会怎样，论文没做消融，也没解释为什么偏向噪声端。

### 1.3 论文没有给"采样器"的任何细节

- 积分步数给了（10 步，§4.3 和 config 一致）。
- 但**积分方法**（Euler？中点？）、**时间网格**（从 1 到 0 均匀？）、**是否最后一步校正**都没写。代码是均匀 10 步显式 Euler，评估时刻 $t=1.0,0.9,\dots,0.1$。
- 对复现者来说这是小问题（照代码抄即可），但对"论文声称的方法"来说是不完整的。

## 2. 架构层：几个论文没提但代码里的"意外"

> 这些是本次精读 + 代码对照的额外发现，不是论文的明显错误，但会影响你对结果的解读。

### 2.1 450M 里有 47M 是死参数

`lm_head`（47.3M）在 SmolVLA 前向中**从不调用**（语言只做输入、不做生成），但它在 policy 里、在参数统计里、在 450M 这个数字里。真正参与前向的参数约 **403M**。
→ 论文用 450M 做"参数量"对比是合理的（和别的 VLA 同口径），但说"expert ≈100M、VLM 350M"时没提这 47M 是死的。

### 2.2 RoPE 的 theta 和 SmolVLM2 的原配置不一样（实现风险）

- `apply_rope(x, positions, max_wavelength=10_000)`（`smolvlm_with_expert.py:41`），调用处从不传参。
- SmolVLM2-500M 的 `text_config.rope_theta = 100000`。
- **后果**：SmolVLA 里的"VLM 前向"不是 HF SmolVLM2 的前向，而是 openpi 风格重写的版本（π₀ 的 Gemma 用 10k，所以抄过来是 10k）。所有 released checkpoint 都是按 10k 训的，复现必须保持 10k；但这也解释了为什么 SmolVLA 里 VLM 的特征和原生 SmolVLM2 对不上。
- 论文完全没提这个替换。**它是不是影响了冻结 VLM 的可用性？值得问。**

### 2.3 前缀注意力是双向的，和 VLM 预训练的因果注意力不一致

SmolVLA 的掩码把图像+语言 token 放在同一个"块"里（`att_masks=0`），因此它们**双向可见**；而 SmolVLM2 预训练时是标准因果注意力。π₀ 也这么做（用它自己的 PaliGemma），所以不是错误；但**冻结 VLM 时，VLM 层是在一个它没见过的注意力模式上运行**。论文没讨论这个偏差，也没做"因果掩码 vs 双向掩码"的消融。

### 2.4 "SA 层"其实也看前缀 KV，不只是看动作

论文文字："SA layers allow the action tokens in $\mathbf{v}_\theta$ to attend to each other"——只说了一半。代码里 SA 层的 key 是 **前缀 KV（prefill 缓存的 VLM KV）+ 动作 KV**（见 `notes/02` §3.2）。所以"纯 CA vs 纯 SA"的对比（Table 6）实际比较的是：
- CA = 前缀 KV（经适配）+ 无动作交互；
- SA = 前缀 KV（直接复用）+ 动作因果交互；
- 交错 = 两者交替。
这比论文的"交错的互补性"解释更具体，也更值得怀疑：**"SA 更好"可能主要来自"动作交互"，而非论文暗示的"双向信息流"**。

### 2.5 时间步注入被简化了

π₀ 用 AdaRMSNorm 把时间步注入 expert 的每一层；SmolVLA 只在**输入处**用一个 MLP 融合时间嵌入和动作嵌入（`modeling_smolvla.py:698-739`）。这是"更省参数"的简化，论文没提。对"0.75 宽还够用"可能有影响。

## 3. 数据层：主卖点的证据缺口

### 3.1 Table 1 的 caption 有单位笔误

caption 写 "At ~10M **episodes**"，但表里是 22.9K episodes / 10.6M **frames**。摘要说 "<30k episodes"、§5.1 说 "~23k trajectories"，都以 22.9K 为准。**这是笔误，不影响结论，但说明表格没校对。**

### 3.2 筛选标准与配比完全没有

- 只说了 "filtered according to embodiment type, episode count, overall data quality, and frame coverage"——**四个维度的阈值一个都没给**。
- 481 个数据集怎么混合？每步 batch 怎么采样（按 episode 均匀？按数据集均匀？按 frame 均匀？）——**没写**。对复现者来说这是"预训练不可复现"的头号原因。
- 附录 A.1 的 481 个数据集清单**不可核对**：逗号粘连、疑似重复、无法数出 481；还出现了 `Ashton3/lerobot-aloha` 这类非 SO100 数据，与 §5.1 "single robot type (SO100)" 的自我描述矛盾。

### 3.3 任务描述重写（Qwen2.5-VL）没有消融

这是数据工程里最"值钱"的一步，但论文没回答：
- 用原始标注训练会差多少？
- 重写的 prompt 产生的句子 ≤30 字符，而 LIBERO/DROID 等任务描述通常 60+ 字符——**预训练语言分布和下游微调分布不一致**，对 instructions following 有何影响？

### 3.4 相机归一化是手工的，且不可复现

"we manually mapped each camera to a standardized view type—prioritizing top, wrist, and side"——481 个数据集的手工映射规则/表没公开。复现自己的数据时只能照搬思路，无法照搬结果。

## 4. 实验设计层：数字能信到什么程度

### 4.1 主表混用"引用数字"和"自家复现"

Table 2 的 caption 明说 baseline 分数来自 Kim et al. 2024 / Wen et al. 2024。**协议（trial 数、初始状态、渲染、动作归一化）都不一定相同**，但表里直接并列比较。这在 VLA 领域很常见，但精读时要打折扣。

### 4.2 每任务只 10 trials，没有方差

- LIBERO：40 任务 × 10 = 400 回合；Meta-World：50 × 10 = 500 回合。
- 没有 std、没有 seed、没有重复。按二项分布粗算（把 400 回合当独立样本）：87.3% 的 95% 置信区间约 **[83.7%, 90.7%]**（±3.3 个点）。也就是说 **87.3 vs 86.0（π₀）的 1.3 分差距在噪声范围内，不能算"打赢"**。
- 更严重的是**同一任务的 10 回合高度相关**（同一初始状态集/同一策略），真实方差只会更大。

### 4.3 消融表之间的基线漂移（详见 `notes/03` §5）

- Table 10–13 的"默认行"都是 (89,94,85,53)=80.3，而 Table 8 的 N=32 和 Table 9 的 ×0.50 恰好也是这一行 → 说明这些消融的基线是"32 层 + 0.5 宽"，**不是主模型（16 层 + 0.75 宽）**。
- Table 6 的 "CA+SA (ours)" 是 85.5，与 80.3 不一致。
- 论文没有给消融的训练预算（步数/batch/seed）→ **跨表不可比**。

### 4.4 两处"正文与数字矛盾"

| 位置 | 正文说 | 数字实际 |
| --- | --- | --- |
| §4.7 / Table 8 | 隔层取（Skip%2）优于缩小 VLM | 75.5 **<** VLM-256M 75.8 |
| §4.7 / Table 11 | state 放 VLM 对 CA 和 SA 都更好 | CA 更好（80.3 vs 73.3），**SA 反向（53.3 vs 74.8）** |

这两条单独看是笔误，但合起来说明：**消融部分的文字是事后叙述，没有严格对照数字**。

### 4.5 真机实验缺关键信息

- 没有 trial 数、没有 seed、没有方差、没有 baseline 的 trial 数。
- 真机"成功率"是分段得分的平均，与仿真的二值成功率不可比。
- Table 3 把 **单任务训练的 ACT** 和 **多任务+预训练** 的 SmolVLA/π₀ 放在一起，30 分的差距不能归因于模型。
- SmolVLA 在 Pick-Place 上（75）其实**输给 π₀（100）**，正文"outperforms both ACT and π₀"只对平均成立。

### 4.6 异步推理的结论被过度美化

- 正文 "comparable success rates"，实际平均 −5 分、Sorting −20 分。
- 超参（$g$、相似度阈值）只在 Pick-Place 上调过就复用到其它任务（Figure 5 caption 明说）。
- **没有测延迟/控制频率**：全文只有端到端任务时间和"30 fps → Δt=33 ms"的假设。摘要说 "enabling higher control rates"，但没有任何 Hz 数据。
- 相似度过滤的阈值 $\epsilon$、聚合函数 $f$ 都没给具体形式 → 异步栈不可精确复现。

### 4.7 π₀ 的参数量在论文里有三种写法

3.3B（§4.4、Table 2 LIBERO）、3.5B（Table 2 Meta-World、Table 3）、"Paligemma-3B"（Table 2 一行）。对比时用了哪个、为什么不同，没说。

### 4.8 "效率"主张全部缺少效率测量

- "π₀ 快 40% 训练、省 6× 显存"（§4.5）——没有表。
- "0.75×d 是好的性能-效率权衡"（Table 9）——没有延迟/显存/FLOPs。
- "N=L/2 省一半计算"（§3.1）——没有实测。
- "可在 consumer GPU 或 CPU 上部署"（摘要）——没有 CPU 实测数据。
- "single GPU 可训练"（摘要/§4.3）——实际预训练用了 4 张 GPU、30k GPU-hours（单卡约 3.4 年）。

> 这一组是**这篇论文最系统性的弱点**：它是一篇"以效率为核心卖点"的论文，但效率证据全部是定性的。

## 5. 复现层：论文配方的不可复现点清单

| # | 缺口 | 影响 |
| --- | --- | --- |
| 1 | 数据筛选阈值、混合比例、采样权重 | 无法复现预训练 |
| 2 | 481 个数据集的精确清单（附录不可核对） | 无法复现预训练 |
| 3 | 消融的步数/batch/seed | 无法复现消融 |
| 4 | Beta 的 α/β（代码给了，正文没给） | 照正文实现会错 |
| 5 | 积分器/时间网格（代码给了，正文没给） | 照正文实现会错 |
| 6 | 异步栈的 $f$（聚合）与 $\epsilon$（相似度阈值）形式 | 无法复现异步 |
| 7 | 真机 trial 数、初始条件、评测脚本 | 真机数字不可比 |
| 8 | 官方 release 的 checkpoint 训练配方 ≠ 论文配方 | 复现目标要选清楚（见 `notes/05` §5） |
| 9 | LIBERO/MetaWorld 的数据版本（`physical-intelligence/libero` vs `lerobot/libero`）与仿真器版本 | 成功率对 MuJoCo 版本极敏感（见下） |
| 10 | 论文没给代码 commit / 数据 revision / 硬件型号 | 复现只能对齐"大方向" |

**第 9 条有多严重？** LeRobot 官方文档里有一个触目惊心的例子（`docs/source/lawam.mdx`）：同一个 checkpoint、同一个任务（`libero_spatial` task 5），**MuJoCo 3.8.1 下 18/50 成功，MuJoCo 3.3.2 下 47/50 成功**。也就是说**仿真器版本可以让同一个模型的成功率差到 2.6 倍**。所以任何跨论文的 LIBERO 数字对比都要先对齐仿真环境版本。

## 6. 作者自己承认的局限（§5.1，p.14–15）

## 7. 如果我是审稿人：会写什么意见

**Major**
1. 效率是核心卖点，但全文没有任何延迟/显存/FLOPs 测量（§4.5、Table 9、摘要、§3.1 均只有定性说法）。
2. 所有成功率都是单次运行、无方差；10 trials/task 的样本量下，与 π₀ 的 1.3 分差距不可解释为显著。
3. 消融表的基线配置与主模型不一致（32 层/0.5 宽 vs 16 层/0.75 宽），且消融训练预算未报告，跨表数字不可比。
4. 正文与 Table 8 / Table 11 的数字矛盾（两处）。
5. 数据是主卖点之一，但筛选标准、混合比例、数据集清单都不可核对；附录清单自身有粘连和疑似冲突项。
6. 真机实验缺 trial 数、seed、方差，且"成功率"是分段得分，与仿真不可比；跨训练范式（ACT 单任务 vs SmolVLA 多任务）并列比较。

**Minor**
7. Table 1 caption 单位笔误（10M episodes vs frames）。
8. π₀ 参数量三种写法（3.3B/3.5B/Paligemma-3B）。
9. Table 2 引用错误（DP 引 DROID、TinyVLA 引 TinyLLaVA）。
10. 异步推理的 "comparable success rates" 与 Sorting −20 分的数字不符。
11. 公式方向约定（$\tau$ vs $t$）没交代，容易误导实现者。
12. 没给 Beta 超参、积分器、聚合函数、相似度阈值等关键实现细节。

## 9. 一句话总结这篇论文的证据结构

> **架构消融（Table 6/7）和真机对照（Table 3/5）是这篇论文最扎实的部分；主表（Table 2）因为混用引用数字而只能作为"量级参考"；所有效率主张都是定性的；作者用大量"工程细节"换来的小模型确实能工作，但"为什么能工作"（哪一部分是必要的）论文自己也没完全拆清楚。**

这也是为什么值得自己复现一遍：论文的**趋势**可信，但**具体数字和因果关系**需要自己验证。
