## 答案与解析

**1.** 总参数量 **450,046,176**（论文 450M）；action expert **98,245,840**（论文"≈100M"）；真正参与前向的约 **403M**。
差异来源：① 450M 里有 **47.3M 的 `lm_head`**——SmolVLA 只做语言输入、不做生成，前向从不调用它；② 视觉编码器 86.4M 只在 prefill 时用一次；③ 不同文献对"参数量"口径不同（是否含 vision encoder / lm_head）。详见 `notes/02` §0、`notes/05` §4。

**2.** 512×512 图 → SigLIP（patch 16）→ **32×32=1024 个 patch** → connector 的 **4×4 pixel shuffle** → **64 个 token/帧**（实测 `[1,1024,768]` → `[1,64,960]`）。
不用 tiling 是为了省推理成本：tiling 会把每帧变成多个 crop（token 数翻几倍），而 VLA 的 VLM 每步都要跑，视觉 token 直接决定延迟。代价：空间细节丢失，论文没做消融。`notes/02` §1.3。

**3.** 理由：① 省一半 LLM 计算；② 有文献表明下游任务最优特征不一定在最后一层。证据 Table 8：N=8/16/24/32 → 75.0/78.5/79.5/80.3，**层数单调增加**；选 16 层代价 **−1.8 分**（78.5 vs 80.3）。`notes/02` §1.2、`notes/03` §4.3。

**4.** 论文：$\mathbf{A}^\tau=\tau\mathbf{A}+(1-\tau)\epsilon,\ \mathbf{u}=\epsilon-\mathbf{A}$，损失 $\|\mathbf{v}_\theta(\mathbf{A}^\tau,\mathbf{o}_t)-\mathbf{u}\|^2$。
代码：$x_t=t\epsilon+(1-t)\mathbf{A}$，目标同样是 $\epsilon-\mathbf{A}$，但 **从 $t=1$ 积分到 $t=0$**，所以 **$t=1-\tau$**。
搞混的后果：速度场符号反了 → 采样时朝噪声方向走 → 模型输出垃圾，但**训练 loss 会先下降**（因为网络总能拟合反符号的目标），很难 debug。`notes/02` §2.2、`notes/05` §8 坑 1。

**5.** $\mathrm{Beta}(1.5,1.0)\times0.999+0.001$（**论文正文没给，只有代码有**）。密度 $\propto t^{0.5}$，质量集中在 $t\to1$＝纯噪声端，即论文的 $\tau\to0$。论文只说"follow π₀"，没解释为什么。这是复现缺口 + 可做实验。`notes/02` §2.3。

**6.** $t=1.0,0.9,\dots,0.1$ 共 **10 个评估点**，$dt=-0.1$，只调用 expert **10 次**（前缀 KV 复用）。最终 $x$ 只是 $x_0$ 的近似（最后一步把 $t=0.1$ 处的速度外推到 0），没有额外校正步。`notes/02` §2.5、`notes/05` §3。

**7.** 偶数层（0,2,…,14）= **SA**：动作 token 之间的因果自注意力；奇数层（1,3,…,15）= **CA**：动作 token 只读前缀 KV。
**SA 层也能看到前缀 KV**（prefill 时缓存了 VLM 的 KV，去噪时把动作 KV 追加到同一层缓存）——论文只写了"SA 允许动作之间互相看"，没说它也看前缀。
影响：所以 Table 6 的"CA vs SA vs 交错"实际比较的是"有没有动作间交互"，而不是"要不要看前缀"。这削弱了论文"互补性"的叙事，也提示"SA 更好"可能主要来自动作交互。`notes/02` §3.2、`notes/04` §2.4。

**8.** **双向**：图像+语言 token 的 `att_masks=0`，在同一个块里互相可见。而 SmolVLM2 预训练是**因果**注意力。
所以"冻结的 VLM"是在一个它没见过（但对下游更合适）的注意力模式下运行。π₀ 也这么做，不算错误，但论文没讨论这个偏差，也没做消融。`notes/02` §3.2、`notes/04` §2.3。

**9.** 训练时若双向，$a_t$ 的 token 能看到 $a_{t+5}$，等于抄答案（chunk 内动作高度相关），训练 loss 漂亮但推理时没有未来 token → 崩。
Table 7：双向 67.5 → 因果 74.5（**+7 分**），Long 子集 23 → 40。`notes/02` §3.4。

**10.** state 放在前缀**最后**（图像+语言之后）。掩码不对称：**state 查询能看到全部前缀，但前缀 token 看不到 state**（`att_masks` 累积和导致）。
Table 11：CA 下前缀 80.3 > 后缀 73.3（成立）；但 **SA 下前缀 53.3 < 后缀 74.8**（反向 21.5 分）。论文正文说"对 CA 和 SA 都更好"是**错的**。`notes/02` §3.2、`notes/03` §4.6、`notes/04` §4.4。

**11.** $g$：队列剩余比例 $|A_t|/n$ 低于 $g$ 时触发新推理（**$g$ 越大越早补货**）。
下界：设推理延迟 $\ell_S$、控制周期 $\Delta t$、chunk $n$，则 $g\ge(\mathbb{E}[\ell_S]/\Delta t)/n$ 时队列不会在执行中耗尽。代入 $n=50,\Delta t=33\text{ms},\ell_S=100\text{ms}$ → $g\ge0.06$，远小于论文的 0.7。
相似度过滤：观测在关节空间距离 < ε 就不发，避免几乎相同的 chunk 反复填队列导致机器人卡死；队列空时强制处理。`notes/02` §5。

**12.** 预训练：**200k steps，global batch 256，4 GPU，≈30,000 GPU-hours**；仿真 finetune：100k steps / batch 64；真机 finetune：200k steps（lr 1e-4，cosine 到 2.5e-6，warmup 100）。`notes/02` §6。

**13.** "VLA Pt. = No" = **没有用机器人数据预训练，只加载 VLM 权重**（caption 原文 "SmolVLA is only initialized from the VLM"）。
所以 Table 2 的 87.3% 是"VLM 初始化 + 在 LIBERO 上训"的成绩；"社区数据预训练"的收益只在 Table 5（真机）展示（51.7→78.3）。两者不是同一条实验线。`notes/01` §1、`notes/03` §2.1。

**14.** 说明**社区数据预训练是最大的单项收益（+26.6 分）**，比多任务本身（+11.7）大一倍多。
混淆：① 三个任务收益极不均匀（Stacking +50，Pick-Place −5）；② 无方差、无 trial 数；③ 单任务行是"每任务单独训模型"，与多任务行不是同一种实验。`notes/03` §2.3。

**15.** Table 13：执行步数 1/10/30/50 → 80.3/82.8/70.8/**51.8**，说明**要频繁重观测**。
官方 checkpoint 的 `n_action_steps=50`（执行完整 chunk），与论文 §4.3"仿真里每执行一个动作就重新观测"**矛盾**；同一模型这两种配置差 **28.5 分**。
本次复现用 50，所以不可与论文 87.3 直接比。
**本地探针**（n=1）：同一 seed/任务下 `n_action_steps=50` 成功（79 步），`=1` 失败（280 步）——方向和 Table 13 相反，说明官方 checkpoint 与论文自训模型的执行协议依赖性不同。`notes/03` §4.8、`notes/05` §5.2/§6.6。

**16.** 不是。Table 10/11/12/13 的默认行都是 (89,94,85,53)=80.3，而 Table 8 的 N=32 行、Table 9 的 ×0.50 行也是同一组数 → 说明消融基线是 **32 层 VLM + expert 宽 0.5**，**不是主模型（16 层 + 0.75 宽）**；Table 6 的 "CA+SA (ours)" 又是 85.5，与所有表都不一致。且消融的训练预算没报告 → 跨表不可比。`notes/03` §5。

**17.** 不准确。平均成功率 78.3 → 73.3（**−5**），其中 **Sorting 70 → 50（−20）**；只有 Pick-Place 上升（75→80）。时间和吞吐改善是真的（−29.5% 时间、9→19 次），但"成功率相当"属于过度概括，且异步超参只在 Pick-Place 上调用。`notes/02` §5.5、`notes/03` §3、`notes/04` §4.6。

**18.** 不显著。LIBERO 协议是 40 任务 × 10 trials = **400 回合**；若按二项分布粗算，87.3% 的 95% CI ≈ **[83.7%, 90.7%]**（±3.3 个点），1.3 分的差距完全在噪声内。而且同任务 10 回合高度相关，真实不确定性更大。所以正确的说法是"接近 π₀"，不是"打赢"。`notes/04` §4.2。

**19.** 三点：① **冻结策略**——论文"只训 expert、VLM 冻结"（99.9M 可训练），libero checkpoint 是 `freeze_vision_encoder=false, train_expert_only=false`（392.9M 可训练）；② **训练预算**——论文仿真 finetune 100k steps/batch 64，checkpoint 记录 25k steps/batch 32；③ **数据 repo 名不同**（论文 `physical-intelligence/libero` vs 训练记录 `lerobot/libero`）。
影响：想复现论文 Table 2 的 87.3%，需要按论文配方（VLM 初始化 + 100k/64 + 冻结）自己训；直接用官方 checkpoint 是另一套配方，数字不可直接对标。`notes/05` §5、`notes/_raw/code-map.md` §6。

**20.** 证据链：`End of eval` + `eval_info.json` 里 `success=true/n_success=1/sum_reward=1.0` + 79 步逐帧视频（人工核对碗确实被放到盘子上）+ 8.90 s 的 `eval_s` + 权重 sha256 与 Hub LFS 一致 + 干净的 commit `83883ae` + 完整版本栈。
不能引成功率的理由：**n=1**（Wilson CI [20.7, 100]）、单任务、单 seed、单初始状态、未训练/微调、素材不完整——只能证明"链路连通，模型权重与仿真环境可用"。`notes/05` §6、`notes/_raw/repro-evidence.md` §0–§2。
