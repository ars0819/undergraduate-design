## 0. 先把整体装进脑子

SmolVLA 只有两个模块：

```
输入: 2~3 路 RGB + 语言指令 + 机器人 state
        │
        ├─► [VLM] SmolVLM2-500M，只用前 16 层（共 32），图像+语言+state 拼成 177 个 token
        │      └─► 输出「前缀 KV cache」（只算一次）
        │
        └─► [Action Expert] 98M 的 16 层 transformer，宽度 0.75×960=720
              每层二选一：偶数层自注意力 SA / 奇数层交叉注意力 CA
              输入 = 50 个带噪动作 token，条件 = 前缀 KV
              用 flow matching 训练，推理时从噪声积分 10 步 → 50×32 的动作 chunk
                 │
                 └─► 裁到 7 维 + 反归一化 → 逐个执行
```

**一句话抓住方法**：**VLM 负责"看懂"，expert 负责"动"；两者通过 KV cache 连接；动作用 flow matching 生成；执行用 chunk 队列。**

我实测的规模账（`repro/verify_model_facts.json`）：

| 组件 | 参数量 | 说明 |
| --- | --- | --- |
| SigLIP 视觉编码器 | 86.4M | 512×512，patch 16，12 层 |
| connector（pixel shuffle） | 11.8M | 1024 patch → 64 token，768→960 维 |
| 文本解码器（前 16 层 + 词嵌入） | 204.6M | 词嵌入 47.3M + 16 层 157.3M |
| `lm_head`（**前向不用**） | 47.3M | 训练文本生成才用；在 policy 里白占 47M 参数 |
| **VLM 小计** | **350.2M** | 其中真正参与前向的约 302.8M |
| **Action expert** | **98.2M** | 16 层 × 720 宽 + 注意力投影 |
| state/action/time 投影 | 1.6M | 5 个小 MLP |
| **合计** | **450.0M** | 论文说的 450M ✅（expert ≈100M ✅） |

> 💡 **精读提示**：论文说"450M，其中约 100M 是 action expert"。这个账能对上，但要注意两点：
> ① 450M 里有 47M 是用不到的 `lm_head`，所以真实前向规模约 403M；
> ② 论文说"只训练 action expert 时 VLM 冻结"，冻结的参数里也包括这 47M。

## 1. §3.1 模型架构（p.3–5）

### 1.1 三路输入怎么变成 token（对照 `fig-dataflow.png`）

| 输入 | 处理 | token 数 | 维度 |
| --- | --- | --- | --- |
| RGB 图像 ×2 | SigLIP → connector（pixel shuffle） | 每帧 **64** → 共 128 | 960 |
| 语言指令 | tokenizer（最长 48）→ 词嵌入 ×√dim | ≤48 | 960 |
| 机器人 state（8 维） | pad 到 32 → `state_proj` 线性层 → **1 个 token** | 1 | 960 |
| **前缀合计** | | **177** | |
| 动作（带噪 chunk） | pad 到 32 → `action_in_proj` → 与时间步嵌入拼接过 MLP | **50** | 720 |

前缀是"图像 token + 语言 token + state token"直接拼接（`embed_prefix`，`modeling_smolvla.py:604`）。**注意 state token 放在最后**，不是最前——这个顺序配合掩码才有意义（见 §3.2）。

代码里还有一个细节：图像和语言嵌入都乘了 `sqrt(hidden_dim)` 做缩放（`modeling_smolvla.py:637, 663`），这是为了复刻 SmolVLM 原生 processor 的数值尺度，因为这里绕过了原生的多模态嵌入路径。

### 1.2 层截断：为什么只用前 16 层（N = L/2）

论文 §3.1 "Faster inference through layer skipping"（p.4）说得很直接：**不用最后一层特征，而是让 action expert 能访问到第 N 层为止的特征**；实践中取 $N=L/2$。

- 动机有两层：① 省一半 LLM 计算；② 引用了一串工作（El-Nouby 2024、Bolya 2025、Rajasegaran 2025）说明"下游任务最好的特征不一定在最后一层"。
- 论文的代价：Table 8 显示 N=16 平均 78.5%，而用全部 32 层是 80.3%——**少了 1.8 个点换一半算力**。
- 代码实现简单粗暴：直接把 `text_model.layers` 切片（`smolvlm_with_expert.py:104`），后面所有层丢弃。

> 读的时候要问：这个"前 N 层"的结论是**在冻结 VLM 的消融设置下**得到的（§4.7 明确说 VLM frozen、只训 expert），而主模型如果全参微调（官方 release 就是这样），"用前 16 层"的结论是否还成立？论文没有交叉验证。

### 1.3 视觉 token 缩减：每帧只留 64 个

这是全文最"反常识"的设计之一（§3.1 "Visual tokens reduction"，p.4）：

- SmolVLM2 原本支持 **image tiling**（把图切成多块，每块单独编码，再加全局图），能提升 VLM 性能但很贵。
- SmolVLA **完全不用 tiling**：只跑全局图，512×512 / patch 16 = 1024 个 patch，再经 connector 的 4×4 **pixel shuffle** → **64 个 token/帧**。
- 我实测验证：`vision_patch_tokens = [1, 1024, 768]` → `visual_tokens_per_image = [1, 64, 960]`（`repro/verify_model_facts.json`）。

**为什么这重要**：别的 VLA 动辄每帧 256+ 个视觉 token，SmolVLA 只有 64。这直接决定了 VLM 的序列长度（2 相机 = 128 个 token），也是"能上小 GPU / CPU"的关键。

> 但这是本文最大的**未消融**空白：视觉 token 数（64 vs 128 vs 256）、分辨率（512 vs 256）、相机数量，全都**没有**做消融。见 `notes/04`。

### 1.4 投影层与 padding：`max_state_dim` / `max_action_dim`

- 为什么要 pad 到 32？为了让**不同机器人**的 state/action 维度可以用同一个网络（OpenVLA/π₀ 系列的传统做法）：8 维的 LIBERO state 后面补 24 个零，7 维的 action 后面补 25 个零。
- 关键：**loss 只在真实维度上算**。代码里 `losses[:, :, :action_feature.shape[0]]`（`modeling_smolvla.py:325`）把 padded 维度裁掉，然后再 mask 掉 `action_is_pad` 的无效步。
- state 只取当前时刻（`n_obs_steps=1`）：`prepare_state` 里 `state[:, -1, :]`（`modeling_smolvla.py:464`），**没有历史帧/动作历史**——这一点和很多"叠帧"的 VLA 不同。

> 复现注意：如果你自己的机器人 state 只有 6 维、action 6 维，只要能对上 config 的 `input_features`/`output_features` 就不用改代码；如果相机编号/数量不同，要用 `--rename_map` 映射成 `camera1/2/3`（见 `notes/05` §6）。

### 1.5 与"效率"相关的四个设计汇总

| 设计 | 省什么 | 论文给的性能代价 |
| --- | --- | --- |
| 只用前 16/32 层 | 一半 LLM 计算 | −1.8 分（Table 8: N=16 78.5 vs N=32 80.3） |
| 每帧 64 视觉 token（无 tiling） | VLM 序列从 ~300 降到 128 | **未消融** |
| expert 宽度 0.75d | expert 计算 | −4.8 分（Table 9: ×0.75 77.5 vs ×1.00 82.3） |
| 小骨干（500M vs 7B） | 显存/延迟 | 无（Table 2 对比 0.24/0.45/2.25B 三个规模） |

## 2. Flow matching action expert：把论文公式拆到每一项

### 2.1 论文写的（§3.1 p.4）

$$
\mathcal{L}^{\tau}(\theta)=\mathbb{E}_{p(\mathbf{A}_{t}\mid\mathbf{o}_{t}),\,q(\mathbf{A}_{t}^{\tau}\mid\mathbf{A}_{t})}\left[\left\|\mathbf{v}_{\theta}(\mathbf{A}_{t}^{\tau},\mathbf{o}_{t})-\mathbf{u}(\mathbf{A}_{t}^{\tau}\mid\mathbf{A}_{t})\right\|^{2}\right]
$$

逐项翻译：

| 符号 | 含义 | 代码里对应 |
| --- | --- | --- |
| $\mathbf{A}_t=(a_t,\dots,a_{t+n})$ | 真实动作 chunk（n=50） | `actions`，pad 到 32 维 |
| $\epsilon\sim\mathcal{N}(0,I)$ | 高斯噪声 | `sample_noise(shape)` |
| $\tau$ | 流匹配时间，$\tau\sim\mathrm{Beta}$ | `sample_time()` → 注意方向（下节） |
| $\mathbf{A}_t^{\tau}=\tau\mathbf{A}_t+(1-\tau)\epsilon$ | 加噪动作（线性插值路径） | `make_flow_matching_inputs(...)` |
| $\mathbf{u}=\epsilon-\mathbf{A}_t$ | 回归目标（速度场） | `u_t` |
| $\mathbf{v}_\theta(\mathbf{A}_t^\tau,\mathbf{o}_t)$ | 网络预测的速度 | `v_t = action_out_proj(suffix_out)` |
| $\mathbf{o}_t$ | VLM 特征（第 N 层的输出） | `prefix_embs` / KV cache |
| $\|\cdot\|^2$ | MSE（只算真实动作维度） | `F.mse_loss(u_t, v_t, reduction="none")` |

### 2.2 ⚠️ 第一个大坑：论文的 $\tau$ 和代码的 $t$ 方向相反

**论文**：$\tau=0$ 是纯噪声，$\tau=1$ 是干净动作（因为 $\mathbf{A}^\tau=\tau\mathbf{A}+(1-\tau)\epsilon$）。
**代码**（`policies/common/flow_matching.py` 的 `FlowConvention.NOISE_AT_ONE`）：

$$x_t = t\,\epsilon + (1-t)\,\mathbf{A},\qquad \mathbf{u}=\epsilon-\mathbf{A},\qquad \text{从 } t=1 \text{ 积分到 } t=0$$

两者是同一个东西，只是参数化：**$t = 1-\tau$**，$\tau = 1-t$。所以：

| 论文 $\tau$ | 代码 $t$ | 含义 |
| --- | --- | --- |
| 0 | 1 | 纯噪声（采样起点） |
| 1 | 0 | 干净动作（采样终点） |

代码里 `make_flow_matching_inputs(..., convention=FlowConvention.NOISE_AT_ONE)`（`modeling_smolvla.py:751`）明确写了这个约定。**如果你自己实现训练循环而把 $\tau$ 当 $t$ 用，速度场的符号会反，模型完全学不出来**——这是复现时最容易踩的坑，没有之一。

### 2.3 $\tau$ 怎么采样：Beta 分布的具体参数论文没写

- 论文只说 "In keeping with Black et al. (2024), we sample $\tau$ from a Beta distribution"（= π₀ 的做法）。
- 代码里是 `sample_time_beta(..., alpha=1.5, beta=1.0, scale=0.999, offset=0.001)`（`modeling_smolvla.py:601-602`），即
  $$t \sim \mathrm{Beta}(1.5,1.0)\times 0.999 + 0.001$$
- 这个分布密度 $\propto t^{0.5}$，**质量集中在 $t\to 1$**，也就是**训练时更常看到"接近纯噪声"的样本**——对应论文的 $\tau\to 0$。为什么这样更好？论文没解释（π₀ 也没细讲，经验上高噪声区难学，多采样有帮助）。见 `fig-flow-matching.png` 右图。

> 精读时该记下的空白：**论文没给 Beta 的超参**。如果换一个 α 会怎样？没人知道——这是可以做的小实验。

### 2.4 时间步怎么注入 expert：sinusoidal + MLP（比 π₀ 简单）

代码 `embed_suffix`（`modeling_smolvla.py:698-739`）：

1. 带噪动作 `noisy_actions (B,50,32)` → `action_in_proj` → `(B,50,720)`；
2. 时间步 $t$ 用 sin/cos 位置编码（`min_period=0.004, max_period=4.0`，`create_sinusoidal_pos_embedding`）→ 广播到 50 个 token；
3. 两者 concat（1440 维）→ `Linear(1440,720)` → SiLU → `Linear(720,720)` → 得到 50 个 action token 的输入嵌入。

⚠️ **和 π₀ 的差别**：π₀ 用 AdaRMSNorm 把时间步注入每一层，这里只在**输入**处过一次 MLP。所以 SmolVLA 的 expert 内部层没有时间条件（除非它通过 token 表示隐式携带）。论文完全没提这个差异，但它对"为什么 0.75 宽还能work"可能有影响。

### 2.5 推理：10 步 Euler，从 t=1.0 积到 t=0.1

代码（`euler_integrate`，`flow_matching.py:256-421`；`sample_actions`，`modeling_smolvla.py:776-825`）：

```
x ← ε                                  # 50×32 的高斯噪声
for step in 0..9:                     # num_steps = 10
    t = 1.0 - step * 0.1              # 1.0, 0.9, ..., 0.1
    v = expert(x, t, prefix_KV)       # 一次 expert 前向
    x ← x + (-0.1) * v                # 朝 t 减小的方向走
返回 x                                 # 近似 x_0 = 干净动作
```

- 网络只被调用 10 次；**前缀 KV 只算一次**（prefill），每次去噪只跑 50 个 action token——这是延迟低的根本原因。
- 注意最后一次评估在 $t=0.1$，不是在 0；结束时不额外校正。
- `num_steps=10` 是 config 默认值，也是论文 §4.3 明确写的（"During inference, the flow matching is fixed to 10 steps"）。

### 2.6 为什么用 flow matching 而不是回归：Table 10

| 训练目标 | LIBERO 平均（from scratch 消融） |
| --- | --- |
| Flow matching（默认） | **80.25%** |
| L1 回归 | 75.25% |

差 5 个点。论文的解释是"flow matching 对多模态动作分布有更好的归纳偏置"——这是标准说法，但**这个消融只有一组数字、没有方差**，而且回归 baseline 的具体实现（是否也预测 chunk）没写。

## 3. 交错 CA/SA 与注意力掩码（§3.1 最后一段，p.4–5）

这是全文最有"架构味"的一段，也是文字最少、最容易读漏的一段。原文只说：

> "we employ an interleaved approach, where each block contains either a CA or a SA layer... CA layers cross-attend the VLM's keys and values, while SA layers allow the action tokens in $\mathbf{v}_\theta$ to attend to each other. We employ a causal attention mask for the SA layers."

### 3.1 背景：π₀ 用纯 SA，GR00T 用纯 CA

- **π₀（Black et al. 2024）**：把 action token 和 VLM token **拼成一个序列**，全程自注意力。优点：信息流最灵活；缺点：序列变长、VLM 的 KV 要和 action token 做全注意力。
- **GR00T N1（Bjorck et al. 2025）**：expert 用**交叉注意力**去读 VLM 的 KV。优点：前缀只算一次、expert 轻；缺点：action token 之间没有交互。
- **SmolVLA**：**两种交替**。第 0、2、4…、14 层是 SA，第 1、3、…、15 层是 CA。

论文 §3.1 说这样"higher success rates and faster inference"，并且"SA 让动作 chunk 更平滑（在真机上尤其明显）"。Table 6 的消融：

| 注意力方式 | 平均成功率 |
| --- | --- |
| 纯 CA | 79.0 |
| 纯 SA | 74.5 |
| **交错 CA+SA** | **85.5** |

### 3.2 掩码到底长什么样（对着 `fig-attention-masks.png` 看）

我用 checkpoint 的实际 token 数（2 相机、48 语言、1 state、50 动作）把三种掩码画出来了：

**(A) 训练前向的完整掩码（227×227）**

| 谁作为 query | 能看见谁 | 为什么 |
| --- | --- | --- |
| 图像/语言 token | 所有图像+语言 token（**双向**，不是因果） | 前缀内部不需要因果；这也偏离了 VLM 预训练时的因果掩码 |
| state token | 所有图像+语言+自己 | state 要读到全部上下文 |
| action token $i$ | 所有前缀 + 自己及之前的 action | 动作必须因果，防止"看到未来动作" |

**(B) 去噪一步 · SA 层（50×227）**：action token $i$ 能看见**全部 177 个前缀 KV** + **自己的动作前缀**（因果）。
**(C) 去噪一步 · CA 层（50×177）**：action token **只能看见前缀 KV**，动作之间完全隔离。

> 这里有个**文字描述看不出来、读代码才能发现**的事实：**SA 层其实也看前缀 KV**，并不只是"action 之间互相看"。原因是 prefill 阶段每个 SA 层都缓存了 VLM 前缀的 K/V（`smolvlm_with_expert.py:441-464`），去噪时把 action 的 K/V 追加到同一层缓存里（`:281-285`），再在每步结束把它们裁掉（`modeling_smolvla.py:855-858`）。所以更准确的表述是：
> - **SA 层 = 前缀 KV（直接复用）+ 动作间因果自注意力**
> - **CA 层 = 前缀 KV（经 `k_proj/v_proj` 适配）+ 无动作交互**
>
> 这个区别恰好解释了为什么"纯 CA"（79.0）不如"交错"（85.5）：少了动作间交互；而"纯 SA"（74.5）更差，因为所有层都要重新算/拼接动作 KV，且缺少 CA 的轻量适配路径。

### 3.3 代码实现里三个值得注意的点

1. **CA 层的 `k_proj`/`v_proj` 被替换成一个 `Linear(320,320)` 适配器**（`smolvlm_with_expert.py:122-136`）。VLM 的 KV 维度是 `num_kv_heads×head_dim = 5×64 = 320`，expert 的 KV 维度也是 320（因为 KV 头数/头维没变），所以它是个方形线性层——把 VLM 的 KV 投影到 expert 的 KV 空间，而不是降维。
2. **RoPE 位置**：expert 的 position id 被平移成从 0 开始（`smolvlm_with_expert.py:376-378`），即动作 token 的位置编码与前缀无关。
3. **缓存裁剪**：SA 层每步会把 50 个 action 的 KV 追加进缓存，下一步前裁回前缀长度（`modeling_smolvla.py:855-858`），否则缓存会无限增长。这是实现细节，但如果你自定义推理循环漏了它，显存会逐渐涨。

### 3.4 为什么动作必须因果：Table 7

| 动作 token 之间的掩码 | 平均成功率 |
| --- | --- |
| 双向（Bidir） | 67.5 |
| **因果（Causal）** | **74.5** |

论文解释："防止未来动作泄漏"（prevent future action leakage）。直觉：训练时如果把 $a_{t+5}$ 的输入暴露给预测 $a_t$ 的 token，等于让模型抄答案（chunk 内的动作高度相关），训练 loss 会很好看但推理时拿不到未来 token，就会崩。这是 action chunking 模型的通用坑。

> ⚠️ 注意 Table 6 的 SA=74.5 和 Table 7 的 Causal=74.5 是**同一行数字**（(80,94,84,40)），说明 Table 7 的 "Causal" 就是 Table 6 的 "SA"。但 Table 6 的 "CA+SA"（85.5）和后面 Table 10–13 的 baseline（80.3）对不上——见 `notes/03` §5 的表间不一致问题。

## 4. §3.2 预训练数据：社区数据怎么用（p.5）

### 4.1 规模

Table 1（p.5）：**481 个数据集 / 22.9K episodes / 10.6M frames**。

- ⚠️ 这张表的 caption 写 "At ~10M **episodes**"，但表内是 22.9K episodes / 10.6M **frames**——**单位笔误**（摘要 p.2 说 "fewer than 30k episodes"，§5.1 p.15 说 "~23k trajectories"，都以 22.9K 为准）。
- 数据来源：HuggingFace 上 SO100 用户社区上传的 LeRobot 数据集，来自个人、实验室、小团队；机型**几乎全是 SO100**（§5.1 第一条局限自己承认）。
- 筛选标准原文："filtered according to embodiment type, episode count, overall data quality, and frame coverage"——**具体阈值没给**，这是不可复现的点之一。

### 4.2 数据工程 ①：用 Qwen2.5-VL-3B 重写任务描述

社区数据的语言标注质量很差：占位符（`task desc`）、过于含糊（`Hold`、`Up`）、甚至没有。做法（§3.2 + 附录 A.1 p.20）：

- 采样每个数据集的代表性帧 + 原始指令 → 喂给 **Qwen2.5-VL-3B-Instruct** → 生成一句 ≤30 字符、以动词开头的动作描述。
- Prompt 原文（附录 A.1，p.20）要求："Generate a very short, clear, and complete one-sentence describing the action performed by the robot arm (max 30 characters)... Start directly with an action verb like 'Pick', 'Place', 'Open'."

> 精读提示：这一步很"工程"，但影响很大——VLA 的语言条件质量直接决定指令跟随。论文没报告重写前后的对比消融（比如用原始标注训练会差多少），所以"数据重写值多少分"是未知的。另外 30 字符上限也意味着模型学到的语言非常简短（LIBERO 的任务描述通常 >60 字符，见本机复现的 task string——比 30 字符长得多），这里有**预训练/微调的语言分布不一致**问题。

### 4.3 数据工程 ②：相机视角归一化

社区数据里相机命名混乱（`images.laptop` 可能是俯视、侧视或腕部）。做法：手工把每个相机映射到标准化视角类型，重命名为 `OBS_IMAGE_1/2/3`，优先级 **top > wrist > side**；多余视角直接丢弃。

> 为什么重要：VLA 对"哪个视角对应哪个 token 位置"很敏感。如果不统一，模型会把"俯视图"和"腕视图"混在一个位置上学，效果崩。这个设计在论文里只有一段话，但复现自己的数据时**必须做同样的映射**（LeRobot 用 `--rename_map`）。

### 4.4 批判点（详细见 `notes/04`）

- 481 个数据集清单在附录 A.1 里**不可靠**（逗号粘连、有重复、无法数出 481），而且里面出现 `Ashton3/lerobot-aloha` 等非 SO100 数据，与"单一机型"的说法矛盾。
- 没有数据规模消融（22.9K vs 更少会怎样？）——Table 5 只证明"有预训练 vs 无预训练"，没证明"22.9K 够不够"。
- 没有说明每个数据集怎么配比/采样（大 episode 数据集会不会主导训练？）。

## 5. §3.3 异步推理（p.5–8）

### 5.1 问题：chunk 执行期是"盲的"

现有两种做法（§3.3 第一段）：

| 策略 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **同步（sync）** | 执行完整个 chunk 再预测下一个 | 计算摊薄、平均开销低 | 预测期间机器人**空转/盲走**，产生 $\mathbb{E}[\ell_S]$ 的延迟 |
| **每步重算**（ACT/Diffusion Policy 常用） | 每个控制步都推理 + 重叠聚合 | 反应快、能纠错 | 每步一次前向，边缘设备扛不住 |

SmolVLA 的主张：**异步**——执行旧队列的同时，后台请求新队列，算好后聚合重叠部分。

### 5.2 Algorithm 1 逐行（p.6）

```
输入: horizon T, chunk size n, 阈值 g∈[0,1]
初始化: 采 o_0, 发给 PolicyServer, 收到 A_0 = π(o_0)
for t in 0..T:
    a_t ← PopFront(A_t)              # 从当前队列取一个动作
    Execute(a_t)                      # 执行
    if |A_t| / n < g:                 # 队列剩余比例低于阈值 → 该补货了
        capture o_{t+1}
        if NeedsProcessing(o_{t+1}):  # 相似度过滤：和上次差不多的观测就不发
            async_handle ← AsyncInfer(o_{t+1})    # 非阻塞触发
            Ã_{t+1} ← π(o_{t+1})                  # 服务端算新队列
            A_{t+1} ← f(A_t, Ã_{t+1})             # 在重叠时间步上聚合
    if NotCompleted(async_handle):
        A_{t+1} ← A_t                 # 还没算完就继续用旧队列
```

三个关键机制：

1. **阈值 $g$**：队列消耗到 $|A_t|/n < g$ 时触发新推理（注意：$g$ 越大越早触发）。§3.3 说 $g=0.7$ 是实践中好用的值（消耗约 30% 的 chunk 就补货）。
2. **相似度过滤**：把新观测和上次的观测在**关节空间**比距离，小于 $\epsilon$ 就丢掉（避免 queue 被几乎相同的 chunk 反复填满，导致机器人卡住）。队列空时强制处理，不管相似度。
3. **重叠聚合 $f$**：新旧队列在时间上重叠的部分做加权/融合，避免动作跳变。论文没给 $f$ 的具体形式（**复现难点**；LeRobot 后来的 RTC 实现才有明确形式）。

### 5.3 异步为什么能减少延迟：一个简单的数学

论文给的推导（§3.3 p.6–7）：

- 设 $\ell$ = 从发观测到收到 chunk 的总时间 = $t_{C\to S} + \ell_S + t_{S\to C}$（客户端→服务端传输 + 服务端推理 + 回传）。
- 假设通信时间两个方向相等且远小于推理时间：$\mathbb{E}[\ell]\simeq\mathbb{E}[\ell_S]$。
- 控制周期 $\Delta t$：真机 30 fps → $\Delta t = 33\text{ms}$。
- 结论：**只要 $g \ge \dfrac{\mathbb{E}[\ell_S]/\Delta t}{n}$，队列就不会在执行中耗尽**（不会出现空转）。

**代入本文的数**：$n=50$，$\Delta t=33\text{ms}$，若推理延迟 $\mathbb{E}[\ell_S]=100\text{ms}$，则 $g \ge (100/33)/50 = 0.06$——远小于论文用的 0.7。所以 $g=0.7$ 有很大安全余量（也意味着更频繁的观测处理）。这个不等式是读这一节最值得动笔算的东西。

### 5.4 Figure 3：$g$ 的三种极端（p.7）

| $g$ | 行为 | 后果 |
| --- | --- | --- |
| 0（顺序极限） | 队列耗尽才请求 | 每次都有 $\mathbb{E}[\ell_S]$ 的空转，和同步一样 |
| 0.7（异步） | 消耗约 30% 就请求 | 队列不空、计算摊薄，是论文推荐区间 |
| 1（算力极限） | 每个时间步都请求 | 最灵敏，但每步一次前向，边缘设备扛不住 |

Figure 3(B) 还展示了相似度过滤的作用：没有过滤时队列会被"几乎一样的观测"反复触发，曲线呈异常锯齿；过滤后正常。**红色箭头**标出队列空时强制处理的那个点——这是设计上的兜底逻辑。

### 5.5 真机结果与批判（Figure 5, p.12）

| 指标 | 同步 | 异步 | 变化 |
| --- | --- | --- | --- |
| 成功率（3 任务平均） | 78.3 | 73.3 | **−5.0**（其中 sorting 70→50，−20） |
| 平均完成时间 | 13.75 s | 9.70 s | **−29.5%** |
| 固定时间内完成次数 | 9 | 19 | **+111%** |

论文正文写 "both inference modes achieve comparable success rates"——**这个措辞偏乐观**：平均掉 5 个点、排序任务掉 20 个点不是"comparable"。而且异步的超参"只在 Pick-Place 上调过，然后复用到其它任务"（Figure 5 caption 原文），所以 sorting 的大跌很可能与超参不适配有关。这部分批判见 `notes/04` §6。

## 7. 与 π₀ 的异同：一张对照表（读 §2 时用）

| 维度 | π₀（Black et al. 2024） | SmolVLA |
| --- | --- | --- |
| 骨干 | PaliGemma-3B | SmolVLM2-500M（用前 16 层） |
| 动作生成 | flow matching + action expert | 同（继承） |
| expert 宽度 | 与 VLM 同宽（或更宽） | **0.75×** VLM 宽 |
| VLM 与 expert 的连接 | 拼成一个序列做**纯自注意力** | **交错 CA/SA**（偶数层 SA、奇数层 CA） |
| 时间步注入 | **AdaRMSNorm**（每层） | **输入处一次 MLP**（sinusoidal + MLP） |
| 训练时 VLM | 冻结 | 冻结（论文设置） |
| 数据 | 10,000 小时跨具身（OXE + 自采） | 22.9K episodes 社区 SO100 数据 + Qwen2.5-VL 重写指令 |
| 推理 | 同步 | 同步 + **异步栈**（额外贡献） |
| 参数量 | 3.3B | 0.45B（1/7） |

**核心洞察**：SmolVLA = **π₀ 的方法骨架 + SmolVLM2 小骨干 + 更省钱的双向/单向混合注意力 + 社区数据 + 异步系统**。论文的创新主要在"组合与工程"，而不是新的数学。所以精读它的价值在于**看每个工程选择的证据**，而不是找理论突破。
