# 一页说明：毕设选题建议（v3.1）

## 一句话

毕设方向暂定为**「面向机器人闭环控制的视觉语言动作模型高效推理与执行策略优化」**。
**具体创新点等 Baseline 跑通后再定**——现在不承诺任何一条创新主张。

## 本轮七条调整（相对 v3）

| # | 调整 | 影响 |
|---|---|---|
| 1 | **服务器列为正式实验平台候选**，不再默认只有 12GB 单卡 | 实验设计按「平台待定」编写，规格确认后即可锁定 |
| 2 | 12GB 准入分级**降为前期工程验收 + 辅助成果** | 它不再是首要创新点，只是「能不能开工」的闸门 |
| 3 | 优先 **OpenVLA-OFT 官方 LIBERO checkpoint**，备选 **π0.5 的 LIBERO 专用 checkpoint** | 目标从"挑小模型"变成"先跑通官方基线" |
| 4 | V14 的 suffix/prefix 结论**只适用于已审计的 OFT 代码版本** | 不外推到 π0.5 或其他实现 |
| 5 | 双实现对照**不声称已做因果分解** | 只报描述性差异，混杂如实标注 |
| 6 | T3′ 允许在**显存足够的服务器单卡**上做 BF16 vs 量化公平对照 | 不再要求 BF16 塞进 5070 |
| 7 | 方向措辞固定为上述一句 | 题目可先报，创新点后补 |

## 四条已确认的现状

1. **实验室没有现成的 VLA Baseline。** ⇒ 建立可复现 baseline 是毕设的**必要组成部分**，不是旁支工作，必须计入时间表。
2. **可以用实验室服务器，但 GPU 型号与显存未确认。** ⇒ 本页所有实验设计都写成「服务器优先、规格待填」。
3. **导师允许自主选择方向。** ⇒ 我按「先立平台、再选点」的顺序推进。
4. **下周需提出题目。** ⇒ 本页可直接作为题目与计划的初稿。

## 平台策略

| 平台 | 定位 | 说明 |
|---|---|---|
| **实验室服务器** | **正式实验平台**（首选） | 若单卡显存 ≥ 24 GB，可直接跑 OFT 7B 的 BF16 基线（参照值：4090 上 15.0 GiB，`🟦` 文献实测，非我方实测） |
| **RTX 5070 12GB** | 开发调试 + 量化小规模实验 + 服务器不可用时的退路 | 已知 BF16 的 OFT 放不下（15.0 GiB > 12 GB），故该卡上只做量化路线或小模型 |

`🟥` 服务器 GPU 型号/显存、CUDA/驱动版本均未知——这是**第一优先**要确认的信息。

## 三阶段计划

### 阶段 0：Baseline 跑通 + 工程验收（2–3 周）

| 项 | 内容 |
|---|---|
| 主目标 | 跑通 **OpenVLA-OFT 官方 LIBERO checkpoint**：`moojink/openvla-7b-oft-finetuned-libero-{spatial,object,goal,10}` |
| 备选 | **π0.5 LIBERO 专用 checkpoint**：`lerobot/pi05_libero_finetuned_v044` |
| 验收（辅助成果） | 三级：可加载 / 可推理（输出 `[P,7]`、无 NaN）/ 可评测（跑通 1 套件 1 episode） |
| 交付 | `env_report.md` + 准入表 + 一份可复现的评测命令 |

> 说明：checkpoint 标识符来自 VLAQuantBench 的公开记录（`🟦` 已核对该文 Table 14），**我方尚未下载**（`🟥`）。

### 阶段 1：执行策略与预算测量（4–6 周）

| 项 | 内容 |
|---|---|
| 对象 | **仅限已审计的 OFT 版本**（commit `e4287e9`） |
| 事实 | 该版本 `deque(maxlen=E)` 会保留**后缀**：`E=4` 实际执行槽 4…7，`E=1` 执行槽 7；`E=8` 时前后缀重合 |
| 做法 | 包装层做两臂：`original_suffix`（上游）与 `corrected_prefix`（`actions[:E]`），`E=8` 作共同锚点 |
| 度量 | `T_block=L+S+H`、`f_exec`、`ρ_infer`、块边界间隔、deadline miss 率 |
| **不声称** | **不声称已完成「重规划频率 vs 起始槽偏移」的因果分解**——两者在 `E<P` 时共变，只能报描述性差异 |

### 阶段 2：量化对照（4–6 周，需服务器）

| 项 | 内容 |
|---|---|
| 前提 | 服务器单卡能跑 **BF16 基线**（同卡同配置），否则对照组不成立 |
| 设计 | `{BF16, W8, W4} × {E=8, 4, 1}`，固定 `prefix` 为主、`suffix` 作消融 |
| 措辞 | 只研究「**量化方式与执行长度的交互**」；QVLA 已提出累积敏感度机制，**不声称首次发现** |
| 输出 | 若交互显著 → 部署建议；若不显著 → 边界结论（同样可写） |

## 关于创新点

- 现阶段**明确不承诺**创新点。三个方向（准入/预算、执行语义、量化交互）都只是**候选**。
- 我不把「某篇文献没有报告某个变量」当作原创依据；开题报告里只会写「**在本次检索边界内未见报告**」，并附检索范围与日期。
- 创新点将在阶段 0 结束后、基于**实测**的 baseline 与预算数据再确定——那时代码、数据、算力都已知，判断才可靠。

## 我想请您确认的五件事

1. **服务器规格**：GPU 型号、单卡显存、CUDA/驱动版本、是否可独占。（决定阶段 2 是否存在）
2. **权限**：是否批准在隔离环境安装依赖、下载官方 checkpoint 与 LIBERO 资产；放在哪个目录。
3. **平台取舍**：若服务器显存 < 24 GB，是否接受「以 5070 的量化路线为主、OFT 只作文献参照」的降级方案。
4. **题目措辞**：上面的方向表述是否可直接作为毕设题目上报，或需按学院模板调整。
5. **时间口径**：阶段 0 的两三周是否与开题/中期节点冲突。

## 下周讨论议程（30 分钟）

1. （5 min）过一遍平台策略与三阶段计划；
2. （10 min）确认服务器规格与权限范围——这是唯一会改变方案结构的变量；
3. （10 min）定题目措辞与上报材料；
4. （5 min）约定阶段 0 的验收标准与检查时间。

## 风险与退路

| 风险 | 退路 |
|---|---|
| 服务器显存不足以跑 OFT BF16 | 阶段 2 改为 5070 上的量化路线；OFT 仅作文献参照，不上机 |
| OFT checkpoint 跑不通（依赖/版本） | 切 π0.5 的 LIBERO checkpoint；两者都失败则阶段 0 延长，先解决环境 |
| 双实现对照无差异 | 结论为「`E` 效应非实现伪影」，仍是有效判定 |
| 仿真评测过慢 | 只做 1 套件 × 子集，明确标注非全套 |
| OpenFleX 迟迟不到位 | 全程仿真，真机只作加分项 |

> 一句话总结：**先把一个官方 baseline 跑通，再决定创新点。** 现在能承诺的是工程路径与判定标准，不是科学结论。
