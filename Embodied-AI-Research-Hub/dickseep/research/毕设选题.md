# 面向闭环控制的 VLA 高效推理：文献调研与本科毕设选题

2026-11-02

---

## 摘要

视觉语言动作模型（Vision-Language-Action, VLA）已经把「看到—听懂—动起来」统一进一个端到端网络，但在真实机器人上闭环跑起来仍然困难：模型大、单次推断慢、动作块与执行节拍对不齐。本文调研 2021–2026 年间 46 篇工作（主体集中在 2024 年之后），把它们按「优化对象」分成五条线——动作表征与分块、上下文与视觉 token、数值精度、解码与调度、系统架构——并逐条梳理每条线解决什么问题、用什么手段、报告了什么指标、以及哪些结论其实站不住。

调研得到三个判断。第一，**领域不缺加速技巧，缺的是可比性**：几乎所有工作报的是「相对倍数」，硬件、基座、评测任务各不相同；没有任何一篇在同一硬件上同时给出「绝对延迟 + 绝对显存 + 成功率」。第二，**「效率」的度量本身有问题**：有 2026 年的工作明确指出，降低 FLOPs 的方法往往增加端到端成本、降低动作质量，即使成功率不变。第三，**动作执行长度的语义在实现层是混乱的**：本地代码审计发现，官方 OpenVLA-OFT 在 `E<P` 时执行的是动作块的**后缀**而非前缀，而至少两篇 2026 年的工作把执行长度当作实验变量却没有声明这一点。

基于这些判断，本科毕设的方向定为「**面向机器人闭环控制的 VLA 高效推理与执行策略优化**」，前三周先跑通官方基线并测准预算指标，创新点待实测后确定。

## 1. 引言

### 1.1 VLA 是什么，为什么现在值得做

机器人操作长期有两条路线：一条是模块化的（感知 → 规划 → 控制），另一条是端到端学习。VLA 属于后者，它把视觉观测、语言指令和动作输出放进同一个 Transformer，用大规模机器人数据预训练，再微调到具体任务。

2022 年的 RT-1 把「大规模真实机器人数据 + Transformer 策略」这条路走通；2023 年的 RT-2 进一步证明，把网页-scale 的视觉语言知识迁移到动作上，可以显著提升泛化。但两者都不开源，社区无法复现。

转折点是 2024 年的 **OpenVLA**：7B 参数，970k 真实演示，完整开源权重与训练代码，在 29 个任务、多种本体上比 RT-2-X（55B）绝对成功率高出 16.5%，参数少 7 倍；比从零训练的 Diffusion Policy 高 20.4%。更重要的是它顺带证明了工程可行性：可以用 LoRA 在消费级 GPU 上微调，可以量化部署而不掉点。

此后一年，VLA 从「能不能work」转向「能不能用」：π0 引入流匹配动作专家，OpenVLA-OFT 把吞吐提高 26 倍，FAST 重新设计动作 tokenization，SmolVLA、TinyVLA 把模型压小，双系统架构把「慢思考」和「快执行」拆开。效率成为一个独立的研究方向。

### 1.2 闭环控制给推理提了什么要求

VLA 的推理不是「一次前向出一个答案」，而是嵌在一个控制回路里：

```
观测 → [预处理] → 模型前向（延迟 L） → 动作块（P 步） → 逐帧执行（每步 Δt） → 新观测 → …
```

这里有三件事容易混：

- **预测长度 `P`**：模型一次输出多少步动作。由网络结构与训练配置决定，改它等于改预测接口。
- **执行长度 `E`**：执行多少步后重新推理。理论上可调，但 `E ≤ P`。
- **控制周期 `Δt`**：执行端每步的真实墙钟时长，由仿真或机器人决定。

闭环能不能成立，取决于 `L` 与 `E·Δt` 的关系。而「动作块」这个设计（ACT 首创，2023）正是为了用一次性预测摊销推理成本——`E` 越大，重规划越少，但块内不再看新观测，误差会累积。

## 2. 工作背景：VLA 的三层结构

理解这 46 篇工作的关系，先把 VLA 拆成三层：

**基座层**——用什么样的 VLM，多大参数。OpenVLA 用 7B Llama-2 + SigLIP/DINOv2 双视觉塔；π0 用 PaliGemma 3B 加一个 300M 的流匹配动作专家；GR00T N1 用双系统；SmolVLA、TinyVLA 走小模型路线。

**动作表征层**——动作怎么生成。离散 token 自回归（RT-2、OpenVLA）、流匹配（π0、π0.5）、扩散（Diffusion Policy、RDT-1B、CogACT）、并行解码（OpenVLA-OFT）、一致性蒸馏（Consistency Policy、One-Step DP）。

**执行层**——动作怎么落地。动作块大小、重规划频率、异步执行、队列管理。这一层最不受重视，却直接决定真机能不能跑。

五条优化线分别对应这三层的不同位置：

| 线 | 优化对象 | 主要手段 | 副作用 |
|---|---|---|---|
| A 动作表征与分块 | 单帧要生成多少 token / 模型多大 | 动作分块、FAST tokenization、并行解码、小模型 | 块变长→开环误差 |
| B 上下文与视觉 token | 每帧重复算什么 | KV 缓存复用、视觉 token 剪枝、历史压缩 | 剪错 token→细微操作失败 |
| C 数值精度 | 每个算子多贵 | PTQ、1-bit 权重、量化感知训练 | 动作头对量化敏感 |
| D 解码与调度 | 生成 token 的方式 | 投机解码、并行解码、延迟感知分块 | 接受率下降→反变慢 |
| E 系统架构 | 谁在什么频率上跑 | 慢 VLM + 快策略、异步、分层 | 两级不一致 |

## 3. 基座模型谱系（线 A 的上游）

### 3.1 从 RT-1 到 OpenVLA

RT-1（2022）用 Transformer 处理 130k 演示，验证了规模化的可行性，但动作仍是离散 token、泛化有限。RT-2（2023）把动作当成文本 token 交给 VLM 生成，首次展示网页知识可迁移到机器人控制，但模型 55B、闭源。

OpenVLA（2024）是开源替代：7B、970k 演示、29 个任务上超过 RT-2-X 16.5 个百分点。它的工程贡献同样重要——论文明确写了「可用现代低秩适配在消费级 GPU 上微调，并可通过量化高效服务而不损失下游成功率」。这两句话成了后来大量工作的前提假设。

但 OpenVLA 有个结构性缺陷：动作是**离散 token 自回归生成**，7 个维度要生成 7 个 token，延迟高、且不适合高频控制。

### 3.2 流匹配与扩散路线

π0（2024）换掉了自回归：用流匹配（flow matching）训练一个动作专家，一次前向输出整段动作，配合 50 Hz 级别的控制频率，能做折叠衣服这类灵巧任务。π0.5（2025）在其上加入异构数据共训与高层子任务推理，把泛化推到开放世界家庭场景。

扩散路线并行的有 Diffusion Policy（2023，在 4 个 benchmark、12 个任务上平均比当时 SOTA 高 46.9%）、RDT-1B（2024，1B 参数的双臂扩散基础模型）、CogACT（2024，把 VLM 的认知与 DiT 的动作模块解耦）。

扩散的代价是采样步数：多步去噪意味着多次前向。于是有 Consistency Policy（2024）和 One-Step Diffusion Policy（2024），用一致性蒸馏把采样压到 1–4 步。这条线与「动作分块」是**正交**的加速轴，但很少有工作把它们放在一起比较。

### 3.3 小模型与效率导向基座

TinyVLA（2024）的动机写得很直白：现有 VLA「推理慢、且需要大量机器人数据预训练」。SmolVLA（2025）针对「十亿参数级模型训练贵、部署难」。这两个工作的共同问题是：**摘要都没有给出具体的加速数字**，只给了定性主张。

更彻底的效率改造是 **OpenVLA-OFT**（2025，RSS）：保留 7B 基座，但把自回归换成**并行解码**（一次前向出整块），动作头换成连续 L1 回归，配合动作分块。结果：LIBERO 四套件平均成功率从 76.5% 提到 97.1%，动作生成吞吐提高 **26 倍**；在双臂 ALOHA 真机上超过 π0、RDT-1B 的默认配方，以及从零训练的 DP、ACT，最高领先 15 个百分点。

这是本次调研里**唯一同时给出「速度」和「成功率」两个明确数字**的工作，也是后面所有「执行长度」讨论的代码基座。

### 3.4 其他

Octo（2024）是开源通用策略的另一条线，800k 轨迹、Transformer 结构、支持多本体与多目标；SpatialVLA（2025）关注空间表征；RoboFlamingo（2023）把冻结的 VLM 加轻量策略头，用少量演示做模仿学习。

## 4. 线 A 下：动作分块与执行策略

### 4.1 ACT：动作分块的起点

ACT（2023，RSS）提出两件事：**动作分块**（一次预测多步、执行多步再重规划）和 CVAE 结构。实验很朴素但有说服力：6 个真机任务，只用 10 分钟演示数据，成功率 80–90%，包括打开半透明调料罐、插电池这类精细操作。

动作分块的核心价值是把「每步都要推理」变成「每块推理一次」，直接摊薄了推理成本。但它同时引入一个新问题：块内是开环的。

### 4.2 块边界问题

RTC（2025，NeurIPS）把这个问题讲清楚了：动作分块虽然带来了时序一致性，但**并没有解决延迟问题**——推理延迟会让块边界出现停顿或跳变，动作变得不平滑。它的解法是延迟感知的实时分块拼接，摘要称对推理延迟鲁棒、能提升任务吞吐，在高精度任务（点蜡烛）上尤其明显。摘要未给具体数值。

### 4.3 自适应执行长度（2026 的两条独立路线）

既然固定 `E` 有两难——太小则频繁重规划、块间不连续导致抖动；太大则对新信息反应慢——自然有人做自适应。

**AAC**（2026，CVPR）用**动作熵**作为信号：熵低（模型确信）就执行更长，熵高就缩短；另加一个「最小动作幅值」约束避免块切得太碎。基座是 GR00T N1.5，真机用 Realman 单臂。它的 Table 4 给了一条「采样数—延迟—成功率」曲线：采样数 1/5/10/20/30/40 对应推断时间 **83.0 / 83.5 / 84.3 / 106.0 / 136.5 / 157.0 ms**，成功率 94.1 / 94.7 / 94.4 / 95.0 / 95.0 / 95.5%。真机三任务平均成功率从 67.0% 提到 82.0%。

**Knowing When to Stop**（2026）用另一路信号：动作专家内部的 **cross-attention 熵动力学**。基座是 π0.5 与 X-VLA，评测覆盖 RoboTwin 2.0、LIBERO 和三个真机任务。它给了完整的固定执行长度网格：

| 数据集 | 固定 E | 成功率 |
|---|---|---|
| LIBERO（均值） | 2 / 4 / 6 / 8 / 10 | 93.00 / 94.63 / 94.88 / 94.13 / 94.75 |
| LIBERO（均值） | 自适应 | **97.25** |
| RoboTwin 2.0（π0.5） | 10 / 15 / 20 / 25 | 61.6 / 58.0 / 53.8 / 52.2 |
| RoboTwin 2.0（X-VLA） | 15 / 20 / 25 / 30 | 43.5 / 64.9 / 74.1 / 76.1 |

这张表值得细看：**三个数据集的趋势方向不一致**。π0.5 在 RoboTwin 上 E 越小越好，X-VLA 在同一 benchmark 上 E 越大越好，而 LIBERO 上 E∈[4,10] 之间几乎平坦（极差 0.75 个百分点，E=6 与 E=10 只差 0.13）。这说明「最优执行长度」不是模型的固有属性，而与任务、基座、训练配置都有关。

它同时报了延迟：单次动作块推理 **0.2661 s**（fixed，A100，π0.5），自适应方法 0.2725 s（多 6.4 ms）；多采样基线要多 29.5 ms。真机设置里明确写了「图像 20 Hz、低层控制环 60 Hz」，执行器是 ARX R5 双臂。

### 4.4 并行解码与投机解码

**PD-VLA**（2025，IROS）针对「动作分块 + 自回归解码」的矛盾：既然一次要出整块，为什么还要逐 token 解码？改成并行解码后，7 自由度机械臂上的执行频率提高 **2.52 倍**，成功率保持竞争力。

**Spec-VLA**（2025，EMNLP）走投机解码路线：小模型起草、大模型校验，配合松弛接受策略。接受长度提高 44%，相对 OpenVLA 加速 **1.42 倍**，成功率不掉。

**SpecVLA**（2026，注意与上一条同名不同文）提出算法-系统协同设计：观察到机器人环境在「活跃态」（动作精确性关键）和「非活跃态」（动作影响小）之间交替，据此自适应平衡动作长度、延迟与可靠性，在 OpenVLA 和 RDT 上跨 LIBERO、ManiSkill 验证。

### 4.5 FAST：动作 tokenization

FAST（2025）从另一个角度切入：自回归 VLA 必须先把连续动作离散化，而 tokenization 方式直接决定序列长度与可学性。它用 DCT + BPE 压缩动作序列，让高维动作块变得可学。摘要未给量化指标，但这条线解释了为什么 π0 系列后来能用上 FAST tokenizer。

## 5. 线 B：上下文与视觉 token

这条线的共同假设是：**相邻帧的视觉信息高度冗余**。

**VLA-Cache**（2025，NeurIPS）按重要性决定哪些 token 复用、哪些重算，在 LIBERO、SIMPLER 和真机上测得 CUDA 延迟加速 **1.7 倍**、控制频率提升 **15%**，成功率损失可忽略。

**KV-Efficient VLA**（2025）关注的是 KV 缓存：保留历史图像 token 会让 KV 显存爆炸。它用 RNN 门控的 chunked cache 选择性保留高价值上下文，报告 FLOPs 减少 **24.6%**、加速 **1.34 倍**、KV 显存降低 **1.87 倍**。

**VLA-Pruner**（2025）指出视觉 token 剪枝会剪掉与动作相关的信息，提出时序感知的双层剪枝，在多架构上通用，最高加速 **1.99 倍**。

**SP-VLA**（2025）把「模型调度」与「token 剪枝」联合优化，LIBERO 上 1.5 倍、SimplerEnv 上 2.4 倍「无损」加速，平均性能还涨了 6%，推理频率与延迟改善 2.2×/1.4×。

这一组的共同特点是**训练无关**：只改推理路径，不需要重训。这使它们对小显存设备最友好。但四点要注意：

1. 全部只报相对倍数，没有一篇给绝对毫秒或绝对显存。
2. 「无损」「可忽略」这类词，需要回到正文看是「统计不显著」还是「每个任务都不掉」。
3. 剪枝类方法的风险是**长尾任务**：剪掉的 token 可能只在少数精细操作里关键，均值看不出来。
4. 缓存类方法与执行长度强耦合——`E` 越大，相邻帧越不相似，缓存命中率越低。这一点很少有人讨论。

## 6. 线 C：数值精度

### 6.1 三条技术路线

**BitVLA**（2025）走最激进的一条：全模型三值权重（{-1, 0, 1}），视觉编码器用 Quantize-then-Distill 压到 1.58-bit，但用全精度教师做表示对齐。结果与全精度 OpenVLA-OFT 持平，模型显存降低 **11.0 倍**、端到端延迟降低 **4.4 倍**。注意它需要量化感知训练（QAT），摘要自述「work in progress」。

**QVLA**（2026，ICLR）走通道级路线：先用「动作空间敏感度」给每个通道打分，再用全局贪心算法从全精度往下逐级降比特，同时把 0-bit 视为剪枝。在 OpenVLA 与 OpenVLA-OFT 上，量化版只需原模型 **29.2%** 的显存、保留 **98.9%** 性能、加速 **1.49 倍**，比从 LLM 迁移的 SmoothQuant 高 22.6 个百分点。实验在 RTX 4090 上完成。

值得注意的是它的 §3.2：作者明确指出单步误差指标「无法充分刻画长程自回归任务中的误差累积」，并提出 **cumulative sensitivity metric**——把「误差会在动作序列上复合」这件事显式建模进比特分配。

**QuantVLA**（2026，CVPR）走训练无关 PTQ：选择性布局——只把语言主干和 DiT 的前馈块整型化，attention 投影保持浮点，再用两个标量（ATM/OHB）做校准。它自称是首个 VLA 的 PTQ 框架、首个成功量化 DiT 动作头的工作。在 π0.5 上 W4A4 平均成功率 95.3%，被量化组件显存节省约 70%。

**SQAP-VLA**（2025）把量化与剪枝联合：量化感知剪枝框架，加速 **1.93 倍**，平均成功率还提升 4.5%。

### 6.2 VLAQuantBench：目前最系统的评测

2026 年 9 月的 **VLAQuantBench** 是这条线上规模最大的一篇：28 页、35 张表、409 次评测运行、94,574 个仿真 episode，覆盖 OpenVLA-OFT（四个 LIBERO 套件）、π0、π0.5、X-VLA。

它的主要发现：

- **8-bit 激活也可能造成严重损失**（与「8-bit 安全」的直觉相反）。
- **量化更多层反而能提升成功率**：π0.5 的动作头子集从 126 层扩到 167 层，未校准 W4A4 RTN 下成功率从 **7.0% 升到 70.5%**。
- **校准几乎免费**：只用 2 个 episode 的校准就消除了所测子集里的严重联合失效。
- **配方不可迁移**：同一套 smoothing-and-clipping 在 π0 上反而降低成功率，也不能恢复 OpenVLA-OFT。
- **单点保护足够**：对 OpenVLA-OFT，只保护一个 **28,672 参数**的输出投影，就能把成功率恢复到接近基线；其余 441 个线性层可以保持 W3 或 8-bit 激活。
- **省显存不等于省时间**：见下。

### 6.3 一个反直觉的结果：量化更慢

VLAQuantBench 的 Table 10 在 RTX 4090、batch=1、**仅量化 LLM（224 层）**的条件下测得：

| 方法 | 峰值显存 (GiB) | 控制调用 (ms) | 完整推理 (ms) |
|---|---|---|---|
| BF16 | **15.0** | 18.8 | **139.9** |
| AWQ | 6.1 | 24.1 | 181.1 |
| NF4 | 6.3 | 20.2 | 152.6 |
| LLM.int8() | 9.0 | 48.3 | 379.5 |
| SmoothQuant | 9.0 | 23.8 | 181.8 |

两点必须同时说：显存降了 2.5 倍左右，**但单次推理全部变慢**（+9% 到 +171%）。作者的限定是「这些结果描述的是所测实现与负载，而不是量化算法的普遍排序」。

这个结果对本项目的直接含义：**在 12GB 卡上，量化不是加速手段，而是能否运行的准入门槛**——BF16 的 15.0 GiB 已经超过 12GB。

## 7. 线 E：双系统与分层架构

**RoboDual**（2024）的观察很实际：通用大模型慢、专用小模型不通用。解法是双系统——通用 VLM 低频规划，专用策略高频执行，后者只需 **20M** 可训练参数。真机比 OpenVLA 高 26.7%，CALVIN 上高 12%，只用 5% 演示数据仍保持性能，控制频率提升 **3.8 倍**。

**Fast-in-Slow**（2025）把双系统塞进一个模型：System 1 嵌入 System 2，**部分参数共享**。仿真成功率 +8%、真机 +11%，控制频率 **117.7 Hz**（动作块为 8）。

**DualVLA**（2025）做推理与动作的**部分解耦**：SimplerEnv 平均成功率 61.0，八个多模态 benchmark 平均 65.4。

**GR00T N1**（2025，NVIDIA）是面向人形机器人的双系统基础模型；**Hi Robot**（2025，ICML）是分层 VLA，高层理解指令与反馈、低层执行。

这一组的共同贡献是**把「模型加速」翻译成「机器人行为改善」**：控制频率是唯一对任务有意义的指标。但三点要注意：

1. 「控制频率」在不同论文里定义不同（有的指模型吞吐，有的指实际执行频率）。
2. 双系统带来的是**异步**架构，而多数仿真评测并不模拟延迟，所以论文里的增益在真机上可能打折。
3. Fast-in-Slow 的 117.7 Hz 对应 chunk=8 的小块，不能外推到长块。

## 8. 评测、基准与「度量本身」

### 8.1 基准

- **LIBERO**（2023）：lifelong 学习的操作基准，四个套件（Spatial / Object / Goal / Long），每套件 10 任务，标准评测是每任务 50 个 episode、共 500 个，初始状态固定。
- **SimplerEnv**（2024）：与真机对齐的仿真评测，用来缩小 sim-real gap。
- **CALVIN**（2021，RA-L）：长程语言条件操作。
- **Open X-Embodiment**（2023）：跨本体数据集合，294 位作者，是预训练数据的事实标准。
- **DROID**（2024）：大规模真实场景数据集，101 位作者。

### 8.2 两篇综述

**VLA 综述**（2024）：把领域分成组件（视觉表征、动力学、世界模型、推理）、控制策略、任务规划三层，加上数据与基准的支撑层。

**高效 VLA 综述**（2025，TPAMI 录用）：系统梳理压缩、加速、数据效率的方法。

### 8.3 对「效率」度量的批判

**From Inference Efficiency to Embodied Efficiency**（2026）是本次调研里少数直接质疑评价体系的工作。它指出：当前用参数、FLOPs、token 吞吐衡量的「效率」，**并不能反映机器人在真实平台上的表现**——降低计算量的方法常常增加端到端执行成本或降低动作质量，即使任务成功率没变。

这条结论如果成立，会推翻大量工作的评价方式。它也是本项目把「控制频率、块边界间隔、动作抖动」纳入指标的理由。

### 9.2 指标缺口

把上表的「延迟 / 吞吐 / 显存 / 成功率」四列单独看，会发现一个结构性空缺：

- 报延迟的，多半只报相对倍数（VLA-Cache、SP-VLA、Spec-VLA）；
- 报绝对延迟的，只有 KWS（0.2661 s，A100）和 AAC（83–157 ms，GPU 未声明），且两者基座不同、硬件不同，**不可比**；
- 报绝对显存的，只有 VLAQuantBench（15.0 GiB 等，4090）；
- 报成功率的，绝大多数。

**没有任何一篇在同一硬件上同时给齐「绝对延迟 + 绝对显存 + 成功率」。** 这意味着「在我这张卡上能跑多快」这个问题，在现有文献里引用不到答案，只能自己测。

## 10. 五个被反复引用但站不住的说法

1. **「量化能加速」**——在消费级单卡、batch=1 的条件下，VLAQuantBench 实测四种量化实现全部变慢。显存确实降了，延迟没有。（限定条件：4090、仅 LLM 量化、特定 kernel。）
2. **「无损加速」**——多数工作没给每任务方差，也没给置信区间；「无损」可能只是均值上不显著。
3. **「最优执行长度存在」**——三个数据集的趋势方向不一致（π0.5 越小越好、X-VLA 越大越好、LIBERO 平坦），说明它不是模型的固有属性。KWS 给出的 LIBERO 网格里，E=6 与 E=10 只差 0.13 个百分点，且没有置信区间，不足以支撑「内点最优」。
4. **「1-bit 可以不掉点」**——目前只有 BitVLA 一篇，且自述 work in progress，需要 QAT。
5. **「FLOPs 降了就更快」**——2026 年的效率度量批判直接指出这个等价不成立。

## 12. 一个具体发现：执行长度的实现陷阱

本地审计 OpenVLA-OFT（commit `e4287e9`）时发现一个具体问题。

LIBERO 配置下模型一次预测 8 步（`P=8`，动作维度 7），`get_action` 返回完整 8 个动作。但执行循环用的是 `deque(maxlen=E)`，把完整 8 步 `extend` 进去后，**有界队列从左侧淘汰**，所以留下的是末尾 E 个：

| 配置 `E` | 实际执行槽 | 设计意图 |
|---|---|---|
| 8 | 0…7 | 0…7 ✔ |
| 4 | **4…7** | 0…3 ✘ |
| 2 | **6…7** | 0…1 ✘ |
| 1 | **7** | 0 ✘ |

只有 `E=8` 时两者重合。这意味着：**任何只改 `num_open_loop_steps` 去扫执行长度的实验，同时改变了「执行几次」和「从第几步开始执行」**，两者无法分离，但论文里通常只报告前者。

同时，该入口是**同步阻塞**的：队列空了才推理，推理完再逐步执行，推理与执行没有重叠。所以常用的 `max(E·Δt, L)`、「`L ≤ P·Δt` 就能不间断闭环」这类判据在这个入口上不成立。实际块周期是 `T_block = L + S + H`（推理延迟 + 各步仿真耗时 + 各步其他开销），平均速率预算是 `L ≤ E[Δt_target − (s+h)]`。

修复很简单（`action_queue.extend(actions[:E])`），但**这个发现只适用于这个 commit**，不能外推到 π0.5（openpi/lerobot）或其他实现——它们的执行代码我没有审计。

## 13. 对本毕设的含义

### 13.1 选题

方向定为「**面向机器人闭环控制的视觉语言动作模型高效推理与执行策略优化**」。前三周不碰创新点，先做三件事：

1. 跑通 OpenVLA-OFT 官方 LIBERO checkpoint（备选 π0.5 的 LIBERO checkpoint）；
2. 做三级验收：可加载 / 可推理 / 可评测；
3. 测准预算指标：`L`、`step_wall`、`H` 的 p50/p95/p99，以及块边界间隔。

拿到这些数字之后，再从三个候选方向里选：

| 方向 | 科学问题 | 前提 |
|---|---|---|
| A 执行语义与预算判定 | 「执行长度效应」里有多少来自起始槽偏移？（只做描述性对照） | 12GB 即可 |
| B 量化方式 × 执行长度交互 | 量化惩罚是否随开环执行变长而放大？ | 服务器能跑 BF16 基线 |
| C 12GB 准入基准 | 三级分别卡在哪？ | 12GB 即可，创新性弱 |

### 13.2 为什么先做基线而不是先选点

因为现在缺的不是想法，是**实测数字**。比如「执行长度效应」这个方向，如果实测发现 `L` 远小于目标周期，那整个题目就失去张力；如果服务器显存不够，量化方向就不成立。先测再选，比先选再找证据可靠。

### 13.3 三周计划

| 周 | 做什么 | 产出 |
|---|---|---|
| 1 | 环境 + 权重 + 跑通 1 episode | 一条可复现命令、版本表 |
| 2 | 三级验收 + 计时脚本 | 准入表、预算指标 |
| 3 | `E∈{8,4}` × `{后缀, 前缀}` 各一个套件子集 | 方向性对比表 |
