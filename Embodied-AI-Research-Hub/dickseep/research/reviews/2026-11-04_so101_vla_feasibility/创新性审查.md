## 1. 三篇决定性论文做到了什么

### 1.1 Cowling（2026）：离线指标 vs 真机成功 🟦

- 平台：**一台 SO-101**；策略：**ACT / Diffusion Policy / SmolVLA / π₀.₅（仅动作专家）**。
- 数据：**12—200 条嵌套演示子集**，一个 pick-and-place 任务；70 次训练、**700 个中间 checkpoint**。
- 评测：25 条 held-out 演示上给 **82 个 checkpoint** 打分，与 **930 次台面 rollout** 对照。
- 结论（摘要级，已核实为原文英文摘要）：
  - 同一策略内，held-out **动作误差**与台面成功率相关（Spearman ρ 从 −0.23 到 −0.88），但**并不比"训练集条数"单独一个变量更强**；同数据不同种子之间**完全不相关**。
  - **跨策略排名是反的**（200 集时 ρ = +0.90）：held-out 误差最低的策略在 **110 次 rollout 里只成功 3 次**。
  - **最常见的失败是"臂始终没有离开静止姿势"**：在未裁剪演示上训练的 Diffusion Policy 有 **96%** 的 rollout 如此，SmolVLA 为 **47%**；而这种失败**在由演示构成的 held-out 集里根本不可能出现**。
  - 在"臂确实动起来"的 rollout 里，SmolVLA 的 held-out 动作误差预测成功率较好（ρ = −0.81）。
  - 对 diffusion / flow 策略，**held-out loss 在训练中上升 2—5 倍**，而 held-out 动作误差**下降最多 29%**。
  - 建议：**把"启动失败"与"已启动 rollout 中的成功"作为两个独立的实验结果报告。**

**对你的直接含义**：① 你的评测协议**必须**拆分启动失败；② **不要**把"离线误差能预测成功"当卖点（已被证伪式回答）；③ 这条论文本身就是"低分平台 + 四策略"的先例，**你不能再把它当创新点**。

### 1.2 VLA-HWBench（2026）：边缘硬件上时间去哪了 🟦

- **18 个 VLA 模型**，**7 阶段**分解（预处理 / 视觉 / LLM / 动作生成 / …），平台 **NVIDIA Jetson AGX Thor** 与 **AMD Ryzen AI Max+ PRO 395**。
- 关键发现：
  - **动作生成**在 19 个配置中的 **14 个**里是最大阶段；延迟跨度 **Jetson 82×、AMD 157×**。
  - **参数量只能解释 ≤15% 的延迟方差**。
  - 生成**长动作块 + 少流匹配步**的模型跟得上控制；**逐 token 解码**跟不上。
  - **4-bit 权重 + kernel fusion** 让 π₀.₅ 与 GR00T N1.7 比 PyTorch + `torch.compile` **快 2.6—2.9×**，但**只对这两个模型、只在 Jetson 上存在**。
  - 优化会**把时间挪到它缩短最少的阶段**（GR00T N1.7 的调用里 CPU 预处理从 12% 涨到 39%）。
  - 优化后：少 token 的阶段受**内存带宽**限制，其余受**软件**限制。

**含义**：你"测推理延迟"的做法，人家已经用 7 阶段分解做成了基准。"参数量解释 ≤15% 方差"这一条，直接否掉了"按模型大小推断速度"的朴素比较。

### 1.3 VLALagBench（2026）：延迟为何、何时重要 🟦

- 主基准在 **MuJoCo**，另在 **Isaac Sim 与真机**做验证（第 2 页原文明确）。
- 五因子：任务类型（Release / Set-down / Grabbing / Articulated）、目标速度、VLA 策略（π₀.₅ / GR00T N1.7 / MolmoAct2）、**执行模式（同步/异步）**、**受控的推理延迟**。
- 术语：**K = action chunk size（预测步数）**，**H = execution horizon（执行步数）**，原文明确写"**执行一个短前缀（H < K）**"。
- 关键结果：
  - 100 ms 延迟在某任务上把成功率从 **71.5% 砍到 40.5%**；另一个任务只掉到 **74.0%（保留 86%）**。
  - 机制：**观测过时**（做决策时目标已移动）＋ **同步推理造成的机器人停顿**。
  - **异步执行**能挽回"连续运动"类任务的损失，代价是**更频繁的推理请求**。
  - 用少量标定数据拟合成功率模型，**RMSE 5.7—7.8%**，据此为给定系统选择**执行模式与动作时域**（机上 GPU / 共享服务器 / 远程云）。

**含义**：同步 vs 异步、执行时域选择——**已经是别人论文里的"决策变量"了**。

### 1.4 一条关键的自证：静态任务里延迟不影响成功率

VLALagBench 第 3 页明确写道：由于 LIBERO 等基准是**静态物理环境**，"**更长的推理延迟会增加任务完成时间，但不会直接影响任务结果**"。

**这条既是坏消息也是你的机会**：

- 坏消息：如果你的任务是静态桌面抓放，那么"扫延迟看成功率"**在概念上就是一条平线**，做出来不新。
- 机会：**没有人**在低成本真机上回答"既然延迟不改变成功率，那么静态抓放的失败到底由什么主导"。

## 3. 尚未被充分解决的具体问题

### G1 静态任务里"延迟不敏感"的边界与主导变量 🟦🟨

- **问题**：在低成本真机的静态抓放中，成功率的主导变量是延迟、执行长度、定位精度，还是启动失败？各自贡献多少？
- **为什么还没解决**：LagBench 主动把静态任务排除在"延迟敏感"范畴之外（它要研究动态任务）；Cowling 只研究离线指标，不研究执行/延迟。
- **可证伪假设 H1**：在静态抓放中，把推理延迟从 ~0 提高到 300 ms，成功率变化 < 10 个百分点（即"平台型"曲线），而定位误差从 1 mm 提高到 5 mm 时成功率显著下降。
  - **若 H1 成立**：产出"低成本平台的延迟预算可以很宽松，钱应该花在机械精度上"的工程结论——这对所有做低成本 VLA 的人有用。
  - **若 H1 被否证**：产出"即使在静态任务里延迟也敏感，原因是 X"——同样有用，且直接挑战 LagBench 的静态假设。

### G2 执行语义（前缀 / 后缀）作为必控因子 🟦

- **问题**：当 `H < K` 时，实现执行的是动作块的**前缀**还是**后缀**？这个差异是否足以改变"执行长度效应"的估计？
- **事实基础**：LagBench 明确假设"短前缀"；而本地源码审计（commit `e4287e9`）显示上游 OpenVLA-OFT 用 `deque(maxlen=E)` 接收完整块，**`E<P` 时执行的是后 E 步**。
- **为什么值得**：如果 LagBench 类研究依赖的实现在某些分支上是后缀，那么其 H 效应估计**可能含有系统性偏移**。
- **风险（必须承认）**：这可能只是"少数实现的小 bug"，不构成方法学问题；若两实现成功率差异不显著，此点退化为复现。

### G3 机械定位精度进入闭环因果链 🟦🟨

- **问题**：定位工装 / 快换接口的重复定位误差，是否等价于额外延迟？给定延迟预算，定位精度需要做到多少？
- **为什么还没解决**：三篇重叠论文**没有一篇有机械自变量**（它们的自变量全是模型、硬件、延迟、执行模式）。
- **为什么适合你**：这是机械工程本科唯一能合法占据的位置，也是"大组不会做"的位置。

### 结论

- **最推荐：A——但必须是"带机械变量"或"带语义变量"的 A**，不能是裸的"同步 vs 异步"。
- **备选（风险更低）：D + G1 的组合**——即"统一评测"作为方法，但**研究问题锁定在"静态任务的主导变量"**上。它比裸 D 多一个明确命题，且不需要改执行层。

## 6. 三个必须承认的审查意见（自我批评）

1. **"低成本平台"本身价值有限**。评审可能说："换成便宜机械臂，结论有什么不同？"你必须提前准备答案：**便宜的代价是定位精度与重复性差，这会改变延迟—精度的权衡关系**——这才是低成本平台值得单独研究的理由。
2. **H1 有相当概率被否证**。若实测发现延迟确实敏感，你的第一章叙事要改写为"低成本平台同样敏感，且原因是舵机响应延迟 `l_mech`"——所以**必须一开始就把 `l_mech` 测起来**（用电流/位置响应或高速相机）。
3. **G2 可能是伪问题**。若各实现差异不显著，它只是一次复现。**把它当"必控因子"而非"发现"来写**，即使无差异也有方法学价值。
