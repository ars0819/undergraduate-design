## 2. 通道实测（本轮结论：学术 API 全部不可达）

| 通道 | 目标 | 结果 |
|---|---|---|
| `curl.exe`（进程级） | `export.arxiv.org` / `api.crossref.org` / `api.openalex.org` / `huggingface.co` | **HTTP 000**（连接失败） |
| `curl -x http://127.0.0.1:7890` | 同上 | **HTTP 000**（无代理环境变量，且该端口不通） |
| harness `web_fetch` | `export.arxiv.org/api/query` | 上轮可用，**本轮变为** `resolves to a non-public IP address` |
| harness `web_fetch` | `huggingface.co` / `api.github.com` / `raw.githubusercontent.com` / `cdn.jsdelivr.net` / `hf-mirror.com` / `people.csail.mit.edu` / `causalai.net` | 全部 `resolves to a non-public IP address` |
| harness `web_search` | 通用 | 可返回结果列表，但**摘要不能作为元数据来源** |

**原因判断**🟨：用户开启了全局代理，且为 **fake-ip 模式**——非直连域名被解析成保留地址（如 `198.18.x.x`），harness 的安全策略拒绝访问；而进程级 socket 另受沙箱阻断。

**后果**：本轮**无法新增任何联网检索**。所有新证据来自用户桌面 PDF。

## 4. 本轮新增证据（逐条）

### E1｜Cowling 2026（arXiv:2611.00283v1）

| 断言 | 证据位置 | 级别 |
|---|---|---|
| 一台 SO-101 上训练 ACT / Diffusion Policy / SmolVLA / π₀.₅（仅动作专家） | 摘要 | 🟦 |
| 12—200 条嵌套演示子集；70 次训练；700 个中间 checkpoint | 摘要 | 🟦 |
| 82 个 checkpoint × 25 条 held-out 演示 对照 930 次台面 rollout | 摘要 | 🟦 |
| 策略内 held-out 动作误差与成功率相关（Spearman ρ −0.23 ~ −0.88），但不强于"训练集条数"单独变量；同数据不同种子间完全不相关 | 摘要 | 🟦 |
| 跨策略排名反转（200 集时 ρ=+0.90）；held-out 误差最低者在 110 次 rollout 中仅成功 3 次 | 摘要 | 🟦 |
| 最常见失败 = 臂未离开静止位；Diffusion Policy 96%、SmolVLA 47%；该类失败在演示构成的 held-out 集中不可能出现 | 摘要 | 🟦 |
| 臂移动后，SmolVLA 的 held-out 动作误差预测成功率较好（ρ=−0.81） | 摘要 | 🟦 |
| diffusion/flow 策略的 held-out loss 训练中上升 2—5 倍，而动作误差下降最多 29% | 摘要 | 🟦 |
| 建议把"启动失败"与"已启动中的成功"作为两个独立结果报告 | 摘要 | 🟦 |

**支持/反驳**：**反驳**"离线指标可替代真机评测"；**支持**本方案把"启动失败率"列为独立指标。

### E2｜VLA-HWBench（arXiv:2610.34717v2）

| 断言 | 证据位置 | 级别 |
|---|---|---|
| 18 个 VLA 模型、7 阶段分解、Jetson AGX Thor + AMD Ryzen AI Max+ PRO 395 | 摘要 | 🟦 |
| 动作生成在 19 个配置中的 14 个里是最大阶段 | 摘要 | 🟦 |
| 延迟跨度 Jetson 82×、AMD 157×；参数量仅解释 ≤15% 方差 | 摘要 | 🟦 |
| 长动作块 + 少流匹配步可跟上控制；逐 token 解码不行 | 摘要 | 🟦 |
| 4-bit + kernel fusion 使 π₀.₅ / GR00T N1.7 快 2.6—2.9×，但仅限这两个模型且仅 Jetson | 摘要 | 🟦 |
| 优化使 CPU 预处理占比从 12% 升至 39%（GR00T N1.7） | 摘要 | 🟦 |
| 优化后少 token 阶段受内存带宽限制，其余受软件限制 | 摘要 | 🟦 |

**支持/反驳**：**反驳**"按参数量推断部署速度"；**表明**"测延迟"已是成熟基准，不宜作为创新点。

### E3｜VLALagBench（arXiv:2611.03103v1）

| 断言 | 证据位置 | 级别 |
|---|---|---|
| 主基准在 MuJoCo；另在 Isaac Sim 与**真机**验证 | 第 2 页 | 🟦 |
| 五因子：任务类型（Release/Set-down/Grabbing/Articulated）、目标速度、VLA 策略、执行模式、受控推理延迟 | 第 2 页 | 🟦 |
| **K = action chunk size，H = execution horizon**，并明确"执行一个短**前缀**（H<K）" | 第 3 页 | 🟦 |
| 100 ms 延迟使某任务成功率 71.5%→40.5%；另一任务仅 86.5%→74.0% | 第 2 页 | 🟦 |
| 机制：观测过时 + 同步推理造成的机器人停顿 | 第 2 页 | 🟦 |
| 异步执行可挽回连续运动任务，代价是更频繁推理请求 | 第 2 页 | 🟦 |
| 用少量标定数据拟合成功率，RMSE 5.7—7.8%，指导选择执行模式与动作时域 | 第 1—2 页 | 🟦 |
| **静态环境基准中，延迟增加任务完成时间但不直接影响任务结果** | 第 3 页 | 🟦 |
| 既有异步/自适应工作（ReflexBench、RTC 等）未联合变化任务类型、速度、执行模式与通用策略 | 第 3 页 | 🟦 |

**支持/反驳**：这是本轮**最关键的一条**——它既封住了"静态任务扫延迟"的路，也**指出了本方案的立足点**（静态任务里延迟之外的主导变量）。
