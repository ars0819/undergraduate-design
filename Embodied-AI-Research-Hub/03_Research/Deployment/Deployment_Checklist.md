# Deployment Checklist

> 用于把“模型能输出动作”推进到“系统能安全、可复现地执行”。  
> 本清单是通用工程检查，不是 OpenFleX 的已验证接口规范。

## 1. 接口契约

| 项目 | 必须写清 | 证据 |
|---|---|---|
| 图像 | 相机数量、键名、分辨率、颜色顺序、时间戳 | 实际 topic/文件名 + 一帧样例 |
| 语言 | instruction 来源、长度、编码 | 样例 + tokenizer 版本 |
| 本体状态 | 维度、顺序、单位、坐标系 | schema + 样例 |
| 动作 | 维度、顺序、单位、绝对/相对、夹爪符号 | schema + 反归一化代码 |
| 控制 | 频率、超时、动作有效期、急停 | 控制器文档/测试 |
| 版本 | 模型/代码/配置/权重 hash | manifest |

## 2. 时间与性能

- 端到端：观测→预处理→推理→后处理→控制命令。
- 新动作块 p50/p95；缓存动作不算。
- 控制周期是否能覆盖最坏延迟？不能覆盖时怎么办（丢帧/降速/停机）？
- 队列积压、时间戳错位、动作过期如何处理？

## 3. 安全与失败

- 输入 NaN/维度错/越界/超时：拒绝下发，记录原因。
- 动作限幅、速度/加速度限制、工作空间限制。
- 通信中断/模型崩溃/显存 OOM 的 fallback。
- 仿真保护不等于真机安全认证；真机需要额外风险评估/急停/人工监督。

## 4. 可观测性

- 每次 episode：配置、初态、动作、终止原因、成功判据、墙钟、视频索引。
- 失败分类：模型/依赖、渲染/初态、接口/归一化、抓取未成、掉落、放置不达标、超时、约束拒绝。
- 原始日志不可被覆盖；重跑规则写清。

## 5. 复现

- 新进程按 README 复跑关键命令。
- 权重/processor/数据 hash；环境 freeze；代码 commit。
- 大文件放外部目录，不放进本库。

## 6. OpenFleX 待核实

以下全部**未验证**，不得写成已具备：

- 底盘/双臂自由度、关节顺序、控制协议；
- ROS/SDK、相机型号/标定、时间同步；
- 急停、限速、碰撞检测、工作空间；
- 控制频率、动作接口、是否支持动作块；
- 演示数据/遥操作/安全责任人。

## 7. 与本科毕设的关系

- 先 LIBERO 仿真闭环，再做接口规格；不承诺零样本迁移。
- LIBERO 单臂 7 维动作不能直接复制到轮式双臂。
- 仿真成功只证明仿真协议内有效；真机部署需单独验证。
