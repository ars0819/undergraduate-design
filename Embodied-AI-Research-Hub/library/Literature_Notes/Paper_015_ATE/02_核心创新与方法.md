## 一、创新的分级

### A. 最重要的创新（只选 1 项）

> **Euler Cost：把地形通行代价从"各向同性标量"改成"路径方向与地形梯度的解耦函数"，用 $\sin^2\alpha$ 重罚横穿、用 $\cos\alpha$ 区分上下坡。**

为什么是它：
- 传统代价 $\text{cost}=f(\theta)$（只看坡度）；
- 本文代价 $\text{cost}=f(\theta,\alpha)$（坡度 × 方向）；
- 这一个改动直接让最大侧倾降 5–8 度。

而且它**几乎不加计算**——因为在稀疏图上算，节点数少了几个数量级。

### B. 其他有价值的改进

| 改进 | 价值 | 是否首创 |
|---|---|---|
| **图像域 Sobel 卷积算坡度** | $O(N^3)\to O(N^2)$，快几个数量级 | ★ 巧妙的"降维" |
| **双阈值迟滞分类** | 解决单阈值在边界处的高频翻转 | 借鉴图像处理（Canny） |
| **只在坡上采样稀疏节点** | 图规模大幅缩小 | ★ 关键设计 |
| **85 百分位高度** | 抗点云离群 | 工程细节 |
| **朝向一致性效用 $\Delta\psi$** | 消融显示：去掉后累计偏航翻倍 | ★ 实战有效 |
| **Two-Opt 序列优化** | 比贪心更平滑的探索序列 | 常见 |
| **平地退化分析（Scene 3）** | 诚实地证明"优势休眠时不拖后腿" | ★ 好的实验设计 |

### C. 借鉴已有研究的技术

| 技术 | 来源 | 角色 |
|---|---|---|

### D. 工程实现与实验设置

- 仿真：i5-10200H + 32 GB（模拟机载中端算力）；
- 三场景：769 / 2803 / 3160 m²；每方法 5 次；探索到 95% 可通行面积；
- 平台：四轮差速 1.0 m/s（仿真）、0.5 m/s（真机）+ 四足 Lite3；
- 传感器：RoboSense LiDAR；SLAM：FAST-LIO。

> **本文的原创性 ≈ "方向 × 梯度"的代价解耦 + "图像算子替代几何拟合"的降维。**

## 二、核心创新的八个追问

### ① 以前的研究通常怎么处理"地形可通行性"？

| 路线 | 做法 | 问题 |
|---|---|---|
| PCA/SVD 局部平面拟合 | 从点云拟合法向量、算坡度 | $O(N^3)$；点云截断会让法向量崩溃 |
| 各向同性标量代价 | 坡度/粗糙度 → 一个数 | **丢掉方向信息** |
| 方向性风险（TRG） | 分垂直/水平风险 | 在稠密全局采样下太贵 |
| CVaR 尾部风险（STEP） | 局部风险感知 | 非凸优化，不适合大范围图搜索 |

### ② 原有方法的缺点是什么？

| 缺点 | 原文依据 | 我的核查 |
|---|---|---|
| 几何拟合计算量大 | §I："extremely high computational burden" | 成立，$O(N^3)$ |
| 法向量估计会崩 | §I："collapse of normal vector estimation" | 成立 |
| 各向同性忽略进入角度 | §I："ignoring the angle differences of robots entering the terrain" | **这是本文的立论** |
| 3D 稠密采样维度爆炸 | §I | 成立 |

### ③ 作者具体修改了什么？

**四处**：

**(1) 表示：3D → 2.5D**
$$H(u,v)=\text{85th percentile}\{\text{points in cell}\}$$
每格取 85 百分位高度（抗离群）。

**(2) 梯度：拟合 → 卷积**
$$G_x=H*S_x,\quad G_y=H*S_y,\quad \theta=\arctan\left(\frac{\sqrt{G_x^2+G_y^2}}{\text{Res}}\right)$$

**(3) 分类：单阈值 → 迟滞**
$$S_t=\begin{cases}S_{slope}, & \theta>\tau_{f\_high}\ \lor\ (\theta>\tau_{f\_low}\land M_{t-1}=S_{slope})\\ S_{flat}, & \text{otherwise}\end{cases}$$

**(4) 代价：各向同性 → Euler Cost**
$$C_{terrain}=d_{base}\cdot\max\left(0.1,\ 1+\omega_{slope}s_{avg}\cos\alpha+K_{cross}s_{avg}\sin^2\alpha\right)$$
$$C_{Euler}=C_{terrain}+K_{turn}\cdot\frac{1-\cos\beta}{2}\cdot d_{base}$$

### ④ 修改发生在哪一层/哪一环？

```
LiDAR 点云 → 2.5D 高程图（降维）
          → Sobel 卷积（快）→ 坡度图
          → 迟滞分类（稳）→ 平/坡/障 mask
          → 只在坡上采样 → 稀疏节点集 V
          → Euler Cost 连边 → 稀疏图 G=(V,E)
          → 2D 可达域 + frontier → Two-Opt → 目标序列
```

**改动贯穿"感知表示 → 图构建 → 代价 → 探索"四层**，但每一层都只做了一件事：**降维或加方向**。

### ⑤ 为什么这种改变有效？

**(a) 为什么 Sobel 能替代平面拟合？**
- 平面拟合要解协方差矩阵的特征值（$O(N^3)$）；
- Sobel 只是两个 $3\times3$ 卷积核，$O(N^2)$；
- 在"高程图"这个规则网格上，梯度本来就可以用差分算——**这是降维带来的红利**。

**(b) 为什么迟滞分类必要？**
- 单阈值在 $\theta\approx\tau$ 附近会高频翻转（噪声导致）；
- 双阈值 + 上一帧状态 = **迟滞（hysteresis）**：进入难、退出也难，状态稳定；
- 这与 Canny 边缘检测的双阈值是同一个思想。

**(c) 为什么 $\sin^2\alpha$ 能表达"横穿风险"？**
- $\alpha$ 是行进方向与梯度的夹角；
- $\alpha=0$（顺坡）：$\sin^2=0$，只有 $\cos\alpha=1$ 的纵向项；
- $\alpha=90°$（横穿）：$\sin^2=1$，横向惩罚最大、纵向项为 0；
- $K_{cross}\gg\omega_{slope}$ → 横穿被重罚。

**(d) 为什么只在坡上采节点？**
- 平地可以自由走，不需要拓扑引导；
- 只在"危险区"建图 → 节点数大幅减少 → 精细的各向异性代价才负担得起。

### ⑥ 它引入了什么新代价？

| 新代价 | 说明 | 证据 |
|---|---|---|
| **延迟 +10 ms** | 30 vs 20 ms | 表 I |
| **效率略降** | η 5.34 vs 5.45；路径 +15% | 表 I |

### ⑦ 与最接近的前人方法有什么区别？

| 维度 | LRAE | TARE | TRG | **本文** |
|---|---|---|---|---|
| 地形分析 | 3D 模块 | 只分平/障 | 方向性风险 | **2.5D + 卷积 + 迟滞** |
| 代价 | 各向同性 | 各向同性 | 方向性（稠密） | **各向异性（稀疏）** |
| 图规模 | 稠密 | 稠密 | 稠密 | **稀疏** |
| 起伏地形 | 可跑 | **fail** | 可跑 | 可跑且更安全 |
| 延迟 | 20 ms | 18.5 ms | — | 30 ms |

## 三、算法完整流程

### 3.1 【输入】

| 输入 | 形式 | 出处 |
|---|---|---|
| 点云 | 实时 LiDAR + 里程计 | §III-A |
| 位姿 | FAST-LIO | §IV-C |
| 目标 | 无显式目标（自主探索） | §III-D |

### 3.2 【预处理】

- 点云 → 按 Res 投影 → 每格 85 百分位高度 → 高程矩阵 $H$；
- Sobel 卷积 → $G_x,G_y$ → 坡度 $\theta$。

### 3.3 【核心模块】

| 模块 | 职责 |
|---|---|
| 图像域地形分析 | 高程图 + 卷积 + 迟滞 → 平/坡/障 mask |
| 稀疏节点采样 | 只在坡上按 $D_{sparse}$ 采样 |
| Euler Cost 连边 | 方向相关代价 |
| 探索规划 | 可达域 + frontier + Two-Opt |

### 3.4 【信息传递】

```
点云 → H → (Gx,Gy) → θ → 迟滞 mask
     → 稀疏节点 V → Euler Cost 连边 → 图 G
     → 2D 可达域 → frontier → 聚类 → Two-Opt → 目标序列
```

### 3.5 【推理流程】

```text
1. 收点云 → 投影成高程图
2. Sobel 卷积 → 坡度
3. 迟滞分类（用上一帧状态）→ mask
4. 稀疏采样 → 节点集 V
5. 对相邻节点算 Euler Cost → 图
6. 更新 2D 可达域 → 提取 frontier → 扇区聚类
7. Two-Opt 优化访问顺序（效用含 Gain、Euler Cost、Δψ）
8. 下发目标 → 低层规划器执行
```

### 3.6 【训练流程】

**无训练**——全是几何与启发式算法。

### 3.7 【机器人执行】

## 五、方法层面的疑点清单

1. **表 I 的交叉反常**："w/o Kin." 的侧倾（19.65/18.68）比 "w/o Euler"（22.84/25.31）更低——若 Euler Cost 是安全主因，这个顺序不合理。作者未解释。
2. **路径长度 +15%**：作者说"效率几乎不变"，但 η 只降 2%、路径却长 15%，说明"效率"的定义（面积/时间）掩盖了路径代价。
3. **感知模块耗时未单独报告**：只说"复杂度降低"，没给实测。
4. **85 百分位的选择**未做敏感性分析。
5. **准静态假设**与 1.0 m/s 的速度上限之间没有论证。

## 六、把方法浓缩成一条因果链

```text
起伏地形探索难
 ├─ 难点 1: 3D 地形分析太贵
 │    └─ 对策: 2.5D 高程图 + Sobel 卷积（O(N^3)→O(N^2)）
 ├─ 难点 2: 阈值分类会抖
 │    └─ 对策: 双阈值迟滞
 ├─ 难点 3: 各向同性代价会为走近路横穿斜坡
 │    └─ 对策: 【创新】Euler Cost（方向 × 梯度）
 └─ 难点 4: 稠密图搜索太慢
      └─ 对策: 只在坡上稀疏采样

结果: 侧倾 23.54° → 18.46°，效率略降，延迟 +10 ms
代价: 参数手调、准静态、只验证低速
```

> 这条链的结构叫"**逐层降维**"：空间维（3D→2.5D）、节点数（稠密→稀疏）、状态（连续→三类）。每降一次，后面就能负担更精细的建模。
