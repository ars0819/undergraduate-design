## 一、创新的分级

### A. 最重要的创新（只选 1 项）

> **把"下一步做什么"表述成一个可分解的概率乘积：$p(c_\pi\mid s,\ell_\pi)\cdot p(\ell_\pi\mid i)$——左边是学出来的可供性（世界接地），右边是 LLM 打出的任务相关性（任务接地），相乘取最大。并且证明这条分解在实践中成立。**

这个创新的精妙之处在于**它同时解决了两个不对称的问题**：
- LLM 懂语义但不懂物理 → 用可供性补；
- 技能懂物理但不懂语义 → 用 LLM 补。

而且它保持了一个**受限的输出空间**（只能是技能描述），从而：
- 计划可解释（每一步都有两个分数）；
- 计划可解析（不需要从自由文本里抽动作）；
- 计划可扩展（加技能只需加一行描述 + 一个价值函数）。

**修改发生在系统的哪一环？**
- 不动低层策略，不动 LLM 权重；
- **在"规划器"这一环**：把 LLM 从"生成器"改成"打分器"，再与价值函数相乘。

### B. 其他有价值的改进

| 改进 | 价值 | 是否首创 |
|---|---|---|
| **用稀疏奖励 RL 的价值函数当可供性** | 把"能不能做成"变成一个可学的概率 | 论文明确说这是对可供性文献的借用 + 新用法 |
| **打分而非生成** | 让概率可比较、计划可解析 | ★ 关键工程决策 |
| **对话式提示（"I would: 1. …"）** | 让 LLM 输出稳定格式 | 提示工程 |
| **多任务技能（multi-task BC / RL）** | 摊销 551 个技能的训练成本 | 借用 BC-Z / MT-Opt |
| **语言嵌入用冻结句编码器** | 技能条件化简单可靠 | 借用 USE |
| **LLM 规模消融（8B/62B/540B/137B FLAN）** | 证明"LLM 变强 → 机器人变强" | ★ 少见的跨领域耦合证据 |
| **失败归因（65% LLM / 35% 可供性）** | 给出系统瓶颈的定量拆解 | ★ 很有价值 |

### C. 借鉴已有研究的技术

| 技术 | 来源 | 角色 |
|---|---|---|
| PaLM 540B | Chowdhery et al.（[9]） | 打分器 |
| FLAN 137B | Wei et al.（[8]） | 消融对象 |
| 价值函数 / TD 学习 | 经典 RL | 可供性来源 |
| MT-Opt | [14] | 多任务 RL 技能 |
| BC-Z | [13] | 多任务 BC 技能 |
| RetinaGAN | [16] | 仿真到真实的图像转换 |
| Universal Sentence Encoder | [15] | 语言嵌入 |
| 可供性（affordance）概念 | Gibson 传统 / [10] | 理论框架 |
| 提示工程 / 对话格式 | GPT-3 时代惯例 | 输出约束 |

### D. 工程实现与实验设置

- 机器人：Everyday Robots 2 移动机械臂（7 DoF 臂 + 两指夹爪 + 移动底盘）；
- 动作空间：末端 6 DoF + 夹爪 + 底盘 $(x,y,\text{yaw})$ + terminate（§4）；
- 技能：提出 **551 个**（7 族、17 物体），实际用其子集；
- 场景：15 个物体、5 个语义位置；两个厨房（训练用的 mock + 真实办公室厨房）；
- 评测：101 条指令、7 个族；3 位人类评审、2/3 多数通过。

> [!important] 一句话总结分级
> **SayCan 的原创性 ≈ "把 LLM 当打分器 × 把价值函数当可供性"这个公式，加上"输出限制在技能描述集合内"这个工程约束。**

## 二、核心创新的八个追问

### ① 以前的研究通常怎么处理"LLM 控制机器人"？

| 路线 | 做法 | 问题 |
|---|---|---|
| 纯 prompt 生成 | 让 LLM 自由写步骤 | 格式乱、可能给出做不到的动作 |
| 端到端策略 | 直接从指令学动作 | 2022 年时做不了 10+ 步长程 |
| 语义解析 / 符号规划 | 把指令解析成逻辑式再规划 | 需要预先定义符号与状态，扩展难 |
| **SayCan** | LLM 打分 × 可供性 | 依赖技能库 |

### ② 原有方法的缺点是什么？

| 缺点 | 原文依据 | 我的核查 |
|---|---|---|
| LLM 不接地 | §1、图 1（"你可以用吸尘器"的例子） | 成立，且这个例子很有说服力 |
| 纯生成不可解析 | §3"it can produce inadmissible actions or language that is not formatted" | 成立 |
| 长程任务超出端到端能力 | §1 | 2022 年的判断；后来 VLA 部分推翻 |
| 符号规划需要手工状态定义 | §2 隐含 | 成立，作者选择不采用 |

### ③ 作者具体修改了什么？

**三步改造**：

**(1) 让 LLM 打分而不是生成**
把技能描述集合 $\ell_\Pi$ 当作候选答案，计算 $p(\ell_\pi\mid i)$。这需要 prompt 把模型"逼"进对话格式（`I would: 1. …`），然后只读概率。

**(2) 用价值函数当可供性**
在"成功得 1、失败得 0"的稀疏奖励下，$Q$ 值就等于"从该状态出发能成功的概率"。作者直接把这个值当作 $p(c_\pi\mid s,\ell_\pi)$。

**(3) 相乘并迭代**
$$\pi_n=\arg\max_{\pi\in\Pi}\ p(c_\pi\mid s_n,\ell_\pi)\cdot p(\ell_\pi\mid i,\ell_{\pi_{n-1}},\dots)$$
执行 $\pi_n$，把 $\ell_{\pi_n}$ 追加到对话，$n\leftarrow n+1$，直到选到 "done"。

### ④ 修改发生在哪一层/哪一环？

```
[用户指令 i]
     ↓
[LLM 打分器]  p(ℓ_π | i)          ← Say：任务接地
     ↓  ×
[价值函数]    p(c_π | s, ℓ_π)     ← Can：世界接地
     ↓
[选择] argmax → 技能 π_n
     ↓
[低层策略] 执行技能（秒级）
     ↓
[状态更新] → 回到 LLM 打分
```

**一句话**：**它改的是"语言与动作之间的接口"，而不是语言模型或低层策略本身。**

### ⑤ 为什么这种改变有效？

**(a) 为什么"相乘"是合理的？**
原文给了一个明确的假设推导（§3）：
> 假设"技能成功"时它以 $p(\ell_\pi\mid i)$ 的概率推进任务，"技能失败"时推进概率为 0，则
> $p(c_i\mid i,s,\ell_\pi)\propto p(c_\pi\mid s,\ell_\pi)\,p(\ell_\pi\mid i)$。

这个假设很强（成功与"是正确技能"独立），但它是可检验的——而表 2 的消融（No VF 67% vs 组合 84%）就是间接检验：**两个因子都不可省**。

**(b) 为什么价值函数能当可供性？**
稀疏奖励下，$V(s)$ 的语义就是"从这里开始能拿到 1 的概率"。这正好是"这个技能现在能不能做成"。
→ 这是本文最优雅的一步：**把"可供性"这个哲学概念落地成一个可训练的标量**。

**(c) 为什么打分比生成好？**
- 生成式输出无法给出"跨技能的相对概率"，也就无法与可供性相乘；
- 生成式输出可能不在技能集合内；
- 打分的输出空间是离散的技能集合，**天然可解析、可解释**。
→ 表 2 的 Generative 基线（74% 规划）低于打分版（84%），是直接证据。

**(d) 为什么 LLM 变大机器人就变强？**
因为 LLM 负责的是"语义分解"这一环；这一环越强，计划越正确。表 3 中长程任务从 47%（FLAN）到 73%（PaLM）就是证据。

### ⑥ 它引入了什么新代价？

| 新代价 | 说明 | 证据 |
|---|---|---|
| **能力上限 = 技能库** | 作者自己承认是主要瓶颈 | §6 |
| **技能粒度 = 重规划粒度** | 一个技能执行完才重新规划 | Algorithm 1 |
| **无法从技能失败中恢复** | 价值函数报高但实际失败时，系统不知道 | §6 |
| **规划延迟未报告** | 每步要对全部技能打分（551 个） | 【原文未给出】 |
| **继承 LLM 偏见** | 作者承认 | §6 |
| **依赖人类评审** | 3 人 2/3 多数 | §5 |

### ⑦ 与最接近的前人方法有什么区别？

| 维度 | 纯 prompt（如 Zero-shot Planner） | 符号规划 | 端到端策略 | **SayCan** |
|---|---|---|---|---|
| 输出空间 | 自由文本 | 逻辑动作 | 连续动作 | **技能描述集合** |
| 是否接地 | ❌ | 部分（需手工状态） | ✅（但泛化弱） | **✅（价值函数）** |
| 长程能力 | 弱（不可执行） | 强（需模型） | 弱（2022） | **强** |
| 可解释 | 弱 | 强 | 弱 | **强（两个分数）** |
| 扩展新技能 | — | 改模型 | 重训 | **加一行描述 + 一个 VF** |

**最本质的区别**：SayCan 把"语言理解"和"物理可行性"做成**两个独立的概率**，再用乘法合成。这让两者可以**各自独立进步**——这正是它"LLM 变强机器人就变强"的原因。

### ⑧ 实验是否真的支持作者的主张？

| 作者主张 | 证据 | 支持度 | 我的评语 |
|---|---|---|---|
| "可供性接地关键" | 表 2：84% vs 67%（No VF） | ✅ 强 | 但只比了规划，没比执行 |
| "语言关键" | BC NL 0%、BC USE 9% | ✅ 强 | 基线很弱（把整条指令喂给 BC 本来就不合理） |
| "LLM 越强机器人越强" | 表 3：84/74 vs 70/61 | ✅ 中强 | 只有两个 LLM，且 FLAN 与 PaLM 差异不止规模 |
| "摘要：接近翻倍" | 摘要 vs 表 2 | ⚠️ **口径不明** | 见 01 笔记 §6.2 第 1 条 |
| "可解释" | 图 6 | ✅ 定性 | 没有用户研究 |
| "可扩展新技能" | §5.2 抽屉例子 | ⚠️ 定性 | 没有量化 |

## 三、算法完整流程（Algorithm 1 展开）

### 3.1 【输入】

| 输入 | 形式 | 出处 |
|---|---|---|
| 用户指令 $i$ | 自然语言（可长、可抽象） | §3 |
| 状态 $s$ | 图像观测（RGB） | §4 |
| 技能库 $\Pi$ | 每个技能带策略、价值函数、语言描述 | §4 |

### 3.2 【预处理】

- 技能描述 → 冻结的句编码器 → 嵌入（给策略/价值函数用）；
- 指令 + 已执行技能序列 → 拼进 prompt → 送 LLM。

### 3.3 【核心模块】

| 模块 | 职责 | 备注 |
|---|---|---|
| LLM（PaLM 540B） | 给每个技能描述打分 $p(\ell_\pi\mid i,\dots)$ | **不生成，只打分** |
| 价值函数 $V_\pi(s)$ | 输出可供性 $p(c_\pi\mid s,\ell_\pi)$ | RL 学出来，多任务 |
| 乘法选择器 | $\arg\max$ | 无参数 |
| 技能策略 $\pi(s)$ | 执行选中的技能 | BC 或 RL |

### 3.4 【信息传递】

```
指令 i + 历史技能 → prompt → LLM → 每个技能的 log-prob
状态 s → 价值函数 → 每个技能的可供性
                ↓ 相乘
        每个技能的 combined 分数
                ↓ argmax
            选中的技能
```

### 3.5 【推理流程】

```text
1. n = 0，π = 空
2. while 上一个技能不是 "done":
     对每个技能 π:
        p_LLM  = LLM(ℓ_π | i, ℓ_π_{n-1}, ..., ℓ_π_0)   # 打分
        p_aff  = V_π(s_n)                              # 可供性
        p_comb = p_LLM × p_aff
     选 p_comb 最大的技能 π_n
     执行 π_n(s_n)，状态更新为 s_{n+1}
     n = n + 1
3. 结束
```

### 3.6 【训练流程】

训练**分两块**，且都在 SayCan 之外完成：
- **技能策略**：多任务 BC（BC-Z）或 RL（MT-Opt + RetinaGAN）；
- **价值函数**：多任务 RL，稀疏奖励；
- **LLM**：**完全不训练**，只用提示工程。

> 这一点很关键：**SayCan 本身不需要训练**。它只是"把两个已有模型乘起来"。所以它的"训练成本"≈ 技能库的训练成本。

### 3.7 【机器人执行】

| 问题 | 原文回答 | 状态 |
|---|---|---|
| 动作粒度 | **一个技能**（秒级原子行为） | §3、Algorithm 1 |
| 重规划频率 | 每执行完一个技能 | Algorithm 1 |
| 技能内部是否闭环 | 是（策略自己闭环），但**规划层不知道中途状态** | 【推断】基于 Algorithm 1 |
| 失败恢复 | 无（作者承认） | §6 |
| 控制频率 | 未报告 | 【原文未给出】 |

### 3.8 【输出】

- 一串技能描述（可读的计划），如 `find a sponge → pick up the sponge → bring it to you → done`；
- 每个技能的中间分数（可解释）。

## 五、方法层面的疑点清单

1. **"接近翻倍"的口径**：摘要是全文最常被引用的话，但表 2 只支持"规划 +25% 相对"。
2. **分解假设很强**：$p(c_i\mid i,s,\ell)\propto p(c_\pi\mid s,\ell)p(\ell\mid i)$ 假设"成功 ⟂ 是正确技能"。现实中"正确的技能执行失败"很常见（技能成功率约 60–90%），这个近似会高估组合概率。
3. **规划延迟未报告**：551 个技能 × 每步打分，成本可能不低。
4. **技能粒度的选择没有讨论**：为什么"pick up the can"是一个技能，而"移到 can 上方 10 cm"不是？粒度直接决定了重规划频率。
5. **人类评审的主观性**：3 人 2/3 多数，未报告一致性（如 Cohen's kappa）。
6. **族均值 vs 任务均值**：总 84% 是 7 个族的平均，不是 101 条指令的加权平均（族样本量 11–15 不等）。

## 六、把方法浓缩成一条因果链

```text
LLM 有知识但不接地
 ├─ 表现 1: 给出做不到的动作（"用吸尘器"）
 │    └─ 对策: 把输出限制在技能库描述内（打分而非生成）
 ├─ 表现 2: 不知道当前场景状态
 │    └─ 对策: 乘上价值函数（可供性）
 └─ 表现 3: 不能处理长程序列
      └─ 对策: 迭代式"选一个 → 执行 → 追加到对话 → 再选"

效果
 ├─ 规划 84% / 执行 74%（训练环境）
 ├─ 真实厨房 81% / 60%
 └─ LLM 从 FLAN-137B 换到 PaLM-540B：规划 70 → 84

天花板
 ├─ 技能库的能力上限（作者自认）
 ├─ 技能失败无法恢复
 └─ 技能粒度 = 重规划粒度
```

> 这条链最后三行"天花板"，就是后来 VLA 要解决的问题：**把技能库换成一个大模型，就同时去掉了三个限制。**
