## 二、六个概念的五层解释

### 2.1 什么是"异构机器人团队"

1. **一句话**：不同的机器人干不同的活，接力完成一件事。
2. **类比**：搬家公司——有人搬重物、有人开电梯、有人拆包装。
3. **机器人例子**：轮腿的走平地省电、腿式的上楼梯、空中的跨障碍、双臂的操作。
4. **技术原理**：按形态分配任务，每台做自己最擅长的段。
5. **与本文关系**：全文的组织原则。

### 2.2 为什么"下洗气流"是空中操作的天敌

1. **一句话**：无人机自己吹出的风，会把要抓的东西吹跑。
2. **类比**：你想捡起地上的一张纸，但你在用吹风机对着它吹。
3. **机器人例子**：多旋翼在 <1 m 距离时，气流把纸箱吹走（原文前 3 次抓取失败）。
4. **技术原理**：旋翼产生的下洗流速与距离平方成反比，近距时极强；物体越轻、面积越大越容易被吹动。
5. **与本文关系**：§Lessons Learned（空中团队）。

### 2.3 为什么"地板材质"能让机器人过热

1. **一句话**：地面变软 → 轮子阻力变大 → 腿要更用力 → 电机发热。
2. **类比**：在沙地上骑自行车比在柏油路上累得多。
3. **机器人例子**：Centauro 从水泥地进入泡沫飞行区，橡胶轮摩擦骤增，腿部关节内应力上升，驱动器温度危险升高。
4. **技术原理**：轮腿混合机器人的腿要"顶住"轮子传来的反力，摩擦增大会把这个力放大。
5. **与本文关系**：§Lessons Learned（Centauro 团队）。

### 2.4 什么是"传感器化环境"

1. **一句话**：与其教机器人开各种门，不如让门自己告诉机器人"我开了"。
2. **类比**：自动门不需要你会推门。
3. **机器人例子**：门装了 M5Stack Core 2，通过 ROS 2 topic 发布开关状态。
4. **技术原理**：把"感知-决策-执行"的一部分外包给环境。
5. **与本文关系**：§Scenario。

> [!tip] 我认为这是本文最可复用的设计思想
> 在真实部署里，**改造环境往往比改造机器人便宜得多**。

### 2.5 为什么"遥操作兜底"是合理的

1. **一句话**：难的环节让人上，其余让机器跑。
2. **类比**：自动驾驶的"接管"。
3. **机器人例子**：空中交接、开门把手由人操作。
4. **技术原理**：把"可靠性"和"自主性"解耦——先保证能跑通，再逐步替换。
5. **与本文关系**：§结论明确承认。

### 2.6 为什么"预建图 + 数字孪生"是双刃剑

1. **一句话**：准备得越多，现场越稳；但准备本身很贵。
2. **类比**：演出前的彩排——彩排越充分，正式演出越稳，但成本高。
3. **机器人例子**：ANYmal 需要预建图才能高速低耗地跑。
4. **技术原理**：把"在线难度"转移到"离线准备"。
5. **与本文关系**：§Lessons Learned（ETHZ 团队）。

## 三、关键接口与协议（替代"公式"一节）

### 接口 1：ROS 2 自动发现

**性质**：🟢 **原文 §Scenario 提到**。

**做法**：各团队的节点加入同一 ROS 2 域，靠 DDS 自动发现彼此。
**优点**：不需要手工配置 IP。
**问题**：多团队、多网络时**发现可能混乱**，需要划分域/命名空间。

---

### 接口 2：ROS 1 / ROS 2 桥

**性质**：🟢 **原文提到多个团队用 ROS 1，通过桥接入**。

**做法**：`ros1_bridge` 双向转发 topic。
**问题**：QoS 语义不同（ROS1 无 QoS），可能丢消息。

---

### 接口 3：ArmarX RESTful API

**性质**：🟢 **原文提到 KIT 用 ArmarX 的 RESTful API 做多机协同**。

**做法**：把机器人的能力封装成 HTTP 服务，其他机器人调用。
**优点**：语言/框架无关。
**问题**：延迟比 topic 高，不适合高频控制。

---

### 接口 4：传感器化门

**性质**：🟢 **原文 §Scenario 描述**。

**做法**：门 → M5Stack Core 2 → ROS 2 topic（状态/命令）。
**意义**：把"开门"从"操作问题"降级为"通信问题"。

---

### 指标：总执行时间

**性质**：🟢 **原文 §结论**。

**数值**：**18 分钟**（完整链条，含两处遥操作）。
**注意**：任务在现场定义、无前期准备，所以**不代表系统极限**（作者自己说明）。
