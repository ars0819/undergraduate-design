## 一、创新的分级

### A. 最重要的创新（只选 1 项）

> **用一套可复核的失败归因流程，把"移动操作 19% 的成功率"拆成三个可干预的瓶颈（规划 21.0% / 导航与底盘 25.9% / 局部操作 53.1%），并针对每个瓶颈设计"不动底层策略"的外挂。**

为什么这是核心：
- 它把"性能差"这个模糊判断变成了**一张处方**；
- 每个外挂都能追溯到一条 Finding（技能卡 ← Finding 1，底盘调整 ← Finding 2，末端修正 ← Finding 3）；
- 表 2 的消融显示：**每个外挂去掉都会掉点**，没有凑数的。

### B. 其他有价值的改进

| 改进 | 价值 | 是否首创 |
|---|---|---|
| **"3 次重规划恢复窗口"的归因规则** | 把"失败"定义得可操作、可复核 | ★ 方法学贡献 |
| **Fleiss κ=0.86 的标注一致性** | 归因不是拍脑袋 | ★ 少见 |
| **自适应视觉记忆（planner 触发检索）** | 表 2：47% vs 均匀给 32 帧的 35% | ★ 反直觉且有数据 |
| **可达性三分（reachable/marginal/out-of-reach）** | 表 2：去掉掉 11 点，是底盘调整里最关键的一环 | ★ 设计精准 |
| **分层几何技能（check_stance → approach_xy / goto_stance → EE 修正）** | 用最小干预修三类问题 | 工程扎实 |
| **"失败前沿移动"的分析** | 图 5：修好一层，下一层暴露 | ★ 有系统论洞察 |
| **在 3 个平台上验证同一套设计** | RoboCasa365 / BEHAVIOR-1K / 真机 | 外推性好 |

### C. 借鉴已有研究的技术

| 技术 | 来源 | 角色 |
|---|---|---|
| 分层 agentic baseline | Harness VLA（[Zhang et al., 2026b]） | 基线架构 |
| 技能库 / 示范转文本 | [Zhong et al., 2023]、[Wake et al., 2024] | 规划引导 |
| 视觉记忆 | [Yoneda et al., 2024]、[Sridhar et al., 2026] | 进度跟踪 |
| Grounding DINO + SAM | [Liu et al., 2024b]、[Kirillov et al., 2023] | 目标分割 |
| A\* + 占据栅格 | [Hart et al., 1968] | 重新选位的路径规划 |
| 失败归因 / 恢复 | Inner Monologue、Voxposer 等 | 概念来源 |
| Kimi K3 / Gemini 3.5 Flash / Qwen3.8-27B | 各家 2026 模型 | 高层规划 / 技能卡 / 检索 |

### D. 工程实现与实验设置

- 20 个复合任务 × 5 rollout = 100 episode（开发集）；另设 5 个留出 seed；
- 失败归因：3 个 Codex 独立诊断 + 人工按规则复核；30 例子集上 κ=0.86；
- 所有 agentic 方法共享**同一个**分任务 VLA checkpoint，只用 Kimi K3 做高层；
- 几何参数（距离阈值、0.1 m 膨胀、0.3 m 修正上限）**在评测前固定**。

> [!important] 一句话总结分级
> **本文的原创性 ≈ "失败归因流程"这个方法学 + "四个对症外挂"这个系统设计 + "失败前沿会移动"这个观察。**

## 二、核心创新的八个追问

### ① 以前的研究通常怎么处理"移动操作不可靠"？

| 路线 | 做法 | 问题 |
|---|---|---|
| 端到端 VLA 扩展 | 把移动操作数据也喂给大模型 | π0/π0.5 只有 2–4%（表 1） |
| 分层模块化 | 规划 + 导航 + 操作各自独立 | 模块之间的"交接"没人管（本文的 Finding 2） |
| Agentic | planner + 工具调用 | 基线只有 19% |
| 失败检测 / 恢复 | 检测失败后重试 | 多用于局部，未做系统级分解 |

### ② 原有方法的缺点是什么？

| 缺点 | 原文依据 | 我的核查 |
|---|---|---|
| 子任务强 ≠ 组合强 | 摘要：80% vs 19% | 成立，且这是全文的立论基础 |
| 导航完成 ≠ 可操作 | Finding 2 | 表 2：可达性检查掉 11 点 |
| 规划不跟踪进度 | Finding 1 | 细项：放置目标错误 9→0 |
| 局部几何误差 | Finding 3 | 细项：抓取错位 10→3 |

### ③ 作者具体修改了什么？

**四个外挂，每个对应一条 Finding**：

| Finding | 外挂 | 具体做法 |
|---|---|---|
| 1 规划不跟踪进度 | **技能卡 + 自适应视觉记忆** | Gemini 3.5 Flash 总结示范为技能卡；Qwen3.8-27B 按查询检索 16 帧 |
| 2 到了但站姿不行 | **可达性检查 + 底盘调整** | Grounding DINO + SAM → 反投影 → 三分 → `approach_xy` 或 `goto_stance`（A\*） |
| 3 最后一下不准 | **末端几何修正** | 分割 → 3D 点中位数 → 表面法向 → 有界修正（≤0.3 m） |

### ④ 修改发生在哪一层/哪一环？

```
[用户指令]
   ↓
[高层 planner（Kimi K3）]  ←── 技能卡（示范总结）
   ↓                      ←── 视觉记忆（按需检索）
[子任务指令]
   ↓
[可达性检查 check_stance]  ←── Grounding DINO + SAM + 深度
   ├─ 够不到 → goto_stance（A* 重新选位）
   ├─ 勉强 → approach_xy（小幅平移）
   └─ 可达 → 继续
   ↓
[冻结的分任务 VLA]  ←── 完全不动
   ↓
[末端几何修正]  ←── 分割 + 法向 + 有界更新
   ↓
[执行]
```

**关键**：**改动全部在"VLA 之外"**——输入端（技能卡、记忆）、接口处（可达性检查、底盘）、输出端（末端修正）。

### ⑤ 为什么这种改变有效？

**(a) 为什么技能卡有效？**
- 规划失败的本质是"不知道该按什么顺序、该对哪个目标"；
- 技能卡把"示范里怎么做的"变成显式上下文，**等价于给了 planner 一个先验**。
- 表 2：去掉关键帧掉 4 点；换真机数据掉 7 点（**域内数据更重要**）。

**(b) 为什么"按需检索"比"全给"好？**
- 均匀给 32 帧只有 35%，比给 8 帧（37%）还差——**信息过载会干扰规划**；
- 按需检索让 planner 自己决定"我现在需要看什么"，检索出的是**任务相关的证据**。
- 这与 SayCan 的"打分而非生成"是同一哲学：**约束输入的质量，而不是数量**。

**(c) 为什么"可达性检查"最关键？**
- 它决定了**要不要动底盘**——这是"导航→操作"的交接点；
- 没有它，机器人会"到了地方就开始抓"，然后够不到（细项：接近无效 11→1）；
- 有了它，才谈得上"后续的底盘调整"和"末端修正"。

**(d) 为什么几何修正比让 planner 给 3D 目标好？**
- planner 是语言模型，给 3D 坐标不是它的强项；
- 几何管线（分割 → 反投影 → 中位数 → 法向）给的是**度量上可信**的目标；
- 表 2：43% vs 47%。

**(e) 为什么"失败前沿会移动"？**
- 三个瓶颈是**串联**的：规划错 → 到不了；导航错 → 站不好；站不好 → 操作失败；
- 修好前两个，更多 episode 走到第三步 → 操作失败占比上升。
- 图 5 直接画出了这个移动过程。

### ⑥ 它引入了什么新代价？

| 新代价 | 说明 | 证据 |
|---|---|---|
| **多次大模型调用** | planner（Kimi K3）+ 技能卡（Gemini）+ 记忆检索（Qwen） | §4 |
| **延迟未报告** | 每轮 planner + 工具调用的耗时未知 | 【原文未给出】 |
| **依赖闭源模型** | 三个模型都是外部服务 | 复现受限 |
| **几何参数要标定** | 距离阈值、膨胀半径、修正上限 | §4.3 |
| **失败归因需要人力** | 3 个 Codex + 人工复核 | §3.2 |
| **只覆盖 20/32 任务** | 其余 12 个未评估 | 表 1 题注 |

### ⑦ 与最接近的前人方法有什么区别？

| 维度 | Harness VLA（基线） | Xiaomi Robotics 1 | 本文 |
|---|---|---|---|
| 类型 | agentic | 端到端 VLA | **agentic + 按瓶颈干预** |
| 底层策略 | 同一分任务 VLA | 单一模型 | **同一分任务 VLA（冻结）** |
| 是否有可达性检查 | ❌ | 隐含在模型里 | **✅ 显式** |
| 是否有视觉记忆 | ❌（只有文本工具历史） | 隐含 | **✅ 按需检索** |
| 开发集成功率 | 19% | 44% | **47%** |
| 留出集成功率 | 18% | 45% | **49%** |

**最本质的区别**：**同样是 agentic，本文的每个模块都对应一个被量化的失败模式**——不是"加了几个工具试试看"。

### ⑧ 实验是否真的支持作者的主张？

| 作者主张 | 证据 | 支持度 | 我的评语 |
|---|---|---|---|
| "子任务强 ≠ 组合强" | 80% vs 19% | ✅ 强 | 立论清晰 |
| "三类瓶颈" | 81 episode 归因，κ=0.86 | ✅ 强 | 方法学扎实 |
| "每个外挂都有效" | 表 2（15 个变体全掉点） | ✅ 强 | 但只有 100 episode |
| "底盘调整贡献最大" | 29.0 → 40.0 | ✅ 中强 | 其余中间点未给数 |
| "失败前沿移动" | 图 5 | ✅ 中强 | 定性趋势清晰，数字在附录 G |
| "留出集泛化" | 18→49，p<0.001 | ✅ 强 | 5 个 seed |
| "外推到其他平台" | BEHAVIOR-1K / 真机 | ✅ 中 | 样本少（5 任务 / 20 次） |
| "追平端到端 VLA" | 47/49 vs 44/45 | ⚠️ 中 | 差异在统计误差内（每任务 5 次） |

## 三、算法完整流程

### 3.1 【输入】

| 输入 | 形式 | 出处 |
|---|---|---|
| 高层指令 | 自然语言任务描述 | §3.1 |
| 观测 | 图像 + 机器人状态 | §3.1 |
| 技能卡 | 文本（目标、子任务顺序、关键帧、完成判据） | §4.1 |
| 视觉记忆 | 当前 episode 的历史帧（只允许过去） | §4.2 |

### 3.2 【预处理】

- 目标物体名 → Grounding DINO → 框 → SAM → 掩码；
- 掩码内有效深度像素 → 反投影 → 3D 点 → 中位数（抗离群）；
- 3D 点 → 局部表面法向 → 末端接近方向。

### 3.3 【核心模块】

| 模块 | 职责 | 是否学习 |
|---|---|---|
| 高层 planner（Kimi K3） | 选子任务 / 调工具 | 不训练（提示） |
| 技能卡生成（Gemini 3.5 Flash） | 示范 → 文本程序 | 不训练 |
| 视觉记忆检索（Qwen3.8-27B） | 查询 → 最相关 16 帧 | 不训练 |
| 可达性检查 | 目标距离 → 三分 | 阈值用训练数据定 |
| 底盘调整 | 平移 / 重新选位（A\*） | 不学习 |
| 子任务 VLA | 执行子任务 | **冻结** |
| 末端修正 | 有界几何更新 | 不学习 |

### 3.4 【信息传递】

```
指令 → planner ← 技能卡 / 记忆
        ↓ 子任务
     可达性检查 → （可能需要）底盘调整
        ↓
     子任务 VLA → 动作
        ↓
     末端修正 → 执行
        ↓
     观测 → 记忆
```

### 3.5 【推理流程】

```text
1. planner 读指令 + 技能卡 + 相关记忆 → 选子任务
2. 若子任务是"操作"，先 check_stance
   2a. 够不到 → goto_stance（A*）
   2b. 勉强 → approach_xy
3. 子任务 VLA 执行（冻结）
4. 若涉及抓取/放置 → 末端几何修正
5. 观测入记忆 → 回到 1
```

### 3.6 【训练流程】

**本文没有训练新模型**，只有：
- 子任务 VLA（沿用已有，训练细节在附录 B）；
- 技能卡生成 / 记忆检索 / planner 全部是**提示工程**（无梯度）；
- 几何阈值从训练轨迹估计，评测前固定。

### 3.7 【机器人执行】

| 问题 | 原文回答 | 状态 |
|---|---|---|
| 子任务粒度 | 2–15 个子任务/任务 | §3.1 |
| 重规划 | 每子任务后（planner 择机） | §4 |
| 底盘调整幅度 | 平移小幅；重新选位用 A\* | §4.3 |
| 末端修正上限 | **0.3 m/次** | §4.3 |
| 延迟 | **未报告** | 【原文未给出】 |
| 恢复窗口 | 后续 3 次重规划 | §3.2 |

### 3.8 【输出】

- 子任务序列 + 机器人动作 + 工具调用；
- 不输出连续价值、不输出地图（导航用局部占据栅格）。

## 五、方法层面的疑点清单

1. **延迟完全没报**：四个外挂 + 每轮 planner 调用，在真机上能不能实时？
2. **失败归因本身可能有偏见**：3 个 Codex 诊断 + 人工复核，Codex 的标签会锚定人工。
3. **"3 次重规划"窗口未做敏感性分析**：窗口改成 1 或 5，失败分布会不会变？
4. **20/32 任务**：剩下 12 个为什么不算"移动操作"？标准未明。
5. **表 1 的差异在噪声内**：47 vs 44（每任务 5 次 rollout），作者说"comparable"，是诚实的。
6. **可达性阈值"从训练轨迹估计"**：换机器人要重标，扩展性受限。

## 六、把方法浓缩成一条因果链

```text
移动操作 19%（子任务 80%）
 ├─ 诊断：81 个失败 episode 归因
 │    ├─ 规划 21.0% —— 进度跟踪失败
 │    ├─ 导航/底盘 25.9% —— 到了但站不好
 │    └─ 局部操作 53.1% —— 最后一下不准
 ├─ 干预（每个对应一条诊断）
 │    ├─ 技能卡 + 视觉记忆 → 规划 21.0% 类失败减少
 │    ├─ 可达性检查 + 底盘调整 → 导航类失败减少（最大单步 29→40）
 │    └─ 末端几何修正 → 抓取错位 10→3
 └─ 结果：19% → 47%（留出 49%）

副作用（作者自己指出）
 └─ 失败前沿移动：修好前两段，操作成为新的主要失败
```

> 这条链最值得学的是**"诊断 → 干预 → 再诊断"的循环结构**。它比"提出一个模块"更接近真实系统的改进方式。
