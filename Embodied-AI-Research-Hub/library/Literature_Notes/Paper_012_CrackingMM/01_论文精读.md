# P012 · Cracking Mobile Manipulation 论文精读

> [!abstract] 一句话先给你
> **一个原子任务能做到 80% 的 VLA，把它串成移动操作长任务后只剩 19%。** 作者没有去训更强的策略，而是先**诊断失败发生在哪一步**：任务规划 21.0%、导航与底盘定位 25.9%、局部操作 53.1%。然后针对三个瓶颈各加一个"外挂"——示范技能卡、自适应视觉记忆、可达性检查 + 底盘调整、末端几何修正——把成功率从 **19% 推到 47%**（留出集 18% → 49%），且**底层 VLA 完全冻结**。

## 二、三种长度的摘要

### 2.1 30 秒摘要（约 170 字）

移动操作有个奇怪的现象：单个抓取任务能到 80%，但把几个串起来只剩 19%。这篇论文先做"验尸"：把 81 个失败 episode 逐个归因，发现三类瓶颈——任务规划（21.0%）、导航与底盘定位（25.9%）、局部操作（53.1%）。然后针对每一类各加一个不改底层策略的"外挂"：示范技能卡、按需检索的视觉记忆、可达性检查 + 底盘调整、末端几何修正。19% → 47%（留出集 49%）。

### 2.2 3 分钟摘要（约 520 字）

**问题。** 移动操作不是"桌面操作 + 底盘移动"的简单相加。机器人要跨工作区移动、每个位置都改变视角与手臂可达空间、早期的动作还会改变场景让后续决策失效。所以**局部能力强 ≠ 长任务可靠**。

**诊断（这是本文最有价值的部分）。** 作者搭了一个分层 agentic baseline（高层 planner 选子任务/工具 + 一个共享的分任务 VLA 同时做导航和操作），在 RoboCasa365 的 20 个移动操作任务上跑 100 个 episode，成功 19 个，失败 81 个。然后做**严格的失败归因**：
- 对每个失败 episode，回看动作、观测、仿真状态，找出失败的子任务；
- 检查 agent 是否能在**后续 3 次重规划**内恢复；能恢复的不计入主因；
- 否则找**最早未解决的错误**，把它的时刻记为 $t^*$；
- 用 3 个独立的 Codex 诊断给出候选标签，再由人工按同一规则复核；在 30 个随机子集上，3 位评审 26 例一致（**Fleiss κ = 0.86**）。

结果：**规划 21.0%、导航与底盘定位 25.9%、局部操作 53.1%**。三条发现：
1. 规划失败往往不是"不会做"，而是**进度没跟踪好**——对错误的目标、在错误的阶段调用了正确的技能；
2. **到达正确的工作区 ≠ 有合适的底盘位姿**——导航和操作之间有一个"交接问题"；
3. 规划与导航都对了，**最后的接触仍会因定位误差、抓取错位而失败**。

**干预（四个外挂，底层 VLA 冻结）。**
1. **示范技能卡**：用 Gemini 3.5 Flash 把训练集里的示范视频总结成"任务目标 + 子任务顺序 + 关键帧 + 完成判据"，作为 planner 的上下文；
2. **自适应视觉记忆**：存当前 episode 的观测，planner 需要时用 Qwen3.8-27B 检索最相关的 16 帧（**不能用未来帧、不能用仿真状态**）；
3. **可达性检查 + 底盘调整**：用 Grounding DINO + SAM 把子任务里的目标物体分割出来，反投影得到距离，把当前姿态分成"可达/勉强/够不到"；勉强时 `approach_xy` 小幅平移，够不到时 `goto_stance` 用 A\* 在 2D 占据栅格上重新选位（障碍物膨胀 0.1 m）；
4. **末端几何修正**：同样的分割管线得到目标 3D 点（取中位数以抗深度离群），估计局部表面法向决定接近方向，做**每次不超过 0.3 m** 的有界修正。

**结果。**
- **渐进集成**：19.0% → 47.0%；其中**底盘调整贡献最大**（29.0% → 40.0%）；
- **失败前沿在移动**：随着规划/导航被修好，更多 episode 走到后段，**操作重新成为主要失败类型**；细项上"放置目标/容器指派错误 9→0"、"接近无效/底盘不好 11→1"、"抓取错位/空抓 10→3"；
- **留出集**：18.0% → 49.0%（p < 0.001）；
- **外推**：BEHAVIOR-1K 14.0% → 37.0%；真机 5/20 → 13/20；
- **对照**（表 1）：端到端 VLA 里最强的 Xiaomi Robotics 1 是 44%/45%，**本系统 47%/49%**——用一个"模块化 + 冻结子策略"的设计追平了端到端大模型。

**结论。** 可靠性提升不一定来自"更强的策略"，也可以来自"在瓶颈处精确干预"。

### 2.3 一句话核心创新

> **把"移动操作为什么失败"变成一张可归因的失败分布图，然后按这张图逐个加"外挂"——每一步干预都对应一个被诊断出的失败模式，而不是笼统地提升策略能力。**

## 三、用大白话回答六个问题

### ① 想解决什么问题？

为什么"单个技能会、连起来就废"，以及怎么在不重训模型的前提下修好它。

### ② 为什么以前不行？

| 原因 | 说明 |
|---|---|
| 规划不跟踪进度 | 走错目标、顺序错、忘了已经做过什么 |
| 到了地方但站姿不行 | 手够不到、视角不好 |
| 最后一下不准 | 定位误差、抓取错位 |

### ③ 作者提出了什么办法？

先诊断（81 个失败 episode 逐个归因），再对症下药（四个外挂）。

### ④ 为什么可能更好？

- **不改底层策略**：Kimi K3 的 planner + 冻结的子策略 VLA，所有提升都来自"系统设计"；
- **对症**：每个外挂都对应一个被量化的失败模式；
- **可解释**：能画出"失败分布如何随干预移动"。

### ⑤ 最后取得什么结果？

19% → 47%（开发集）、18% → 49%（留出集）；BEHAVIOR-1K 14% → 37%；真机 5/20 → 13/20。

### ⑥ 最重要的结论是什么？

> **"失败前沿会移动"**：修好一个阶段，下一个阶段的失败就浮现出来。这意味着**可靠性改进是一个迭代的诊断—干预循环**，而不是一次性的能力提升。

### 5.4 细粒度失败变化（§5.2）

| 失败模式 | 干预前 | 干预后 |
|---|---|---|
| 放置目标/容器指派错误 | 9 | **0** |
| 接近无效/底盘位置差 | 11 | **1** |
| 抓取错位/空抓 | 10 | **3** |

**读法**：**被干预明确针对的失败模式几乎被清零**，剩下的失败集中在"放置不准、运输中掉落、碰撞扰动"——这些是**后段**的问题，正好对应"失败前沿移动"。

### 5.5 设计消融（表 2，同一 100 个 episode）

| 组件 | 变体 | 成功率 % |
|---|---|---|
| **技能库** | 完整系统 | **47.0** |
| | 纯文本技能卡（VLA 训练数据） | 43.0 |
| | 文本 + 关键帧（HIW-500 真机数据） | 40.0 |
| | 文本 + 关键帧（VLA 训练数据） | 47.0 |
| **视觉记忆** | 每轮均匀给 8 帧 | 37.0 |
| | 每轮均匀给 16 帧 | 40.0 |
| | 每轮均匀给 32 帧 | 35.0 |
| | planner 触发检索 8 帧 | 42.0 |
| | **planner 触发检索 16 帧** | **47.0** |
| | planner 触发检索 32 帧 | 45.0 |
| **底盘调整** | 去掉可达性检查（check_stance） | **36.0** |
| | 去掉小幅平移（approach_xy） | 42.0 |
| | 去掉重新选位（goto_stance） | 39.0 |
| **末端调整** | 目标位置由 planner 直接给 | 43.0 |
| | **目标位置由几何技能估计** | **47.0** |

**读法（四条可复用的结论）**：
1. **技能卡要有"域内"数据 + 关键帧**：换成真机数据（HIW-500）掉 7 点；去掉关键帧掉 4 点；
2. **记忆要"按需检索"而不是"全给"**：均匀给 32 帧只有 35%（比给 8 帧的 37% 还差）——**信息过多反而干扰**；
3. **可达性检查是底盘调整里最关键的一环**：去掉它掉 11 点（47 → 36），比去掉"重新选位"（掉 8 点）和"小幅平移"（掉 5 点）都重要；
4. **几何接地优于让 planner 直接给 3D 目标**：43 vs 47。

## 六、局限性

### 6.1 作者提到的（§6）

1. 失败前沿会随能力提升而移动，**需要持续的诊断—干预**。
2. 剩余失败（放置不准、运输掉落、碰撞）**没有被当前的几何修正覆盖**。

### 6.2 我识别出的

| # | 局限 | 依据 | 影响 |
|---|---|---|---|
| 1 | **每任务只有 5 次 rollout** | §5.1 | 单任务成功率分辨率 20%，总体 ±5–7 点 |
| 2 | **20/32 任务** | 表 1 题注 | 另外 12 个任务未评估 |
| 3 | **依赖多个闭源大模型** | Kimi K3、Gemini 3.5 Flash、Qwen3.8-27B | 成本、可复现性、延迟都未讨论 |
| 4 | **未报告任何延迟** | 全文 | 四个外挂 + 每轮 planner 调用的开销未知 |
| 5 | **可达性阈值用训练数据定** | §4.3 | 换机器人要重标 |
| 6 | **真机只有 2 个任务、20 次** | §5.3 | 统计意义弱 |
| 7 | **"检查恢复"的窗口是 3 次重规划** | §3.2 | 这个超参会影响归因结果，但没有敏感性分析 |
| 8 | **失败归因用 3 个 Codex + 人工** | §3.2 | 归因本身可能带模型偏见（虽然 κ=0.86） |

## 八、我的一句话评价

> **这篇论文最珍贵的不是 47% 这个数字，而是它示范了一种**研究方法**：先把失败切开看，再针对性地补。**
> 在一个人人都在"堆更大模型"的领域里，它用一个冻结的 80% 子策略 + 四个外挂，追平了最强端到端 VLA（44% → 47%）。而它提出的"**失败前沿会移动**"——修好规划，导航就暴露；修好导航，操作就暴露——是我在这 12 篇里读到的最有系统论味道的一句话。
