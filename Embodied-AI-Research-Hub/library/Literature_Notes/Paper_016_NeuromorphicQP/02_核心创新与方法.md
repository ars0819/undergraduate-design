## 一、创新的分级

### A. 最重要的创新（只选 1 项）

> **把带约束凸 QP 的"投影梯度动力学"映射成 Loihi 2 上的两类脉冲神经元网络，让求解过程在"存算一体"的硬件上以事件驱动方式执行。**

为什么是"映射"而不是"新算法"：
- 算法本身是经典的（梯度下降 + 约束反弹，与投影梯度/Uzawa 一类方法同源）；
- 新的是**硬件的使用方式**：$Q$ 变成突触、$x$ 变成神经元状态、迭代变成脉冲事件。

### B. 其他有价值的改进

| 改进 | 价值 | 是否首创 |
|---|---|---|
| **两类神经元分工**（梯度下降 / 约束检查） | 把"变量更新"与"约束检查"解耦 | ★ 映射清晰 |
| **收敛通知器** | 硬件上判断是否已收敛 | 工程细节 |
| **定点化策略**（减半步长 + 加倍） | 绕过 Loihi 2 无浮点 | 实用妥协 |
| **规模估算公式** | 给出"问题规模 → 神经元/突触" | ★ 对硬件规划有用 |
| **系统性的 EDP 评测** | 不只比时间，还比能耗 | ★ RAM 文章里少见的严谨 |

### C. 借鉴已有研究的技术

| 技术 | 来源 | 角色 |
|---|---|---|
| 凸 QP / 投影梯度 | 经典优化（1950s 起） | 算法基础 |
| OSQP | [16] | 主要基线 |
| Loihi 2 | [8] | 硬件平台 |
| Lava 框架 | lava-nc.org | 软件栈 |
| 脉冲局部竞争算法（SLCA） | [6][7] | 前作（无约束 QP） |
| ANYmal MPC | [9][25] | 应用场景 |

### D. 工程实现与实验设置

- 六种问题规模（来自 ANYmal MPC 的真实 QP）；
- 指标：TTS（求解时间）、ETS（求解能耗）、EDP（能量延迟积）；
- 对比：OSQP on 笔记本 CPU / 边缘 CPU / GPU；
- 硬件：Oheo Gulch 板 + Loihi 2，8 位权重、24 位状态。

> [!important] 一句话总结分级
> **本文的原创性 ≈ "QP 动力学 → 神经形态硬件"的映射工程 + 系统性的 EDP 评测。**

## 二、核心创新的八个追问

### ① 以前的研究通常怎么解机器人 MPC 里的 QP？

| 路线 | 代表 | 问题 |
|---|---|---|
| 高性能 CPU 求解器 | GUROBI、MOSEK | 重、不适合边缘 |
| 嵌入式 CPU 求解器 | OSQP、qpOASES、ECOS | 并行度不足 |
| GPU 求解器 | [17][18] | 稀疏/batch=1 时利用率低 |
| FPGA / ASIC | [19]–[21] | 开发成本高、专用 |
| **神经形态** | SLCA（无约束）、本文（有约束） | 精度受限、硬件稀缺 |

### ② 原有方法的缺点是什么？

| 缺点 | 原文依据 | 我的核查 |
|---|---|---|
| 冯·诺依曼瓶颈 | §Introduction："memory with compute units to minimize data movement" | 成立，是全文的核心论证 |
| GPU 稀疏利用率低 | §Introduction | 成立 |
| GPU batch=1 流水线填不满 | §Introduction | 成立，MPC 正是 batch=1 |
| ASIC 专用性强 | §Introduction | 成立 |

### ③ 作者具体修改了什么？

**三层映射**：

**(1) 变量 → 神经元**
$x$ 的每个分量 → 一个"梯度下降神经元"（24 位状态）；
约束松弛量 $v$ → 一个"约束检查神经元"。

**(2) 矩阵 → 突触**
$Q$ → 梯度神经元之间的突触权重；
$A$、$A^\top$ → 两类神经元之间的突触权重（8 位）。

**(3) 迭代 → 脉冲事件**
每次状态更新只在有变化时发出 graded spike，通过片上路由器送到相关核。

### ④ 修改发生在哪一层/哪一环？

```
[传统] x^{t+1} = (I - αQ)x^t - αp - βAᵀG(x^t)
         ↑ 每步都要从内存读 Q、A

[Loihi] 同样的公式，但：
   Q、A 存在突触里（不搬运）
   x 存在神经元状态里（不搬运）
   更新在核内完成（存算一体）
```

**改动不在数学，而在"数学在哪里执行"。**

### ⑤. 为什么这种改变有效？

**(a) 为什么能省能？**
- 能量主要花在"数据搬运"上（冯·诺依曼瓶颈）；
- 存算一体把搬运消掉；
- 事件驱动让"没变化的变量"不发脉冲。

**(b) 为什么稀疏问题特别受益？**
- 稀疏矩阵在 GPU 上会导致线程发散、利用率低；
- 在神经形态芯片上，零元素根本不产生脉冲——**稀疏即省电**。

**(c) 为什么小问题 CPU 反而快？**
- Loihi 有固定的"编译 + 路由 + 启动"开销；
- 小问题的计算量不足以摊薄这个开销。

**(d) 代价是什么？**
- 无浮点 → 定点 → 精度与最优性间隙；
- 需要专用硬件与 INRC 资格；
- 编程模型与主流差异大。

### ⑥ 它引入了什么新代价？

| 新代价 | 说明 | 证据 |
|---|---|---|
| **定点精度损失** | 最优性间隙 | §实验 |

### ⑦ 与最接近的前人方法有什么区别？

| 维度 | OSQP（CPU） | GPU 求解器 | SLCA（前作） | **本文** |
|---|---|---|---|---|
| 约束 | ✅ | ✅ | ❌（无约束） | **✅** |

## 三、算法完整流程

### 3.1 【输入】

| 输入 | 形式 | 出处 |
|---|---|---|
| QP 参数 | $Q$、$p$、$A$、$k$ | 式 (1)(2) |
| 初始状态 | $x^0$（warm start） | §实验 |
| 步长 | $\alpha_t$、$\beta_t$ | 式 (4) |

### 3.2 【预处理】

- QP → 神经元/突触映射（编译到 Lava）；
- 浮点参数 → 定点（8 位权重、24 位状态）；
- 步长处理：减半 + 加倍（模拟浮点范围）。

### 3.3 【核心模块】

| 模块 | 职责 |
|---|---|
| 梯度下降神经元 | 维护 $x$，执行 $x\leftarrow x-\alpha Qx-\alpha p$ |
| 约束检查神经元 | 维护 $v$，计算 $G_i(x)=\max(0,A_ix-k_i)$ |
| 突触矩阵 | 存 $Q$、$A$、$A^\top$ |
| 收敛通知器 | 判断是否收敛 |

### 3.4 【信息传递】

```
x（梯度神经元）--A--> v（约束神经元）
v --Aᵀ--> x（修正项）
x --Q--> x（梯度项）
```

### 3.5 【推理流程】

```text
1. 初始化 x（warm start）
2. 重复直到收敛：
   a. 约束神经元算 v = A x - k，再过 ReLU 得 G
   b. 梯度神经元算 x ← (I - αQ)x - αp - βAᵀG
   c. 收敛通知器检查残差
3. 输出 x*
```

### 3.6 【训练流程】

**无训练**——这是求解器，不是学习模型。所有参数（$Q$、$A$）来自 MPC 问题的定义。

### 3.7 【机器人执行】

| 问题 | 原文回答 | 状态 |
|---|---|---|
| MPC 时间步 | 10 ms/步 | §实验 |
| 执行时长 | 只执行 20–30 ms（2–3 步） | §实验 |
| 求解时间 | < 10 ms | 摘要 |
| 闭环性能 | **未报告** | 【原文未给出】 |

### 3.8 【输出】

- QP 的近似最优解 $x^*$；
- 不输出控制指令（需外部 MPC 封装）。

## 五、方法层面的疑点清单

1. **没有闭环控制结果**：只报求解器 TTS/ETS，没报 ANYmal 的跟踪误差。这是最大的空白。
2. **定点 vs 浮点的公平性**：把 Loihi 的定点解与 OSQP 的浮点解在"同一精度"下比 EDP，需要仔细读原文的 gap 处理。
3. **公式抽取困难**：式 (1)–(8) 在 PDF 里错乱，读者难以复核。
4. **"可扩展"只有估算**：神经元数随规模的公式给了，但没有真的跑更大规模。
5. **电压/并行化的调优空间**：47% 的电压收益说明默认配置未必最优，可能还有空间。

## 六、把方法浓缩成一条因果链

```text
边缘机器人 MPC 要又快又省电
 ├─ 原因 1: 冯·诺依曼瓶颈（数据搬运）
 │    └─ 对策: 存算一体（Loihi 2）
 ├─ 原因 2: 稀疏 + batch=1 时 GPU 利用率低
 │    └─ 对策: 事件驱动（只在变化时通信）
 ├─ 原因 3: 有约束的 QP 不能直接梯度下降
 │    └─ 对策: 约束反弹（式 4、5）
 └─ 原因 4: Loihi 2 无浮点
      └─ 对策: 定点化 + 精度换规模

结果: EDP 好 2 个数量级、TTS < 10 ms、N=100 只需 7248 神经元
代价: 精度间隙、硬件门槛、小问题不划算、无闭环验证
```

> 这条链最值得学的是**"硬件-算法协同设计"的思考顺序**：先看硬件的特性（存算一体/事件驱动/低精度），再找匹配的算法（迭代/稀疏/可定点化）——而不是先有算法再想怎么加速。
