## 一、三线体系

### 线 1：组件（Components）

**回答"用什么积木"。** §III-A 列了 9 类：

| 组件 | 作用 |
|---|---|
| 强化学习 | 策略优化的历史基础 |
| 预训练视觉表征 | 视觉编码器（CLIP/SigLIP/DINO） |
| 视频表征 | 时序信息 |
| 动力学学习 | 预测下一状态 |
| 世界模型 | 环境的预测模型 |
| LLM 诱导的世界模型 | 用语言模型做预测 |
| 视觉世界模型 | 用视频生成做预测 |
| 推理 | 思维链/子目标推理 |
| 策略引导 | 用额外信号引导策略 |

### 线 2：底层控制策略（Low-Level Policies）

**回答"怎么出动作"。** §III-B 列了 9 类：

| 策略类型 | 动作表示 | 代表 |
|---|---|---|
| 非 Transformer | 各类 | 早期方法 |
| **Transformer 策略** | 离散 token | RT-2 |
| 带 3D 视觉的 Transformer | 离散 token + 3D | 3D-VLA 类 |
| **扩散策略** | 连续（去噪） | Diffusion Policy |
| 带 3D 视觉的扩散 | 连续 + 3D | — |
| 面向运动规划的策略 | 轨迹 | — |
| **点云动作策略** | 点云 | — |
| **大 VLA（LVLA）** | 视规模 | OpenVLA、π0 |

### 线 3：任务规划器（Task Planners）

**回答"怎么拆长任务"。** §IV 分两大类：

| 类型 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **单体式** | 一个大模型直接端到端规划 | 简单、无接口损失 | 与 LVLA 架构冗余；难扩展 |
| ├ 端到端 | 直接出子任务 | — | — |
| ├ 端到端 + 3D | 加 3D 视觉 | — | — |
| └ **接地式（grounded）** | 把子任务"接地"到可执行技能 | 减少幻觉 | 依赖技能库 |
| **模块化** | 规划器 + 独立策略 | 可替换、可解释 | **不"即插即用"** |
| ├ 语言式 | LLM 出子任务文本 | 灵活 | 可能生成策略做不了的子任务 |
| └ 代码式 | LLM 出可执行代码 | 可验证 | 需要手工包装 API |

**作者的关键判断（§VI-e）**：分层最实用，但**引入复杂度与延迟**；单体式与 LVLA 冗余；模块式不即插即用 → **呼吁统一的端到端长任务框架**。

### 2.2 校验结论

**① 能覆盖吗？** **能覆盖 17/20**。剩下 3 篇（P016 神经形态 QP、P018 FLORA、P019 Koopman）不属于"VLA 策略"，它们分别属于**硬件加速**、**奖励学习**、**控制理论**——**是综述的边界之外，不是综述的漏洞**。

**② 补上了我漏掉的一条线**：**任务规划器**。我前 20 篇里只有 P007（SayCan）与 P012（Cracking MM）明显属于这条线，而我之前没有把它当成一个独立维度。

**③ 我的笔记里"线 2"覆盖最厚**（12 篇），说明**我的阅读重心确实在"动作生成"上**——这与我的研究兴趣一致。

**④ 综述对"加速"着墨很少**：9 类策略里没有一类是"高效推理"，只有 §VI-f 提了一句。**这说明"VLA 加速"在 2024–2026 的综述视角里还不是一个独立分类**——这既是缺口，也是机会。

### 2.3 一个我自己的补充维度

综述的三条线**没有覆盖"执行调度"**（动作块、重规划频率、占空比）。而这是我读的 12 篇里反复出现的变量。

所以我给自己的知识库补**第四条线**：

| 线 4：执行调度 | 代表 |
|---|---|
| 无动作块（每步重算） | RT-2（P003）、AC-MPC（P017）、MPC（P016） |
| 有动作块（开环执行一段） | Diffusion Policy（P006）、π0（P005）、TinyVLA（P001） |
| 混合（不同部件不同调度） | MAVP（P011） |
| 任务级接力 | Cracking MM（P012）、euROBIN（P020） |

> **这条线是我加的**，综述没有。它恰好是我的研究兴趣所在——所以这是"综述的缺口 = 我的空间"。

| 挑战 | 与我的方向关系 | 我读过的相关论文 |

| h 伦理 | 低 | — |

**f 条是原文对我最有价值的一句**：

> "If inference time cannot keep pace with environmental changes, the model may generate obsolete actions repeatedly."

**这句话把"加速"从"工程优化"提升为"控制正确性"问题**——推理慢不只是"慢"，而是**输出的动作已经与当前状态不匹配**。

## 四、这篇综述的四个评价维度

### ① 分类是否清晰可操作？

**是。** 三线正交，"任何一篇 VLA 都能定位到一个格子"——这一点我用 20 篇实测过（17/20 可直接定位）。

### ② 是否覆盖关键缺口？

| 缺口 | 覆盖 |
|---|---|
| 组件 | ✅ 厚 |
| 底层策略 | ✅ 厚 |
| 任务规划 | ✅ 有 |
| **加速/压缩** | ⚠️ 只在挑战里提了一句 |
| **执行调度** | ❌ 无 |
| 触觉/多模态深入 | ⚠️ 点到为止 |

### ③ 是否给出可执行建议？

**弱。** 综述主要"分类"而非"建议"。§VI 的九条更像"问题清单"而非"行动指南"。

### ④ 开放问题是否具体？

**具体且可做**。尤其 e（统一端到端长任务框架）与 f（速度-容量权衡）都是明确的研究方向。

## 五、疑点清单

1. **版本问题**：arXiv v1 是 2024-05，TNNLS 版是 2026——**中间一年半的工作覆盖情况我没核实**。
2. **"第一篇"的说法**：作者自称，我没有独立核实（2024 年前后可能有其他 VLA 综述）。
3. **分类粒度不均**：线 2 有 9 类且互相重叠（如"Transformer 策略"与"带 3D 视觉的 Transformer"），线 1 的"世界模型"三类也重叠。
4. **没有定量比较**：综述通病。
5. **加速缺位**：见上。

## 六、把分类浓缩成一句可操作的话

```text
读一篇 VLA 论文时，问三个问题：
 1. 它用了什么组件？（视觉表征 / 世界模型 / 推理 / 引导）
 2. 它怎么出动作？（离散 token / 扩散 / 流匹配 / 点云 / 3D）
 3. 它怎么处理长任务？（单体式 / 模块化 / 不分层）
再问我自己加的一个问题：
 4. 它的执行调度是什么？（有无动作块 / 重规划频率 / 占空比）
```

**前三个问题来自这篇综述，第四个来自我自己的阅读。**
