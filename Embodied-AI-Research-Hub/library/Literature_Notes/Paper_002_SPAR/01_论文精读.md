# P002 · SPAR 论文精读

> [!abstract] 一句话先给你
> **SPAR 把 π0.5 的 Gemma-2B 语言骨干按"两个维度"——隐藏维（hidden）和 FFN 中间维（intermediate）——分别设定保留率做结构化剪枝，把 2.34B 的 LLM 砍到 0.09B（-96%）、整机 3.37B 砍到 1.12B（-67%），发现"FFN 中间维几乎白送、hidden 维很贵"，再用 PPO 强化学习把剪完掉下去的操作成功率拉回来：LIBERO 从 84.55% → 93.45%（+8.90 点），整机推理加速 1.98×。**

## 二、三种长度的摘要

### 2.1 30 秒摘要（约 140 字）

机器人机载算力有限，VLA 模型推理很贵。粗暴压缩会让操作能力崩掉，光靠监督微调（SFT）救不回来。SPAR 在 π0.5 上做"双维度结构化剪枝"：同时学 hidden 维和 FFN 中间维的通道掩码，两者用**不同保留率**；剪完做 SFT，再用 PPO 强化学习在仿真里恢复。结果 LLM 从 2.34B → 0.09B，整机 3.37B → 1.12B，LIBERO 成功率 84.55% → 93.45%，整机推理 1.98× 加速。

### 2.2 3 分钟摘要（约 480 字）

**问题。** π0.5 这类 VLA 模型的参数大头在语言骨干：3.37B 总参数里 LLM 占 2.34B（§I）。机器人板载算力（如 Jetson）扛不住，所以必须压缩。但压缩有两个难点：第一，**剪哪里**——Transformer 里有两种"宽度"，hidden 维（残差流的宽度，跨层共享）和 FFN 中间维（每个前馈层的膨胀宽度）。两者作用不同，冗余度可能完全不同，但已有工作（如 PAT）只统一处理 hidden 维。第二，**剪完怎么救**——参数一去掉，策略就退化，SFT 只能部分恢复，因为 SFT 只模仿示范，不会主动探索"怎么把任务做成"。

**方法。** SPAR 分三步（图 2）：
1. **掩码学习（PAT 阶段）**：给 hidden 维和 FFN 中间维各学一个 $[0,1]$ 的软掩码，分别设定保留率 $\rho_{hid}$、$\rho_{int}$。掩码由可学习 logits 经 sigmoid 得到，温度系数从 1 线性升到 10，让掩码逐渐"硬化"到 0/1。损失 = 策略的监督损失 + 三个正则：通道数惩罚（让软通道数逼近目标）、熵正则（鼓励接近 0/1）、离散度项（推离 0.5 阈值）。掩码在层间共享，保证残差连接的通道一致。
2. **物理剪枝 + SFT**：把掩码二值化，真正删掉对应的行和列，得到一个更小的稠密模型（不是稀疏矩阵，是实打实的小矩阵），再用 24,000 步 SFT 适配。
3. **RL 恢复**：用 PPO 在 LIBERO 仿真里做在线交互，奖励是稀疏的二值成功信号；更新动作专家（action expert）和价值头，**剪枝后的 LLM 骨干保持冻结**。

**结果。**
- **只剪 FFN 中间维**：保留 10% 时 LLM 从 2.34B 降到 0.82B（-65%），平均成功率 96.45% vs 基线 96.80%，只掉 0.35 点，加速 1.73×（表 I）。→ **FFN 中间维高度冗余**。
- **同时剪 hidden 维**：固定 $\rho_{int}=10\%$，把 $\rho_{hid}$ 从 90% 一路降到 10%，平均成功率从 95.90% 掉到 84.55%（表 II）。→ **hidden 维很贵**。
- **RL 恢复**：最小的模型（1.12B/0.09B）从 84.55% 拉到 93.45%（+8.90），整机 1.98× 加速、显存 7.098 → 2.627 GiB（-63%）（表 II、表 V）。
- **鲁棒性**：在 LIBERO-Plus 七类扰动上，RL 让五个剪枝配置提升 5.52–9.35 点，但最小模型仍比未剪枝基线低 27.64 点（表 III）。→ **压缩的代价主要在鲁棒性，不在标准任务**。
- **真机**：AgileX 双臂 6 任务，剪枝（100%/20%）后 63.33% vs 基线 70.83%，掉 7.50 点（表 IV）。**真机上没有做 RL**。

**结论。** 作者主张：维度感知的压缩 + 剪枝后 RL 是互补的两件工具；VLA 的语言骨干里有大量可删的中间维冗余，但 hidden 维不能乱删；RL 能在标准任务上几乎补回损失，但补不回鲁棒性。

### 2.3 一句话核心创新

> **把"剪哪里"细化为"隐藏维 vs FFN 中间维分开定保留率"，并把"剪完怎么救"从 SFT 升级为 PPO 在线 RL，用实验证明这两步必须配对：中间维几乎免费、隐藏维很贵、而隐藏维的损失只有 RL 补得回来。**

## 三、用大白话回答六个问题

### ① 这篇文章想解决什么问题？

VLA 模型太大，机器人自己（机载芯片）跑不动。要在**不换模型架构**的前提下，把一个已经训好的大 VLA 压小，同时尽量不掉点。

### ② 为什么以前没解决好？

两条已有路线各缺一块：

- **只减 token / 只跳层**（SP-VLA、DART 减 token；EfficientVLA、MoLe-VLA 减层计算）：这些方法**不改变骨干权重**（§I 明确说"Token reduction alone leaves backbone weights intact"），所以模型永远是那么大，省的是计算不是存储。
- **结构化剪枝**（PAT、SliceGPT、LLM-Pruner）：能真的变小，但（a）多数只针对 hidden 维，（b）剪完只做 SFT，恢复有限。
- **动态选择**（EcoVLA 自适应选通道和注意力头）：省的是"这一刻"的计算，模型本身没变小；作者明确说自己走的是"永久性缩小稠密模型"（§I）。

所以空白是：**双维度、永久性、且带恢复机制的压缩**。

### ③ 作者提出了什么办法？

三步流水线（图 2）：**学掩码 → 真剪 → RL 救**。
关键设计是"两个维度分别定预算"：hidden 维控制"层与层之间传多宽的信息"，FFN 中间维控制"每层内部膨胀多少"。前者动一发牵全身（残差连接要一致），后者相对独立，所以两者的"性价比"完全不同。

### ④ 它为什么可能更好？

- **更省**：直接删行删列，模型在磁盘上、显存里都真的变小了（表 V 显存 7.1 → 2.6 GiB）。
- **更准**：知道 FFN 中间维可以狠剪、hidden 维要保守，就能把预算花在刀刃上。
- **更能救**：RL 让策略在仿真里"试错"，能做 SFT 做不到的事——比如发现"这个任务其实只要抓住某个关键子目标就行"，从而绕过被剪掉的精细能力。

### ⑤ 最后取得了什么结果？

LLM 参数 -96%、整机 -67%，推理 1.98×、显存 -63%，LIBERO 93.45%（基线 96.80%，**掉 3.35 点**，但比同规模 PAT-only 的 84.55% 高 8.90 点）。

> [!important] 一个必须说清的口径
> 摘要里"93.45%"听起来接近基线 96.80%，但**它仍然比基线低 3.35 个百分点**。作者强调的是"相对 PAT-only 提升 8.90 点"。读论文时一定要区分"相对谁提升"和"绝对水平"。

### ⑥ 最重要的结论是什么？

> **VLA 语言骨干的 FFN 中间维有巨量冗余（剪到 10% 几乎不掉点），但 hidden 维不能这么剪；而 hidden 维剪掉的损失，只有 RL 能大幅补回（+8.90 点），且补不回鲁棒性。**

这条结论比"我们提出了 SPAR"更有价值，因为它给出了**该往哪剪**的先验。

**读法（很重要）**：

3. **10/10 的 93.45% 仍比基线 96.80% 低 3.35 点**，所以"接近无损"要看你对"无损"的定义。
4. **EcoVLA 与 SPAR 不可直接比加速**：表 II 题注明确写道 EcoVLA 的加速是在 RTX 3090 + 自研 Triton kernel 上测的，SPAR 是在 Jetson AGX Orin + TensorRT 上测的，"These speedups are not same-platform comparisons."——**这是本文少见的诚实声明，值得学习**。

## 六、局限性

### 6.1 作者自己承认的（§V）

1. **鲁棒性差距仍在**：LIBERO-Plus 上最小模型落后 27.64 点。
2. **只验证了一个骨干**（π0.5 / Gemma 2B）和**一种中间维剪枝配置**在真机上（100%/20%）。
3. 未来工作：多骨干研究、真机上也做 hidden+intermediate 联合剪枝、跨平台的能耗测量、用 SimFoundry 重建真机场景以便在真机上做 RL。

## 七、阅读建议

### 7.1 最值得精读的三节

1. **§III-A**（式 2、3）——搞清楚"hidden 掩码"和"intermediate 掩码"分别乘在权重矩阵的哪一侧。这是全文唯一需要空间想象力地方。
2. **§III-B**（式 4–11）——软掩码如何硬化、三个正则各管什么。复现的核心。
3. **§IV-A/B**（表 I vs 表 II）——**"只剪中间维"和"两个都剪"的对照，是全文的科学发现所在**，比方法本身更值得学。

### 7.2 最关键的两张表

- **表 I**：证明"FFN 中间维几乎免费"。
- **表 II**：证明"hidden 维很贵 + RL 能救 + RL 收益随压缩变大"。

### 7.3 最重要的三个公式

- 式 (2)(3)：掩码作用位置（决定"剪了什么"）。
- 式 (7)：通道数惩罚（决定"剪多少"）。
- 式 (12)：PPO 裁剪目标（决定"怎么救"）。

### 7.4 必须理解的五个术语

`结构化剪枝`、`hidden 维 / FFN 中间维`、`保留率 ρ`、`软掩码与温度退火`、`PPO`。
→ 见 [[Paper_002_SPAR/04_术语和公式解释]]。

### 7.5 三个自测问题

1. 为什么 hidden 维的掩码要在**所有层之间共享**，而中间维不需要？（提示：残差连接）
2. 表 I 里 ρ_int=70% 的平均成功率（97.65）比基线（96.80）还高，这说明什么？
3. 如果 RL 收益随压缩率单调上升（+1.90 → +8.90），那为什么不干脆剪到 1%？（提示：表 III 的鲁棒性、以及 RL 能不能救回来是有上限的）

### 7.6 30 分钟读法

> 摘要（2 min）→ 图 2（3 min）→ §III-A 式 2/3（8 min）→ 表 I + 表 II（10 min）→ 表 III 的 Overall 列（4 min）→ §V 局限（3 min）。**跳过** §II 相关工作与式 8–10 的推导细节。

### 7.7 是否建议复现

**建议做"表 I 的部分复现"，不建议复现 RL 部分。** 理由：
- 表 I 只需要剪枝 + SFT，单卡可做（原作用 A800，但小规模可降级）。
- RL 部分要 8×A800 + 128 个并行环境 + RLinf 框架，成本极高，不适合作为第一个复现项目。
- 真正便宜的复现切口是：**换成更小的 VLA（如 SmolVLA）验证"中间维冗余"这个结论是否成立**。见 [[Paper_002_SPAR/05_科研启发与复现建议]]。

## 八、我的一句话评价

> **这是一篇"诊断价值大于方法价值"的论文：方法（掩码剪枝 + PPO）几乎都是现成积木的组合，但它用一组干净的对照实验回答了"VLA 的语言骨干里哪部分参数是浪费的"——答案出人意料地干脆：FFN 中间维可以砍掉 90%，hidden 维不行。这种"给出可复用先验"的实证结论，比又一个压缩 pipeline 更有长期价值。**
