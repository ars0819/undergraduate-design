## 一、创新的分级

### A. 最重要的创新（只选 1 项）

> **双维度分离保留率的结构化剪枝 + 剪枝后 PPO 恢复，作为一条完整流水线；核心实证发现是"FFN 中间维的冗余度远高于 hidden 维，且 hidden 维的损失只有 RL 能大幅补回"。**

我更愿意把 A 定义成"**方法论层面的一个判断**"而不是某个模块，因为：
- 掩码学习来自 PAT（[15]），不是本文发明的；
- PPO 是标准算法（[30]），不是本文发明的；
- 双维度掩码的形式（式 2、3）是 PAT 的自然扩展，工程上并不难想。

真正的新东西是**"把预算分配和恢复机制当成一个联合优化问题，并用对照实验证明二者必须配对"**这一整套判断。作者自己在 §I 的三条贡献里，第一条写"dual-dimension … separate retention targets"，第二条就是"dimension sensitivity"的实证分析——说明他们也知道价值在"发现"而非"模块"。

**修改发生在系统的哪一环？**
不在数据、不在训练范式、不在推理引擎，而是**在模型参数本身的结构上**：删掉 LLM 每一层的部分通道（hidden 维的列/行 + FFN 中间维的行/列），得到一个**更小的稠密权重矩阵**——注意不是稀疏矩阵，是物理上更小的矩阵。

### B. 其他有价值的改进

| 改进 | 价值 | 是否首创 |
|---|---|---|
| 温度退火把软掩码硬化（式 4、5） | 让"连续可导的通道选择"能收敛到 0/1 | 否，是软阈值/退火类方法的常见做法 |
| 通道数惩罚用"软计数"（式 7） | 避免硬计数不可导 | 否（PAT 已有类似思路） |
| 熵正则 + 离散度项（式 9、10） | 双保险地把掩码推向 0/1 | 否 |
| 掩码层间共享 | 保证残差通道一致，剪完不用改结构 | 是 PAT 的既有设计，本文沿用 |
| **RL 时冻结剪枝后的 LLM、只训动作专家与价值头** | 省算力，且防止 LLM 被 RL 改坏 | 这是本文的工程选择，论文未与"全量 RL"对比 |
| 在 LIBERO-**Plus** 上评鲁棒性 | 揭示了"标准任务无损、扰动下崩"的关键现象 | ★ 这是很多压缩论文不做的实验 |

### C. 借鉴已有研究的技术

| 技术 | 来源 | 作用 |
|---|---|---|
| PAT（Hybrid Sparsification Module、通道掩码 + 知识变换） | Liu et al., AAAI 2025（[15]） | 整个掩码学习框架的底座 |
| 结构化剪枝（行/列删除，SliceGPT） | Ashkboos et al.（[25]） | "剪完是稠密小矩阵"的思想 |
| PPO | Schulman et al.（[30]） | RL 恢复 |
| RLinf | Zhang et al.（[27]） | 并行仿真 rollout 与分布式更新 |
| π0.5 / OpenPI | Physical Intelligence（[3]、[31]） | 被剪的模型与实现框架 |
| LIBERO / LIBERO-Plus | [16]、[17] | 评测基准 |

### D. 工程实现与实验设置

- 掩码 logits 初始化 ±1.5；温度从 1 线性升到 10，$r_{stop}=0.8$；
- SFT：batch 256，共 30,000 步（6,000 步掩码学习 + 24,000 步剪后微调），NVIDIA A800；
- RL：8×A800，128 训练环境 + 80 评测环境，actor 全局 batch 2,048，单卡 micro-batch 128，最多 200 RL epochs；
- 延迟：Jetson AGX Orin + TensorRT，报告**中位数**全策略延迟；
- 数据：LIBERO 四个套件共 40 个任务，训练一个策略覆盖全部。

## 二、核心创新的八个追问

### ① 以前的研究通常怎么处理"VLA 太大"？

按 §I/§II 的归类，四条路线：

| 路线 | 代表 | 模型真的变小了吗 |
|---|---|---|
| 换成天生小的策略 | SmolVLA、NORA | 是（但是重新训的） |
| 减视觉 token | SP-VLA、DART | 否（骨干权重不变） |
| 减层/跳层 | EfficientVLA、MoLe-VLA | 否（推理时跳过，权重还在） |
| 动态选通道/头 | EcoVLA | 否（按需选，权重还在） |
| 结构化剪枝 | PAT、SliceGPT、LLM-Pruner | **是** |
| RL 恢复 | RLRC、SimpleVLA-RL | 不改大小，改行为 |

SPAR 站在最后两行之间：**先让它真的变小，再让它变好。**

### ② 原有方法的缺点是什么？

| 缺点 | 原文依据 | 我的核查 |
|---|---|---|
| 只减 token/层，权重不减少 | §I："Token reduction alone leaves backbone weights intact" | 成立。这类方法省的是 FLOPs 和延迟，不是显存占用 |
| 剪枝只盯 hidden 维 | §II-B 对 PAT 的描述：PAT 做的是 hidden-dimension pruning | 成立。所以"FFN 中间维"确实是本文补上的空白 |
| 剪完只靠 SFT 恢复 | §I："can degrade manipulation performance beyond what supervised fine-tuning alone recovers" | **这句话是本文的核心动机，但论文没有给出"SFT 恢复上限"的定量证据**——它只对比了 PAT only vs PAT+RL 的最终数字 |
| 动态方法需要自定义 kernel | §II-B 提到 EcoVLA 用 custom kernels | 这是工程代价，不是科学缺点 |

> [!warning] 一个证据缺口
> "SFT 救不回来"这个前提，本文是用"PAT only 的最终成功率较低"来间接支持的。但严格说，**PAT only 的成功率低也可能是因为掩码学得不好、或 SFT 步数不够**，不一定是"SFT 这种方法有上限"。要证明后者，需要做"SFT 步数 × 数据量"的扫描曲线。原文没做。

### ③ 作者具体修改了什么？

用三句话：

1. **把掩码从一个维度变成两个维度**，并允许两个维度用不同保留率（$\rho_{hid} \ne \rho_{int}$）。
2. **把"剪完就结束"改成"剪完再 SFT，再 RL"** 的三段式。
3. **把 RL 的作用范围限制在动作专家 + 价值头**，LLM 骨干冻结。

用数学表达（详见笔记 04）：

$$
W'_{Q,K,V} = W_{Q,K,V} D_h,\quad O = D_h W_O \tag{2}
$$
$$
W'_{up,gate} = D_i W_{up,gate} D_h,\quad W'_{down} = D_h W_{down} D_i \tag{3}
$$

这两个式子是全文的"物理层"：它们规定了**哪一维的掩码乘在权重的左边（选行/输出通道）、哪一维乘在右边（选列/输入通道）**。

### ④ 修改发生在哪一层/哪一环？

```
[视觉塔 SigLIP]        —— 不动
[LLM 骨干 Gemma-2B]    —— ★ hidden 维剪（列+行）、FFN 中间维剪（行）
[动作专家 action expert] —— 不动（RL 时训练它）
[价值头 value head]     —— RL 时新增/训练
[推理引擎]              —— TensorRT 重新编译小模型
```

> 关键：**这一刀切在"模型结构"上，而不是"计算调度"上。** 所以它省的是显存和权重带宽，而不仅仅是 FLOPs。这也是它能做到 7.098 → 2.627 GiB 的原因。

### ⑤ 为什么这种改变有效？

**(a) 结构层面：为什么 FFN 中间维更冗余？**（原文有实验，无理论解释）
我的解释【推断】：
- FFN 中间维是"每层内部的临时膨胀空间"，它的主要作用是非线性特征变换；相邻通道高度相关，删掉一部分相当于降低秩，信息损失可以被剩余通道 + 下一层补偿。
- hidden 维是"层与层之间的高速公路"，**所有层共享同一组通道**，一旦删掉某个通道，等于在所有层、所有残差连接上同时抹掉这个特征方向，而且不可恢复。
- 所以"中间维便宜、hidden 维贵"符合"共享资源比局部资源更贵"的直觉。**原文没有给出这个解释**，只给了数据。

**(b) 学习层面：为什么需要 RL？**（原文有实验支持）
- SFT 只能模仿示范动作。当模型容量被砍掉后，"精确复现示范轨迹"这条路走不通了，需要**换一条能成功的路径**（比如更早闭合夹爪、绕开某个难抓的姿态）。
- RL 用稀疏的成功/失败信号，允许策略探索"别的成功方式"。这解释了为什么**压缩越狠、RL 收益越大**（+1.90 → +8.90，表 II）：容量越少，越需要"换路线"而不是"更精确"。
- 这也解释了为什么**未剪枝模型上 RL 只涨 0.90 点**（表 II 的 baseline+RL）：它本来就能精确复现，没什么可换的。

**(c) 为什么 RL 补不回鲁棒性？**（原文有实验，无解释）
我的解释【推断】：RL 的奖励是"任务成功"，训练分布是 LIBERO 的标准场景。策略会把剩余容量**过拟合到训练分布的成功模式**上，而扰动（相机、光照、布局）下的泛化需要的是"冗余的表征空间"，恰恰被剪掉了。这是压缩与鲁棒性之间的根本张力。

### ⑥ 它引入了什么新代价？

| 新代价 | 说明 | 证据 |
|---|---|---|
| **RL 训练成本极高** | 8×A800、128 并行环境、最多 200 epochs | §IV-d |
| **需要仿真器** | RL 必须有可交互环境，真机场景没有就只能先重建仿真 | §V 未来工作 |
| **鲁棒性下降** | LIBERO-Plus 上最小模型 -27.64 点 | 表 III |
| **剪枝后不可逆** | 物理删除，无法"反悔"恢复 | 方法本身 |
| **超参变多** | 两个保留率 × 三个 λ × 温度调度 × $r_{stop}$ | 式 4–11 |
| **掩码层间共享** | 牺牲逐层灵活性 | §III-A |

### ⑦ 与最接近的前人方法有什么区别？

| 维度 | PAT | SliceGPT | EcoVLA | RLRC | **SPAR** |
|---|---|---|---|---|---|
| 剪什么 | hidden 维 | 行/列 | 动态选通道+头 | 结构化剪枝 | **hidden + FFN 中间维** |
| 保留率 | 单一 | 单一 | 动态 | 单一 | **两个独立保留率** |
| 模型是否永久变小 | 是 | 是 | 否 | 是 | **是** |
| 恢复手段 | SFT | SFT | 无 | SFT + RL | **SFT + PPO** |
| 鲁棒性评测 | 无 | 无 | 无 | 无 | **有（LIBERO-Plus）** |
| 真机验证 | 无 | 无 | 无 | 无 | **有（6 任务）** |

**最本质的区别**：SPAR = **PAT 的双维扩展** + **RLRC 式的 RL 恢复** + **鲁棒性评测**。它的新颖性在于"组合 + 系统评测"，而不是任何单点。

### ⑧ 实验是否真的支持作者的主张？

| 作者主张 | 证据 | 支持度 | 我的评语 |
|---|---|---|---|

## 三、算法完整流程（严格区分阶段）

### 3.1 【输入】

| 输入 | 形式 | 出处 |
|---|---|---|
| 预训练 VLA | π0.5（Gemma-2B 骨干），3.37B 总参数、2.34B LLM | §IV-a |
| 演示数据 | LIBERO 40 个任务（Spatial / Object / Goal / Long） | §IV-a |
| 保留率超参 | $\rho_{hid}$、$\rho_{int}$（如 70%/10%） | 表 I、II |
| 仿真环境 | LIBERO（RL 阶段） | §III-C |

### 3.2 【预处理】

- 把每个权重矩阵按"输入维/输出维"归类到 hidden 或 intermediate；
- 初始化掩码 logits：候选保留通道 +1.5，其余 −1.5；
- 计算目标通道数 $N_{target}$：$\rho \times d$，并对齐到 32 的倍数（图 3 题注：224 = 32×7，1664 = 32×52）。

### 3.3 【核心模块】

| 模块 | 职责 | 是否可训练 |
|---|---|---|
| 隐藏维掩码 $\mathbf{M}_{hid}\in[0,1]^{d_{model}}$ | 选残差流通道，**层间共享** | 是 |
| 中间维掩码 $\mathbf{M}_{int}\in[0,1]^{d_{ffn}}$ | 选 FFN 膨胀通道，层间共享 | 是 |
| 掩码温度调度 $\tau(s)$ | 1 → 10 线性，把软掩码硬化 | 否（超参） |
| 三个正则 | 控制通道数、二值性 | 否（超参 $\lambda$） |
| 动作专家（action expert） | 生成动作（π0.5 的流匹配专家） | SFT 时训练；RL 时训练 |
| 价值头（value head） | 估计状态价值，供 PPO 用 | RL 时训练 |
| PPO | 用稀疏成功奖励更新策略 | — |

### 3.4 【信息传递】

```
输入 x
 └─ 注意力: W_QKV 先乘 D_h (选输入通道) ─> 得到 Q,K,V
           再乘 D_h (选输出通道) ─> 残差流
 └─ FFN:  W_up/gate 左乘 D_i (选中间通道) 右乘 D_h (选输入通道)
          W_down   左乘 D_h (选输出通道) 右乘 D_i (选中间通道)
 └─ 输出到动作专家
```

用形状说（以 Gemma-2B 量级为例，$d_{model}=2048$、$d_{ffn}\approx16384$）【数值为推断，依据图 3 的 224/1664 目标反推】：

| 张量 | 剪前 | ρ=10% 剪后 |
|---|---|---|
| hidden 通道数 | 2048 | 224 |
| FFN 中间通道数 | 16384 | 1664 |
| $W_{up}$ | $16384\times2048$ | $1664\times224$ |
| 参数比 | 1 | $(1664\times224)/(16384\times2048) \approx 1/90$ |

> 这个 1/90 就是"为什么 LLM 参数能砍 96%"的直观来源：FFN 的参数量随两个维度**同时**缩小。

### 3.5 【训练流程】——四个阶段

```text
阶段 0：加载 π0.5 预训练权重
阶段 1：掩码学习（PAT 阶段，6,000 步）
   每个 step:
     1. M = σ(τ(s) · W_M)              # 式 4，软掩码
     2. 用 D_h, D_i 包装所有权重矩阵     # 式 2、3
     3. 前向算策略损失 L_SFT
     4. 加正则: L_count + L_entropy + L_disc   # 式 7、9、10
     5. 反向传播，更新 W_M 与网络权重
   结束时: M_bin = 1[W_M ≥ 0]，物理删行删列
阶段 2：剪后 SFT（24,000 步）
   在缩小后的稠密模型上继续监督微调
阶段 3：PPO 恢复
   冻结剪枝后的 LLM 骨干
   只更新动作专家 + 价值头
   奖励 = 任务成功 1 / 失败 0（稀疏）
   并行: 128 训练环境 + 80 评测环境
   最多 200 epochs
```

**注意阶段顺序不可交换**：先学掩码（此时模型还大，表达能力够，掩码能学到"哪些通道重要"），再物理剪（一次性不可逆），再 SFT（适配新结构），最后 RL（换行为）。

### 3.6 【推理流程】

```text
1. 视觉塔编码图像 → 视觉 token
2. 剪枝后的 LLM 前向（hidden/FFN 都变小了）
3. 动作专家（flow matching）生成动作块
4. 下发执行
```
延迟 148.71 ms（10/10 配置，Jetson AGX Orin + TensorRT，全策略）。

### 3.7 【机器人执行】

| 问题 | 原文回答 | 状态 |
|---|---|---|
| 动作块（action chunk） | PPO 的奖励和 log-prob **在动作块层级聚合**（§III-C） | 【原文】说明 π0.5 用动作块 |
| 动作块长度 | **未给出** | 【原文未给出】 |
| 控制频率 | **未给出** | 【原文未给出】 |
| 重规划频率 | **未给出** | 【原文未给出】 |
| 真机平台 | AgileX 双臂，6 个任务，每任务 20 trials | 表 IV |

> 和 TinyVLA 一样，**执行调度细节缺失**。但 SPAR 至少透露了一个关键信息："动作块"是 PPO 的基本单位——也就是说，VLA 的 RL 训练天然以"块"为粒度，而不是以"单步"为粒度。这对你做调度研究很重要：**动作块不只是推理加速手段，也是 RL 的语义单位。**

### 3.8 【输出】

- 剪枝后的稠密 VLA 模型（可部署）；
- 动作块（连续动作序列）；
- 可选的 RL 训练后的策略。

## 五、方法层面的疑点清单

1. **式 (10) 的量纲问题**：$\mathcal{L}_{disc} = \lambda_3\left(0.5 - \sum_{j=1}^{d}|M_j-0.5|\right)$ 里没有除以 $d$，那么这一项会随 $d$ 线性放大（hidden 维和中间维的 $d$ 相差 8 倍），同一个 $\lambda_3$ 对两个掩码的实际强度不同。原文没有讨论这一点，也没有给 $\lambda$ 的具体数值。**这是复现时的一个真实坑。**
2. **掩码层间共享的代价**：不同层的通道重要性显然不同，共享掩码是强约束。作者没有做"共享 vs 逐层"的消融。
3. **RL 冻结 LLM 是否最优**：冻结省算力，但也限制了"LLM 表征随新行为一起适配"的可能。没有对照。
4. **"无损"的表述**：表 I 里 70% 那行反超基线，说明评测已饱和。在这种情况下，"96.45 vs 96.80" 不能作为"仅损失 0.35 点"的强证据。
5. **加速比与压缩比不匹配**：LLM 参数 -96%，整机只快 1.98×。这个差距本身就是重要信息——**说明 VLA 的推理瓶颈不只是 LLM**，但论文没有进一步拆解（比如视觉塔占多少）。

## 六、把方法浓缩成一条因果链

```text
VLA 太大，机载跑不动
 ├─ 已有压缩方法的缺陷
 │   ├─ 减 token / 跳层 → 权重还在，模型没变小
 │   ├─ 只剪 hidden 维 → 漏掉了 FFN 中间维这块大冗余
 │   └─ 只做 SFT 恢复 → 容量掉了就回不来
 └─ SPAR 的对策
     ├─ 双维度掩码 + 分离保留率（式 2、3）
     │    └─ 发现：中间维 10% 保留几乎无损（表 I）
     ├─ 物理剪枝 → 稠密小模型（显存 7.1 → 2.6 GiB）
     └─ PPO 恢复，且冻结 LLM
          └─ 效果：84.55 → 93.45（表 II），且压缩越狠收益越大
     
 代价
     ├─ RL 训练极贵（8×A800）
     ├─ 鲁棒性掉 27.64 点（表 III）
     └─ 真机只掉 7.5 点但没做 RL（表 IV）
```

> 这个因果链里最值得学的是**"代价"这一栏**：作者把 RL 的成本、鲁棒性的损失、真机的掉点都写出来了。一篇诚实的压缩论文应该长这样。
