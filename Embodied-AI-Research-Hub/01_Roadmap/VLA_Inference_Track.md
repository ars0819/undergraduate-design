# VLA Inference Track

> 目标：在固定硬件、固定模型、固定任务上，得到**可复跑的原始基线**，再做**一种**推理优化，报告延迟/显存/动作质量/闭环成功率。  
> 当前状态：**没有模型加载、没有权重、没有 episode、没有测速**。以下全部是计划与门槛，不是结果。

## 1. 研究问题（工作版）

在固定开源 VLA（首选 SmolVLA）和固定 LIBERO 任务/初态的闭环设置下：

1. 推理时间具体花在哪里（预处理、视觉/语言骨干、动作头迭代、反归一化、传输、执行）？
2. 一种已有推理优化（优先官方 `torch.compile`，备选减少流匹配 `num_steps`）是否降低**新动作块**的 p50/p95 延迟与峰值显存？
3. 这种变化是否保持动作质量与闭环成功率？如果不保持，失败在哪里？
4. 12GB RTX 5070 与 A100 40GB 的差异如何影响可部署性？不把跨设备数字混在一起。

**不研究**：从零训练大模型、Agent 框架、世界模型、完整机器人大脑、多机协同架构。

## 2. 候选模型

| 路线 | 角色 | 已知/待核 | 风险 |
|---|---|---|---|
| SmolVLA + LeRobot LIBERO | 首选 | 既有项目资料记录为约 450M 级、官方有 LIBERO checkpoint；具体版本/显存/接口待复核 | 相机键、processor 统计、MuJoCo/EGL、依赖版本；12GB 可能够但不保证 |
| OpenVLA-OFT + LIBERO | 备用 | 7B 级；官方 LIBERO checkpoint 与评测脚本；全精度对 12GB 可能不足 | 旧依赖栈、FlashAttention、A100 可用性；不先量化替代原始基线 |

> “约 450M/7B 级”来自既有资料的静态核查记录，需以模型卡和实际加载复核；本库不把它当已测事实。

## 3. 阶段与门槛

### P0：证据与阅读（当前）

- 读 SmolVLA 论文的摘要、方法、实验设置；读模型卡/LeRobot LIBERO 文档。
- 画一页推理链路：多相机图像、语言、proprio → processor/归一化 → VLM 骨干 → 动作头/流匹配 → 动作块 → 反归一化 → 控制/环境。
- 列 3 个接口风险、3 个评价风险、3 个要问导师的问题。
- **Gate G0**：一页纸 + 风险清单 + 环境事实；不下载权重。

### P1：环境与最小推理

- 固定 Python/torch/CUDA/驱动；独立环境；`pip freeze`。
- 固定代码 commit、权重 revision、processor 文件；记录哈希。
- 加载模型，输入一个真实观测，输出有限、shape 正确的动作块；记录峰值显存。
- **Gate G1**：`gpu.json`/环境日志、tensor schema、一次前向、显存数字；无 NaN/OOM。

### P2：单回合闭环

- LIBERO task0，固定初态/语言/动作接口；完整 episode；保存视频索引、终止原因、墙钟。
- 先原样配置；不改精度、不改执行长度、不开 compile。
- **Gate G2**：一个 episode 可重跑；失败也有完整日志；不把“加载成功”当 G2。

### P3：原始基线测量

- 固定 batch=1、输入、dtype、noise、执行长度；新动作块计时，预热后至少 200 次（可降低但记录）。
- 3 个独立进程/session；p50/p95、峰值显存、模块耗时。
- 任务侧：3 个任务 × 10 个初态作为探索性试点（30 回合/条件），报告成功数/总数、Wilson 区间、失败分类。
- **Gate G3**：原始基线的延迟/显存/任务表 + 原始日志；同配置可复跑。

### P4：一种优化

- 只选一种：官方 `torch.compile` 或 `num_steps` 减少；量化另立条件，不在第一步混入。
- 同权重、同输入、同 noise、同精度、同执行长度；配对顺序；记录编译冷启动、graph break、额外显存。
- **Gate G4**：原/优化配对表；p50/p95、显存、动作误差、成功率；负结果也保留。
- 暂拟工程门槛（需导师确认）：p50 降低 ≥10%，p95 不增加 >5%，显存不越界；任务成功率下降不超过预设 δ（例如 5 个百分点，仅为讨论占位，不是统计非劣证明）。

### P5：评测、复跑与打包

- 失败分类：模型/依赖、渲染/初态、接口/归一化、抓取未成、掉落、放置不达标、超时、约束拒绝。
- 新进程复跑关键命令；README、配置、原始表、限制。
- **Gate G5**：别人能按文档复跑；每个数字能追到原始文件。

## 4. 指标与测量纪律

- 时间边界：加载、预处理、H2D、骨干、动作头、D2H、反归一化、后处理、控制；端到端另算。
- **不要**把 `select_action()` 从缓存队列弹出旧动作的平均耗时当作新动作块推理延迟；测 `predict_action_chunk()` 或标记 `new_chunk`。
- 显存：allocated / reserved / NVML 分开；GiB 与 GB 不混。
- 延迟：`perf_counter` + CUDA synchronize 的墙钟；CUDA Events 作设备归因；profiler 单独 run。
- 任务：成功数/总数，不写“100%”除非分母和重复次数支持；20 回合全成功不等于真实成功率 100%。
- 能量/成本：有权限才测；没有就写缺失；不把省显存等同节能。

详见 [`Inference_Metrics_and_Benchmarking.md`](../03_Research/Efficient_Inference/Inference_Metrics_and_Benchmarking.md)。

## 5. 实验设计（试点）

- 实验单元：任务–初始状态对，不是 GPU 调用次数。
- 设计：3 个任务 × 10 个初态 × 2 条件（原始/优化）= 60 回合；随机化运行顺序；记录初态哈希。
- 评价：成功率、完成时间、动作误差、p50/p95、峰值显存、失败类型。
- 统计：报告成功数/总数与 Wilson 区间；试点是工程探索，不宣称非劣/显著。
- 如果只能做 task0：10 初态 × 2 = 20 回合；明确写“未覆盖 3 任务”。

## 7. 失败与退路

| 现象 | 先检查 | 退路 |
|---|---|---|
| 环境装不上 | Python/torch/CUDA/驱动匹配、wheel 架构、网络 | 记录错误，先用 CPU/阅读；1 小时后停 |
| 加载 OOM | 精度、batch、图像尺寸、是否重复加载 | 关 compile、batch=1；必要时 A100；不先量化 |
| 能加载但不能闭环 | 相机键、state/action、processor 统计、MuJoCo/EGL | 只做 L0/L1 证据；两天不闭环切备用/缩任务 |
| compile 无收益 | 计时边界、缓存动作、graph break | 提交负结果；另做 num_steps 独立实验 |
| 量化变慢/掉点 | 真实内核、反量化、动作头精度 | 归类为容量优化或放弃；不写“加速” |
| 任务全败 | 接口/渲染/初态，不先扫优化 | 停优化，修基线；保留失败分母 |
